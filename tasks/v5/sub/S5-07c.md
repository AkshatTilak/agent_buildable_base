# S5-07c: API Key Management CRUD & Middleware

> **Parent:** B5-07 (External API Gateway)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `gateway`, `common/models`

---

## Scope

Enhance the existing `APIKeyModel` with user association and build key management endpoints + validation middleware.

## Actionables

- [x] Modify `APIKeyModel` in `common/models/database.py`:
  - Add: `user_id` (FK→users, nullable), `last_used_at` (DateTime, nullable), `usage_count` (Integer, default=0), `rate_limit` (Integer, default=60 — requests/minute), `prefix` (String(8) — first 8 chars, for display)
- [x] Add to `gateway/api/external.py` or create `gateway/api/api_keys.py`:
  - `POST /api/settings/api-keys` — generate new API key:
    - Generate: `sk-` prefix + 48 random chars
    - Store hashed key in DB (bcrypt or SHA-256)
    - Return full key **once** (not stored in plaintext)
    - Store `prefix` (first 8 chars) for display
  - `GET /api/settings/api-keys` — list keys (show prefix + `***` + last 4 chars, name, created, last_used, usage_count)
  - `PUT /api/settings/api-keys/{id}` — update name, rate_limit, toggle active
  - `DELETE /api/settings/api-keys/{id}` — revoke (hard delete)
- [x] Create `gateway/auth/api_key_middleware.py`:
  - Applied to `/v1/*` routes only
  - Extract key from `Authorization: Bearer sk-...` header
  - Hash and lookup in `api_keys` table
  - Validate `is_active == True`
  - Update `last_used_at` and increment `usage_count` (fire-and-forget)
  - Set `request.state.api_key_id` for downstream use
  - Return 401 if key invalid/inactive
- [x] Generate Alembic migration
- [x] Add test: `gateway/tests/test_api_key_management.py`

## Key Design Decisions

- API keys are separate from JWT auth — `/v1/*` uses API keys, `/api/*` uses JWT
- Keys are hashed at rest — only shown in full once at creation
- The `sk-` prefix follows OpenAI convention for user familiarity
