# S5-03d: JWT Middleware & Role-Based Dependencies

> **Parent:** B5-03 (User Authentication & RBAC)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `gateway`

---

## Scope

Create middleware that validates JWT on protected routes and FastAPI dependencies for role-based access control.

## Actionables

- [ ] Implement `gateway/auth/middleware.py`:
  - `AuthMiddleware` (ASGI middleware):
    - Skip auth on whitelisted paths: `/auth/*`, `/health`, `/api/health/*`, static assets
    - Skip entirely if `AUTH_ENABLED=false`
    - Extract JWT from `Authorization: Bearer <token>` header or `auth_token` cookie
    - Verify token via `verify_access_token()`
    - Validate session exists and not expired in `user_sessions` table
    - Set `request.state.user` with user info (id, email, role)
    - Return 401 if token invalid/expired
- [ ] Implement `gateway/auth/dependencies.py`:
  - `get_current_user(request: Request) -> User`:
    - Returns user from `request.state.user` or raises 401
    - When `AUTH_ENABLED=false`, returns a synthetic admin user (backward compat)
  - `get_optional_user(request: Request) -> Optional[User]`:
    - Same but returns None instead of raising (for optional auth)
  - `require_role(*roles: str)`:
    - Returns a dependency that checks `current_user.role in roles`
    - Raises 403 if role insufficient
    - Usage: `Depends(require_role("admin", "editor"))`
- [ ] Add auth routes in `gateway/auth/routes.py`:
  - `POST /auth/logout` — invalidate session (delete from DB)
  - `GET /auth/me` — return current user info + role
  - `GET /auth/users` — admin only: list all users with roles
  - `PUT /auth/users/{id}/role` — admin only: change user role
  - `DELETE /auth/users/{id}` — admin only: deactivate user
- [ ] Register auth middleware in `gateway/main.py` (conditionally, based on `AUTH_ENABLED`)
- [ ] Register auth router in `gateway/api/__init__.py`
- [ ] Add test: `gateway/tests/test_auth_middleware.py`

## Dependencies
- S5-03a (Auth scaffold)
- S5-03b or S5-03c (at least one OAuth provider for testing)

## Key Design Decisions

- When `AUTH_ENABLED=false`, middleware is not added at all — zero overhead
- The `/v1/*` external API routes use API key auth (S5-07), not JWT — separate auth path
- Session validation hits DB on each request; for performance, cache sessions in Redis with short TTL
