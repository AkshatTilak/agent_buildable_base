## Scope

Create `projects/evalops/src/metrics/ragas_runner.py` — a self-contained RAGAS evaluation engine that takes a list of test cases (input, expected output, expected context) and an agent's actual responses, then computes RAGAS metrics.

## Actionables

- [ ] Create `projects/evalops/src/metrics/__init__.py`
- [ ] Create `projects/evalops/src/metrics/ragas_runner.py`:
  - Import `ragas.evaluate`, `ragas.metrics` (context_recall, faithfulness, answer_relevancy, context_precision)
  - Use `LangchainLLMWrapper` wrapping the platform's LiteLLM completion model (resolve via `get_active_model("completion")`)
  - Use platform's embedding model for semantic similarity (resolve via `get_active_model("embedding")`)
  - Function signature: `async def run_ragas_evaluation(test_cases: List[EvalTestCase], agent_responses: List[str], retrieved_contexts: List[List[str]]) -> RagasEvalResult`
  - `RagasEvalResult` dataclass: per-case scores + aggregate means for each metric
  - Handle missing expected_output gracefully (skip answer_relevancy)
  - Handle missing expected_context gracefully (skip context_recall, context_precision)
- [ ] Create Pydantic models: `RagasEvalResult`, `RagasCaseResult` in `projects/evalops/src/metrics/schemas.py`
- [ ] Add test: `projects/evalops/tests/test_ragas_runner.py` — mock LiteLLM calls, verify metric structure

## Key Design Decisions

- RAGAS requires `datasets` format — convert EvalTestCase records to RAGAS `Dataset` with columns: `question`, `answer`, `contexts`, `ground_truth`
- Judge model must NOT default to OpenAI's GPT-4o. Override via `DEEPEVAL_MODEL` / LiteLLM to use platform's own completion model
- All RAGAS calls are async-wrapped since ragas core is sync
