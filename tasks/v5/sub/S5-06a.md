# S5-06a: IfElseNode (Frontend + Conditional Evaluator Runtime)

> **Parent:** B5-06 (Workflow Builder Enhancements)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend`, `projects/guardroute`

---

## Scope

Implement the IfElse conditional branching node — frontend component and backend evaluator.

## Actionables

### Frontend
- [ ] Create `frontend/src/components/nodes/IfElseNode.tsx`:
  - Diamond-shaped node (rotated square or custom SVG path)
  - Two distinct output handles: "True" (green) and "False" (red)
  - One input handle (top)
  - Display condition summary text on the node face
  - Visual: condition icon, green/red branch indicators
- [ ] PropertyDrawer config for IfElseNode:
  - Condition type dropdown: `complexity_equals`, `output_contains`, `metadata_field`, `regex_match`, `custom_expression`
  - Field selector (dynamic based on type)
  - Operator: `==`, `!=`, `>`, `<`, `>=`, `<=`, `contains`, `matches`
  - Value input
  - "Test Condition" button (dry run with sample data)

### Backend Runtime
- [ ] Create `projects/guardroute/src/nodes/__init__.py`
- [ ] Create `projects/guardroute/src/nodes/conditional_evaluator.py`:
  - `evaluate_condition(condition_config: dict, state: GraphState) -> bool`:
    - `complexity_equals`: check `state["complexity"] == value`
    - `output_contains`: check if any subagent output contains string
    - `metadata_field`: access arbitrary state field via dot notation
    - `regex_match`: apply regex pattern to specified field
    - `custom_expression`: safe eval using `ast.literal_eval` or restricted expression parser (NO arbitrary code execution)
  - Return `True` or `False`
- [ ] Add test: `projects/guardroute/tests/test_conditional_evaluator.py`

## Key Design Decisions

- Custom expressions are sandboxed — only support simple comparisons, boolean operators, string operations. No function calls, no imports
- Condition config stored in node's `data` field in the workflow JSON
