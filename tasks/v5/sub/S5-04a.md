# S5-04a: Playground Chat API

> **Parent:** B5-04 (Model Playground)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `gateway`

---

## Scope

Create `gateway/api/playground.py` with chat completion endpoint supporting any registry model and streaming.

## Actionables

- [ ] Create `gateway/api/playground.py`
- [ ] `POST /api/playground/chat`:
  - Request: `{model_id, messages: [{role, content}], system_prompt?, temperature?, max_tokens?, attachment_ids?: [str]}`
  - Resolve model from registry (validate it exists and is enabled)
  - If `attachment_ids` provided → fetch extracted text from uploaded attachments, prepend to user message as context
  - Build full messages array with system prompt + history + current user message
  - Call `completion_with_fallback(model=model_id, messages=messages, stream=is_streaming)`
  - SSE streaming: return `EventSourceResponse` with token events + usage metadata
  - Non-streaming: return `{response, model_used, input_tokens, output_tokens, latency_ms}`
- [ ] Pydantic models: `PlaygroundChatRequest`, `PlaygroundChatResponse`, `PlaygroundMessage`
- [ ] Register router in gateway
- [ ] Add test: `gateway/tests/test_playground.py`

## Key Design Decisions

- Playground uses the same `completion_with_fallback` infra as agent invocation — unified model access
- For vision-capable models (Gemini, GPT-4V), images can be sent as base64 in message content (multimodal)
- Token limits enforced per model from registry's `context_window`
