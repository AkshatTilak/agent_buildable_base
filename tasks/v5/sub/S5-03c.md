# S5-03c: GitHub OAuth Provider

> **Parent:** B5-03 (User Authentication & RBAC)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `gateway`

---

## Scope

Implement GitHub OAuth2 login flow using `authlib`.

## Actionables

- [ ] Implement in `gateway/auth/providers.py`:
  - `github_oauth` instance configured with `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`
  - GitHub authorization URL: `https://github.com/login/oauth/authorize`
  - GitHub token URL: `https://github.com/login/oauth/access_token`
  - GitHub user API: `https://api.github.com/user`
  - GitHub email API: `https://api.github.com/user/emails` (for users with private emails)
  - Scopes: `read:user user:email`
- [ ] Implement routes in `gateway/auth/routes.py`:
  - `GET /auth/login/github`:
    - Generate state token, redirect to GitHub authorization URL
  - `GET /auth/callback/github`:
    - Exchange code for access token
    - Fetch user info from GitHub API (login, name, avatar_url, email)
    - If email is private, fetch from `/user/emails` endpoint (use primary verified email)
    - Upsert `User` record (provider="github", provider_id=GitHub user ID)
    - Same role assignment logic as Google (first user = admin)
    - Issue JWT, create session, redirect to frontend
- [ ] Handle edge cases:
  - GitHub user with no public email → use emails API
  - Same email across Google and GitHub → link to existing user account
- [ ] Add test: `gateway/tests/test_github_oauth.py`
