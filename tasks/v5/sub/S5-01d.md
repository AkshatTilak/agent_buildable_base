# S5-01d: Enhanced Eval Run Orchestration

> **Parent:** B5-01 (EvalOps Deep Integration)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `projects/evalops`

---

## Scope

Enhance the eval run pipeline (`runner/consumer.py`) to support framework selection (RAGAS/DeepEval/both), metric subset selection, and write granular per-metric results to the new `eval_metric_results` table.

## Actionables

- [ ] Modify `EvalRunRequest` Pydantic model in `api.py`:
  - Add `framework: Optional[str] = "both"` — values: `ragas`, `deepeval`, `both`
  - Add `metrics: Optional[List[str]] = None` — e.g. `["faithfulness", "toxicity"]`
  - Add `thresholds: Optional[Dict[str, float]] = None` — per-metric pass/fail thresholds
- [ ] Modify `POST /api/evalops/run` to pass framework/metrics/thresholds to runner
- [ ] Modify `projects/evalops/src/runner/consumer.py` → `process_agent_eval_run()`:
  - For each test case in the suite:
    1. Invoke the target agent (via agent_invoke from B5-02, or direct LiteLLM)
    2. Collect agent response + retrieved contexts
  - If `framework == "ragas"` or `"both"`: call `run_ragas_evaluation()`
  - If `framework == "deepeval"` or `"both"`: call `run_deepeval_evaluation()`
  - Write per-case, per-metric results to `eval_metric_results` table
  - Compute aggregate scores → update `EvalRunHistory` row
  - Set `run_status` to `"completed"` or `"failed"`
- [ ] Add `GET /api/evalops/runs/{run_id}/metrics` — query `eval_metric_results` for a run
- [ ] Update Kafka message schema to include framework/metrics params
- [ ] Add test: `projects/evalops/tests/test_eval_orchestration.py`

## Dependencies
- S5-01a (RAGAS runner)
- S5-01b (DeepEval runner)
- S5-01e (DB schema — `eval_metric_results` table)
