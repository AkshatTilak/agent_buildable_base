# S5-03f: Frontend — Route Guards, User Badge, Admin Panel

> **Parent:** B5-03 (User Authentication & RBAC)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend`

---

## Scope

Protect frontend routes based on auth state and user roles. Add user identity display and admin user management.

## Actionables

- [ ] Create `frontend/src/components/auth/AuthGuard.tsx`:
  - Wrapper component that checks `isAuthenticated` from Zustand store
  - If `isAuthEnabled && !isAuthenticated` → redirect to `/login`
  - If `isAuthEnabled=false` → pass through (backward compat)
  - Optional `requiredRole` prop: check user role, show 403 page if insufficient
- [ ] Create `frontend/src/components/auth/RoleGuard.tsx`:
  - Takes `roles: string[]` prop
  - Renders children only if current user's role is in the list
  - Otherwise renders "Insufficient Permissions" message
- [ ] Modify `App.tsx`:
  - Wrap all routes (except `/login` and `/auth/callback`) with `<AuthGuard>`
  - Apply `RoleGuard` to sensitive routes:
    - Settings: require `admin`
    - Agent create/edit: require `admin` or `editor`
    - Playground: require `admin` or `editor`
- [ ] Modify `HeaderBar.tsx`:
  - Show user avatar (circular image from `avatar_url`) + display name
  - Role badge (color-coded: admin=purple, editor=blue, viewer=gray)
  - Dropdown menu: "Profile", "Logout"
  - When auth disabled: show generic "Local User" indicator
- [ ] Create `frontend/src/components/settings/UserManagement.tsx`:
  - Admin-only tab in SettingsPage
  - Table of all users: avatar, email, display_name, provider, role, last_login, is_active
  - Role dropdown: change user role (admin/editor/viewer)
  - Deactivate/activate toggle
  - Confirmation modal for role changes
- [ ] Add API service methods: `listUsers()`, `updateUserRole()`, `deactivateUser()`

## Dependencies
- S5-03e (Login page + auth state)
- S5-03d (Backend role endpoints)
