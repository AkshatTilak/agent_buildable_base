# S5-02b: Unified Routing Endpoint

> **Parent:** B5-02 (Agent Endpoints & Routing API)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `gateway`, `projects/guardroute`

---

## Scope

Create a single smart routing endpoint that can direct a query to a specific agent, a specific model, or auto-classify and route.

## Actionables

- [ ] Add `POST /api/route` to `gateway/api/agent_invoke.py`:
  - Request body:
    ```python
    class RouteRequest(BaseModel):
        prompt: str
        agent_id: Optional[str] = None
        model_id: Optional[str] = None
        routing_strategy: Optional[str] = "auto"  # "auto" | "direct" | "round_robin"
        session_id: Optional[str] = None
        stream: Optional[bool] = False
    ```
  - Routing logic:
    1. If `agent_id` provided → direct invoke via agent_invoke logic (S5-02a)
    2. If `model_id` provided → direct `completion_with_fallback(model=model_id, ...)` (bypass agent config)
    3. If `routing_strategy == "auto"`:
       - Run GuardRoute classifier on the prompt
       - Classifier returns `required_agents` list
       - If agents match defined AgentDefinitions → invoke the best match
       - Otherwise → fall through to default completion model
    4. If `routing_strategy == "round_robin"`:
       - Select from active agents in round-robin order (Redis counter)
  - SSE streaming support
  - Return: `{response, route_decision, agent_used, model_used, latency_ms}`
- [ ] Pydantic models: `RouteRequest`, `RouteResponse`
- [ ] Add test: `gateway/tests/test_route_endpoint.py`

## Key Design Decisions

- "auto" routing reuses the existing GuardRoute classifier without going through the full scatter-gather orchestrator
- Round-robin uses a Redis atomic counter for fairness across requests
- The route decision is logged in `agent_invocation_log` with `route_decision` metadata
