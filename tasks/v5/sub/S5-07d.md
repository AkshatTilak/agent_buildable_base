# S5-07d: Per-Key Rate Limiting & Usage Tracking

> **Parent:** B5-07 (External API Gateway)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `gateway`

---

## Scope

Enforce per-API-key rate limits and track detailed usage statistics.

## Actionables

- [ ] Extend API key middleware to enforce rate limits:
  - Use Redis sliding window counter: `ratelimit:{api_key_id}:{minute_bucket}`
  - Default: 60 requests/minute (configurable per key via `rate_limit` column)
  - Return `429 Too Many Requests` with `Retry-After` header when exceeded
  - Include rate limit headers in all `/v1/*` responses:
    - `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`
- [ ] Create `APIKeyUsage` model (optional — for detailed tracking):
  ```python
  class APIKeyUsage(Base):
      __tablename__ = "api_key_usage"
      id = Column(String(36), primary_key=True, default=lambda: str(uuid.uuid4()))
      api_key_id = Column(Integer, ForeignKey("api_keys.id", ondelete="CASCADE"), index=True)
      endpoint = Column(String(100))  # /v1/chat/completions, /v1/embeddings
      model_used = Column(String(200))
      input_tokens = Column(Integer, default=0)
      output_tokens = Column(Integer, default=0)
      latency_ms = Column(Float)
      status_code = Column(Integer)
      created_at = Column(DateTime, default=datetime.utcnow)
  ```
- [ ] Log usage after each `/v1/*` request (background task)
- [ ] Add `GET /api/settings/api-keys/{id}/usage`:
  - Return: total requests, total tokens, breakdown by endpoint, breakdown by model
  - Optional: time range filter (`?days=30`)
- [ ] Generate Alembic migration if new table added
- [ ] Add test: `gateway/tests/test_api_rate_limiting.py`

## Dependencies
- S5-07c (API key middleware)

## Key Design Decisions

- Rate limiting via Redis — graceful degradation if Redis unavailable (allow all, log warning)
- Usage logging is async (BackgroundTask) to not impact response latency
- Token counts come from LiteLLM response's `usage` object
