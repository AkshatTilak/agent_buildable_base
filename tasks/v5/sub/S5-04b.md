# S5-04b: File Upload & Processing Pipeline

> **Parent:** B5-04 (Model Playground)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `gateway`, `inference`, `projects/syntraflow`

---

## Scope

Handle file uploads for the playground — extract text from PDFs, OCR images, transcribe video/audio.

## Actionables

- [ ] `POST /api/playground/upload`:
  - Accept multipart file upload
  - Validate file type: PDF, PNG, JPG, WEBP, MP4, WEBM, TXT, MD, CSV
  - Max file size: 50MB (configurable)
  - Store file temporarily in `gateway/temp_uploads/` (auto-cleanup after 1 hour)
  - Processing by file type:
    - **PDF**: Use SyntraFlow's existing extraction pipeline (`text_extractor`) or `PyPDF2`/`pdfplumber`
    - **Images (PNG/JPG/WEBP)**: Send to inference server's OCR endpoint (`/infer/ocr`)
    - **Video (MP4/WEBM)**: Send audio track to inference server's ASR endpoint (`/infer/transcribe`)
    - **Text files (TXT/MD/CSV)**: Read directly
  - Return: `{attachment_id, filename, file_type, extracted_text_preview (first 500 chars), total_chars, status}`
  - Store attachment metadata in memory dict or Redis (keyed by attachment_id, TTL 1 hour)
- [ ] `GET /api/playground/attachments/{attachment_id}`:
  - Return full extracted text for an attachment
- [ ] `DELETE /api/playground/attachments/{attachment_id}`:
  - Delete temp file and metadata
- [ ] Pydantic models: `UploadResponse`, `AttachmentInfo`
- [ ] Add test: `gateway/tests/test_playground_upload.py`

## Key Design Decisions

- Processing is synchronous for small files (<5MB), async BackgroundTask for larger files
- For vision-capable models, raw image bytes are also stored so they can be sent as multimodal input
- Temp files auto-cleaned via a periodic background task or TTL
