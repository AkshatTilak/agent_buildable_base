# S5-06d: EvalNode & MCPToolNode (Frontend + Runtime)

> **Parent:** B5-06 (Workflow Builder Enhancements)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend`, `projects/guardroute`, `projects/evalops`

---

## Scope

Two workflow nodes: one that triggers eval runs inline, one that invokes MCP tools.

## Actionables

### EvalNode

#### Frontend
- [ ] Create `frontend/src/components/nodes/EvalNode.tsx`:
  - Rectangular node with evaluation/test-tube icon
  - Input handle, two output handles: "Pass" (green) and "Fail" (red)
  - Display: suite name, framework, threshold
- [ ] PropertyDrawer: select agent (auto), suite dropdown, framework radio, metric checkboxes, threshold slider

#### Backend
- [ ] Create `projects/guardroute/src/nodes/eval_executor.py`:
  - `async def execute_eval_node(config: EvalNodeConfig, state: GraphState) -> EvalNodeResult`:
    - Get the agent's latest response from graph state
    - Run selected metrics (RAGAS/DeepEval) against the response
    - Compare aggregate score against threshold
    - Return: `{passed: bool, scores: dict, details: str}`
  - Note: this is a lightweight inline eval — uses the same runners from S5-01a/S5-01b but on a single input

### MCPToolNode

#### Frontend
- [ ] Create `frontend/src/components/nodes/MCPToolNode.tsx`:
  - Rectangular node with tool/wrench icon
  - Input handle, output handle
  - Display: server name, tool name
- [ ] PropertyDrawer: server dropdown (from MCP registry), tool dropdown (from cached tools), input parameter mapping (map graph state fields → tool input params)

#### Backend
- [ ] Create `projects/guardroute/src/nodes/mcp_tool_executor.py`:
  - `async def execute_mcp_tool(config: MCPToolConfig, state: GraphState) -> MCPToolResult`:
    - Resolve server and tool from MCP registry
    - Map input parameters from graph state
    - Invoke via `mcp_client.invoke_tool()`
    - Return: `{result, execution_time_ms, status}`
- [ ] Add tests for both executors

## Dependencies

- B5-05 (MCP Hub for MCPToolNode)
