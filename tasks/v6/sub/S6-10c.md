# S6-10c: Workflow Runs & Trace Drill-Down

> **Parent:** B6-10 (Frontend — Workflow & Eval Hub Workspaces + Admin Console)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend/src`

---

## Scope

Deliver `/hubs/workflow/:hubId/workflows/:wfId/runs` — a persisted run history for a single workflow
plus an ordered per-node trace timeline for any selected run. V5 had no run persistence at all
(execution feedback was ephemeral inside the canvas), so this is net-new UI over the new
`workflow_runs` table and the `eval_flow_traces` rows carrying `run_id`.

Boundary: this subtask owns the runs table, the run-detail drawer, the node timeline component and the
SSE progress client. Eval-side replay with assertion overlays is S6-10e and reuses the timeline
component built here.

## Actionables

- [ ] Create `frontend/src/components/hubs/workflow/WorkflowRuns.tsx` on the shared `DataTable`:
  - [ ] Columns: run id (short, `CopyButton`), status chip (`queued` / `running` / `succeeded` / `failed` / `cancelled`), trigger (`manual` / `api` / `eval` / `schedule`), version `v{n}`, node count, duration, started-by, started-at.
  - [ ] Filters for status and trigger, a date-range filter on `started_at`, and cursor/offset pagination wired to `GET /hubs/{hub_id}/workflows/{wf_id}/runs`.
  - [ ] Virtualised body (S6-12f) so a hub with thousands of runs does not degrade.
- [ ] Create `frontend/src/components/hubs/workflow/RunDetailDrawer.tsx` opened from a row, loading `GET .../runs/{run_id}`:
  - [ ] Header: status, duration, trigger, the exact `version_id` used (linking to that version in the `VersionRail`), and `error_message` when failed.
  - [ ] Collapsible `input_json` / `output_json` viewers using a JSON tree with copy-to-clipboard, never a raw `JSON.stringify` dump in a `<pre>`.
- [ ] Create `frontend/src/components/hubs/workflow/NodeTraceTimeline.tsx` rendering trace rows **in execution order**:
  - [ ] Per node: node label + type icon (reusing the icons from `frontend/src/components/nodes/`), status, latency in ms, and a bar sized proportionally to the run duration.
  - [ ] Expanding a node shows its input state, output state and the state delta it produced, plus token/model attribution when present.
  - [ ] Export the component with a `renderNodeBadge?: (nodeId: string) => ReactNode` prop so S6-10e can overlay assertion pass/fail without forking the component.
- [ ] Implement `frontend/src/services/workflowRunStream.ts` consuming the SSE stream from `POST /hubs/{hub_id}/workflows/{wf_id}/run` (`event: node_start | node_end | run_end`):
  - [ ] Append/patch timeline rows live for in-flight runs and flip the row status chip to `succeeded`/`failed` on `run_end`.
  - [ ] Reconnect with backoff on transient disconnect; on permanent failure fall back to polling `GET .../runs/{run_id}` every 3 s.
  - [ ] Close the stream on unmount and on navigation away — no orphaned `EventSource`.
- [ ] Add a **Run workflow** action (input JSON editor + validation against the published version) available to `contributor`+, which starts a run and opens the detail drawer already streaming.
- [ ] Surface `HUB_LINK_REVOKED` execution failures with the offending node highlighted in the timeline and a link to `HubLinksPanel.tsx` for maintainers, using the error-code map from S6-12c.
- [ ] Store runs in `runsByWorkflow: Record<string, WorkflowRun[]>` on [frontend/src/store/workflowSlice.ts](frontend/src/store/workflowSlice.ts); add `listRuns`, `getRun`, `startRun` helpers to [frontend/src/services/api.ts](frontend/src/services/api.ts), all taking `hubId` first.
- [ ] Add a "Last run" cell contract shared with `WorkflowLibrary.tsx` (S6-10a) so both surfaces render the same status chip component and relative-time formatting.
- [ ] Add tests: SSE events mutate exactly the addressed node row; the stream is torn down on unmount; a failed run renders `error_message` and the failing node is expanded by default.
