# S6-02b: `HubContext` Dependency & `require_hub` Factory

> **Parent:** B6-02 (Hub Access Control, Scoping & RBAC v2)  
> **Status:** `[x] Completed`  
> **Complexity:** 🔴 High  
> **Owner:** `gateway/auth`

---

## Scope

Build the single FastAPI dependency through which **every** `/hubs/{hub_id}/...` route resolves and
authorises its hub, exactly as specified in
[`hubs.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/logic/hubs.md) §5.2. The dependency
loads the hub, verifies it exists, matches the route's expected `hub_type`, is not archived (for mutating
requests), and that the caller's effective hub role meets the route's minimum — returning a frozen
`HubContext` that downstream handlers use as their scoping token.

The failure semantics are a **security control, not a UX choice**: a non-member must receive `404`, never
`403`, so hub existence and hub ids cannot be enumerated by an authenticated outsider. Every deviation from
the table below is a tenancy bug.

## Actionables

- [x] Create `gateway/auth/hub_context.py` with the immutable context object:
  ```python
  @dataclass(frozen=True)
  class HubContext:
      hub: Hub
      user: dict                 # the request.state.user payload
      hub_role: str              # effective role; "owner" for platform admins
      is_platform_admin: bool

      @property
      def hub_id(self) -> str: return self.hub.id
      @property
      def user_id(self) -> str: return self.user["id"]

      def require(self, min_role: str) -> None:
          """Secondary in-handler check for endpoints with per-verb role requirements."""
          if not hub_role_satisfies(self.hub_role, min_role):
              raise HTTPException(403, detail="Insufficient hub role")
  ```
  `frozen=True` is deliberate — a handler must never be able to widen its own scope by mutating the
  context.
- [x] Implement the dependency factory with the signature from `hubs.md` §5.2:
  ```python
  MUTATING_METHODS = frozenset({"POST", "PUT", "PATCH", "DELETE"})

  def require_hub(
      *, hub_type: str | None = None,
      min_role: str = HUB_ROLE_VIEWER,
      allow_archived: bool = False,
  ) -> Callable[..., Awaitable[HubContext]]:
      """Resolves {hub_id} from the path, asserts the hub exists, is not archived,
      matches `hub_type`, and that the caller's effective role >= `min_role`."""
  ```
  - The inner dependency signature is
    `async def _dep(request: Request, hub_id: str = Path(...), session: AsyncSession = Depends(get_db)) -> HubContext`.
  - `hub_type` accepts a single type string; validate at factory construction time that it is in
    `HUB_TYPES` and that `min_role` is in `HUB_ROLES`, raising `ValueError` at import time otherwise.
  - `allow_archived=True` is used only by the unarchive endpoint in `S6-02d`.
- [x] Implement the resolution order **exactly** as follows — the sequence matters, because checking role
      before existence, or type after role, both leak information:
  1. Load the authenticated user via `get_current_user(request)` (`401` if absent).
  2. `hub = await hub_repository.get_hub(session, hub_id)`.
  3. If `hub is None` → `404 Hub not found`.
  4. Determine `is_platform_admin = user.get("platform_role") == "admin"`.
  5. If not admin: `membership = await get_membership(session, hub_id=hub_id, user_id=user["id"])`; if
     `membership is None` → `404 Hub not found` (**never** `403`).
  6. `effective_role = "owner" if is_platform_admin else membership.hub_role`.
  7. If `hub_type` is set and `hub.hub_type != hub_type` → `404 Hub not found`.
  8. If `hub.is_archived` and `request.method in MUTATING_METHODS` and not `allow_archived` →
     `409 Hub is archived`.
  9. If not `hub_role_satisfies(effective_role, min_role)` → `403 Insufficient hub role`.
  10. Return `HubContext(...)`.
- [x] Implement the exact failure-semantics table from `hubs.md` §5.2 and encode it as a docstring table in
      the module so the intent survives future edits:
  | Condition | Status | `detail` | `code` |
  |---|---|---|---|
  | Hub does not exist | `404` | `Hub not found` | `HUB_NOT_FOUND` |
  | Hub exists, caller is not a member, not a platform admin | `404` | `Hub not found` | `HUB_NOT_FOUND` |
  | Caller is a member but role is insufficient | `403` | `Insufficient hub role` | `HUB_ROLE_INSUFFICIENT` |
  | Hub type mismatch for the route | `404` | `Hub not found` | `HUB_TYPE_MISMATCH` internally, `HUB_NOT_FOUND` on the wire |
  | Hub archived and request is mutating | `409` | `Hub is archived` | `HUB_ARCHIVED` |
  - The three `404` variants must produce **byte-identical** response bodies and comparable latency; do
    not include the `hub_id`, the hub type, or any discriminating field in the payload.
  - Log the *internal* discriminator (`HUB_TYPE_MISMATCH` vs `HUB_NOT_MEMBER`) via
    `log_security_event("HUB_ACCESS_DENIED", {...})` from `common/observability/logger.py`, never in the
    response.
- [x] Add per-request caching so a route with several hub-dependent dependencies issues one hub query and
      one membership query, not N:
  ```python
  cache: dict[str, HubContext] = request.state.__dict__.setdefault("_hub_ctx_cache", {})
  key = f"{hub_id}:{min_role}:{hub_type}"
  ```
  - Cache the resolved `(hub, membership)` pair under `request.state._hub_resolved` and recompute only the
    role/type/archive assertions per call, so different `min_role` values still evaluate correctly.
  - The cache lives on `request.state` and therefore dies with the request — never module-level, never
    keyed by user id, or a role change would not take effect until restart.
- [x] Add the convenience aliases used across the feature modules, so handlers read declaratively:
  ```python
  RequireIngestionHub  = lambda min_role="viewer": Depends(require_hub(hub_type="ingestion",  min_role=min_role))
  RequireAgentHub      = lambda min_role="viewer": Depends(require_hub(hub_type="agent",      min_role=min_role))
  RequireWorkflowHub   = lambda min_role="viewer": Depends(require_hub(hub_type="workflow",   min_role=min_role))
  RequireEvalHub       = lambda min_role="viewer": Depends(require_hub(hub_type="eval",       min_role=min_role))
  ```
  Plus `HubCtx = Annotated[HubContext, Depends(require_hub())]` for the type-annotated form.
- [x] Map the capability matrix from `hubs.md` §4.2 to the `min_role` each route class must use, and put
      this table in the module docstring as the reference for B6-04…B6-08:
  - read / list / search / preview / dry-run → `viewer`
  - create / update / ingest / invoke / run workflow / run eval → `contributor`
  - delete resource / manage datastore bindings / manage members / manage links / rename / re-slug →
    `maintainer`
  - archive / unarchive / transfer ownership / hard-delete empty hub → `owner`
- [x] Register a `HubAccessError` → HTTP exception handler in `common/observability/exceptions.py` so
      repository-layer exceptions (`HubNotFoundError`, `HubArchivedError` from `S6-01f`) raised deeper in a
      handler produce the same wire format as the dependency does.
- [x] Add `tests/test_hub_context.py` covering every row of the failure table with a real FastAPI test app
      exposing `GET`/`POST` probe routes:
  - Non-existent `hub_id` → `404`, and the body is byte-identical to the non-member `404`.
  - Member of hub A requesting hub B → `404`, and `403` never appears.
  - `viewer` on a `min_role="contributor"` route → `403`.
  - `require_hub(hub_type="agent")` against an `ingestion` hub, as a full member → `404`.
  - Archived hub: `GET` → `200`, `POST` → `409` with `code="HUB_ARCHIVED"`, and `allow_archived=True`
    lets the `POST` through.
  - Platform admin with **no** membership row → `200` with `ctx.hub_role == "owner"` on a
    `min_role="owner"` route.
  - A route declaring two `require_hub` dependencies issues exactly one `SELECT` against `hubs` (assert
    via a SQLAlchemy event counter).
