# S6-08a: Router Restructure & Typed Route Builders

> **Parent:** B6-08 (Frontend — Hub Shell, Information Architecture & Navigation)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend/src`

---

## Scope

Replace the flat V5 route table currently declared inline in [frontend/src/App.tsx](frontend/src/App.tsx) with the V6 hub-scoped route tree. Every hub workspace becomes a nested route under a single `HubShell` layout route, `/` redirects to `/hubs`, and the legacy top-level surfaces `/ingestion`, `/workflow`, `/agents` and `/evalops` are deleted outright (no redirects, no aliases — per `hubs.md` §9 the cutover is hard).

This subtask also introduces `frontend/src/routes.ts` as the single source of path truth: a typed builder module that every component, sidebar entry, command-palette action and breadcrumb must use instead of hardcoded string literals. The boundary of this subtask is *routing and path construction only* — the shell chrome, hub context and role gating land in S6-08b, and the workspace screens themselves land in S6-09/S6-10. Placeholder route elements are acceptable here so long as the tree compiles and renders.

## Actionables

- [ ] Create `frontend/src/routes.ts` exporting the canonical V6 path tree as typed builder functions, with no exported raw strings other than the static platform paths.
  - [ ] Model hub paths on the `hubs.md` §8 IA: `/hubs/:hubType/:hubId/...`, keeping `hubType` in the URL so the shell can pick its tab set before the hub fetch resolves.

- [ ] Export a matching `ROUTE_PATTERNS` object holding the React Router pattern strings (`"/hubs/:hubType/:hubId/collections/:collectionId"` etc.) so `<Route path>` declarations never diverge from the builders.
- [ ] Add a `parseHubRoute(pathname)` helper returning `{ hubType, hubId } | null`, used by the breadcrumb and hub-switcher "recents" logic in S6-08c.
- [ ] Restructure the `<Routes>` block in [frontend/src/App.tsx](frontend/src/App.tsx) into nested layout routes:
  - [ ] `<Route path={ROUTE_PATTERNS.hubShell} element={<HubShell />}>` wrapping all per-type child routes, so the hub is fetched once by the parent (contract defined in S6-08b).
  - [ ] Index route per hub type resolving to that type's overview.
  - [ ] Child routes only registered for the segments valid for that `hubType`; an ingestion path under an agent hub falls through to the hub not-found element.
- [ ] Change `<Route path="/" element={<Navigate to="/system" replace />} />` to redirect to `routes.hubs.directory()` instead.
- [ ] Delete the `/ingestion`, `/workflow`, `/agents` and `/evalops` route entries and their now-unused imports of `IngestionPanel`, `WorkflowCanvas`, `AgentHub` and `EvalPanel` from [frontend/src/App.tsx](frontend/src/App.tsx); the components themselves are removed by their respective replacement subtasks.
- [ ] Add a dedicated `frontend/src/components/hubs/HubNotFound.tsx` element rendered when the `hubId` param resolves to a `404` from the API, distinguishing "hub does not exist or you do not have access" from the generic [frontend/src/components/NotFound.tsx](frontend/src/components/NotFound.tsx) 404 page.
  - [ ] Because the API deliberately returns `404` for non-member access (`hubs.md` §5.2), the copy must not imply the hub exists.
  - [ ] Offer a primary action back to `routes.hubs.directory()`.
- [ ] Keep `/admin/*` routes behind a platform-admin guard element that renders the standard forbidden state rather than unmounting silently; non-admins never see admin paths in navigation.
- [ ] Preserve the existing `PageTransition` + `AnimatePresence` treatment, but move the `key` from `location.pathname` to the hub-shell outlet so switching tabs inside a hub animates without remounting the shell.
- [ ] Add a `routes.test`-free compile guard: run a repo-wide grep for the literal strings `"/ingestion"`, `"/workflow"`, `"/agents"`, `"/evalops"` under `frontend/src` and assert zero remaining occurrences once dependent subtasks land.
- [ ] Loading / empty / error expectations for this layer:
  - [ ] While the shell's hub fetch is pending, the route renders the shell skeleton — never a blank outlet or a flash of the directory.
  - [ ] A `404` from the hub fetch renders `HubNotFound`; a `5xx` or network failure renders a retryable error state using [frontend/src/components/shared/ErrorBanner.tsx](frontend/src/components/shared/ErrorBanner.tsx), not the not-found state.
  - [ ] Unknown nested segments inside a valid hub render the in-shell not-found so the user keeps hub navigation.
- [ ] Role gating at the routing layer: routes are **not** the gate — mutating *screens* (hub settings, members, links) remain reachable for `viewer` but render read-only per S6-08b; only platform `/admin/*` is hard-gated by route.
