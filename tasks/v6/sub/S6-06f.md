# S6-06f: Duplicate, Import/Export & Templates

## Scope

Make workflows portable. A workflow can be duplicated inside a hub, exported to a self-describing JSON
document, and imported into any workflow hub the caller can write to. Because every node reference is
hub-qualified (S6-06c), portability is fundamentally a **reference remapping** problem: an exported
graph carries a manifest of the hubs and resources it depends on, and the import path must either
resolve each dependency in the destination hub's link graph or refuse the import with an explicit,
per-reference report.

The subtask also seeds three starter templates so a new workflow hub is not an empty canvas.

## Actionables

- [x] Create `projects/guardroute/src/workflows/portability.py` exposing:
  ```python
  EXPORT_FORMAT_VERSION = "contained.workflow/v6"

  async def export_workflow(session, *, hub_id: str, workflow_id: str,
                            version_number: int | None = None) -> dict
  async def import_workflow(session, *, target_hub_id: str, document: dict,
                            actor_id: str, mapping: dict[str, str] | None = None,
                            name_override: str | None = None) -> ImportResult
  async def plan_import(session, *, target_hub_id: str, document: dict) -> ImportPlan
  ```
  `plan_import` is a dry-run that returns the resolvable/unresolvable reference report without writing anything, backing the UI's pre-import dialog.
- [x] Define the export document shape:
  ```json
  { "format": "contained.workflow/v6",
    "exported_at": "ISO-8601",
    "source": { "hub_id": "...", "hub_slug": "...", "hub_type": "workflow" },
    "workflow": { "name": "...", "slug": "...", "description": "...", "tags": [] },
    "version": { "version_number": 7, "change_note": "...", "graph": { "nodes": [], "edges": [], "viewport": {} } },
    "dependencies": [
      { "ref_key": "agent:agt_31c", "type": "agent", "source_hub_id": "hub_9f2",
        "source_hub_slug": "support-agents", "resource_id": "agt_31c",
        "resource_name": "Triage Bot", "resource_slug": "triage-bot", "node_ids": ["node_agent_2"] }
    ] }
  ```
  Build `dependencies` with `collect_references()` from S6-06c, deduplicated by `ref_key`. Export the published version by default, or the numbered version when `version_number` is given.
- [x] Never export secrets: strip credentials, tokens and headers from `WebhookNode` / `APICallNode` node data (any key matching `(?i)(authorization|api[_-]?key|token|password|secret)`), replacing them with `null` and adding a `warnings` entry naming the node so the importer knows to re-enter them.
- [x] Implement reference remapping in `import_workflow`. For each dependency, in order:
  1. If `mapping[ref_key]` is supplied by the caller, use that resource id
  2. Otherwise, if the source hub still exists **and** the destination hub holds a valid `hub_link` to it, keep the reference as-is
  3. Otherwise, attempt auto-match by `(type, resource_slug)` across the hubs the destination hub is linked to; a unique match is accepted, an ambiguous match is reported as `AMBIGUOUS_MATCH`
  4. Otherwise report `UNRESOLVED_REFERENCE`
- [x] Enforce the **cross-hub security check** on every resolved reference before writing the imported version: call `hub_resolver.resolve_linked(session, source_hub_id=target_hub_id, target_resource_type=dep.type, target_resource_id=resolved_id)`, confirm the resolved resource's own `hub_id` matches the reference's `hub_id`, and confirm the link direction is allowed (`workflow → agent`, `workflow → ingestion` per [`hubs.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/logic/hubs.md) §3.3). A caller must not be able to smuggle a foreign resource id in through the `mapping` argument.
- [x] Define the import failure contract: import is **all-or-nothing** inside one transaction. Any unresolved or forbidden reference returns `422`:
  ```json
  { "error": { "code": "IMPORT_UNRESOLVED_REFERENCES",
      "message": "3 of 5 references could not be resolved in the destination hub.",
      "references": [
        { "ref_key": "agent:agt_31c", "node_ids": ["node_agent_2"],
          "reason": "HUB_LINK_REQUIRED", "suggestions": [{"hub_id": "...", "resource_id": "...", "name": "..."}] }
      ] } }
  ```
- [x] Validate the document itself before any resolution: reject a missing or unknown `format` with `422 UNSUPPORTED_EXPORT_FORMAT`, run `validate_workflow_graph(..., strict=False)` on the incoming graph and reject topology failures with `422 GRAPH_INVALID`, and cap `nodes` at 200 and `edges` at 400 with `422 GRAPH_TOO_LARGE`.
- [x] Land the imported workflow as a **draft**: create the `workflows` row with `status="draft"`, a `(hub_id, slug)`-unique slug derived from `name_override or document.workflow.name` (suffixing `-2`, `-3`… on collision), and version 1 holding the remapped graph with `change_note = f"Imported from {source_hub_slug}"`. Do not auto-publish.
- [x] Implement `duplicate` support in this module for the cross-hub case: `version_service.duplicate(..., target_hub_id=...)` (S6-06b) delegates to `export_workflow` + `import_workflow` when the target hub differs, so remapping and link enforcement are not reimplemented. Same-hub duplication keeps references verbatim and only re-slugs.
- [x] Add `projects/guardroute/src/workflows/templates/` containing three seed documents in the export format, each already valid against the V5 node catalogue and terminal-node constraint:
  - `rag_qa.json` — `RetrievalNode → AgentNode → FinalMessageNode`, one `collection` dependency
  - `multi_agent_triage.json` — `ClassifierNode → RouterNode → MultiAgentNode → GatherNode → FinalMessageNode`, three `agent` dependencies
  - `classify_and_route.json` — `ClassifierNode → IfElseNode → {AgentNode, APICallNode} → FinalMessageNode`, one `agent` dependency
  Each template ships with `dependencies[].resource_slug` set but `resource_id` null, forcing resolution through the auto-match path.
- [x] Expose templates read-only: `async def list_templates() -> list[TemplateSummary]` and `async def instantiate_template(session, *, target_hub_id, template_key, actor_id, mapping)` reusing `import_workflow`. Templates are files on disk, not database rows, and are surfaced by the routes added in S6-06e as `GET /hubs/{hub_id}/workflows/templates` and `POST /hubs/{hub_id}/workflows/templates/{key}/instantiate` (min role `contributor`).
- [x] Add `tests/test_workflow_portability.py` covering: export→import round trip inside one hub preserves node and edge counts; import into a hub with no links returns `422 IMPORT_UNRESOLVED_REFERENCES`; import with an explicit `mapping` to a linked hub succeeds and rewrites `data.reference.hub_id`; a `mapping` pointing at an unlinked hub is rejected with `403 HUB_LINK_REQUIRED`; secrets present on export are `null`; each of the three templates instantiates and validates cleanly.
