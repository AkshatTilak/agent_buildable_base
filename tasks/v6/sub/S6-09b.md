# S6-09b: Datastore Bindings Workspace

> **Parent:** B6-09 (Frontend — Ingestion & Agent Hub Workspaces)

## Scope

Build `frontend/src/components/hubs/ingestion/DatastoresWorkspace.tsx` at `/hubs/ingestion/:hubId/datastores`. This is an entirely new surface — the V5 frontend has no equivalent; physical stores were only ever visible read-only through [frontend/src/components/InfrastructurePage.tsx](frontend/src/components/InfrastructurePage.tsx). It lets an ingestion hub declare which Qdrant / Neo4j / Postgres / OpenSearch instances back its data, per `hubs.md` §3.4.

The security boundary is the defining constraint: `credentials_encrypted` is never returned by the API, so credential fields in this UI are strictly write-only, and delete is blocked whenever collections depend on the binding. Managing bindings requires `maintainer` or above, which makes this the most tightly gated of the ingestion tabs.

## Actionables

- [ ] Create `frontend/src/components/hubs/ingestion/DatastoresWorkspace.tsx` listing the hub's bindings, grouped by `store_type` with a section per type.
  - [ ] Row contents: `store_type` icon, binding `name`, masked `connection_uri`, `Default` badge, live health chip, and last-health-check relative time.
  - [ ] Masked URI is rendered in `font-mono` and truncated with ellipsis — never wrapped — showing scheme, host and port only.
  - [ ] Health chip colours map to the design-system status accents: healthy → emerald, degraded → amber, unreachable → rose, unknown → muted.
- [ ] Surface the synthetic "Platform Default" binding for every `store_type` the hub has not declared, rendered read-only with an explanatory caption that the platform-wide value from `common/config/settings.py` is in use and can be overridden by adding a binding.
- [ ] Implement the create/edit form as a side drawer.
  ```ts
  interface DatastoreBindingDraft {
    name: string;                                     // unique within the hub
    store_type: "qdrant" | "neo4j" | "postgres" | "opensearch";
    connection_uri: string;
    credentials: { username?: string; password?: string; api_key?: string } | null; // write-only
    is_default: boolean;
    config_json: Record<string, unknown>;
  }
  ```
  - [ ] `store_type` is selectable on create and locked on edit; changing the physical store type of an existing binding is not supported.
  - [ ] Per-type connection hints and URI placeholders (e.g. `http://qdrant:6333`, `bolt://neo4j:7687`, `postgresql://host:5432/db`).
  - [ ] `config_json` is edited through a validated JSON textarea with inline parse errors and a formatting action.
- [ ] Enforce write-only credential semantics in the UI:
  - [ ] On edit, credential inputs render empty with the placeholder "Stored — leave blank to keep unchanged" and a lock icon; the form never displays or requests the existing secret.
  - [ ] Submitting with blank credential fields must omit them from the payload entirely rather than sending empty strings that would overwrite the stored secret.
  - [ ] A "Replace credentials" toggle makes the intent to overwrite explicit, and a visible note states credentials are encrypted at rest and are never returned by the API.
  - [ ] Credential values must never be written to component state that is persisted, logged, or included in error reports.
- [ ] Implement "Test connection" available both from the drawer (against the unsaved draft) and from each row (against the saved binding).
  - [ ] Show a pending spinner, then a result panel with outcome, round-trip latency, server version where available, and a redacted error message on failure.
  - [ ] Testing a draft must not persist anything; testing a saved binding updates `health_status` and `last_health_check` in the row.
- [ ] Implement "Set as default" per row, enforcing exactly one default per `(hub_id, store_type)`:
  - [ ] Setting a new default visibly clears the badge from the previous default in the same type group.
  - [ ] Confirm the change when collections already reference the current default, explaining that new collections will use the new binding while existing ones keep their explicit binding.
- [ ] Implement delete with hard dependent blocking:
  - [ ] Fetch dependents first; if any collection is backed by the binding, the delete action is disabled and the dialog lists each dependent collection by name with a link to it and instructions to re-point or delete those collections first.
  - [ ] With zero dependents, require typed confirmation of the binding name via [frontend/src/components/shared/ConfirmModal.tsx](frontend/src/components/shared/ConfirmModal.tsx).
  - [ ] The synthetic Platform Default binding can never be deleted or edited.
- [ ] Add a manual "Refresh health" action for the whole list plus a background poll while the tab is visible, pausing the poll when the tab is hidden to avoid needless requests.
- [ ] Role gating: managing bindings requires `can("manage_datastores")` (`owner`/`maintainer`). A `contributor` and a `viewer` see the list plus health chips with no create, edit, set-default, delete or credential controls rendered at all; "Test connection" is a read-only operation and stays available to `contributor` and above.
  - [ ] In an archived hub every mutating control renders disabled with the "This hub is archived and is read-only" tooltip.
- [ ] Loading / empty / error expectations:
  - [ ] Skeleton rows per type group on first load; health chips render as `unknown` until the first check returns rather than flashing a false status.
  - [ ] Zero declared bindings → an empty state that explains platform defaults are in use, with an "Add binding" action for permitted roles.
  - [ ] Failed test-connection is an inline result state on the row/drawer, never a page-level error.
  - [ ] A failed list load renders a retryable [frontend/src/components/shared/ErrorBanner.tsx](frontend/src/components/shared/ErrorBanner.tsx) and leaves the rest of the hub shell navigable.
