# S6-04f: Ingestion Data Migration, Legacy Removal & Tests

> **Parent:** B6-04 (Ingestion Hub — Collections & Datastore Bindings)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `projects/syntraflow`  

---

## Scope

Complete the hard cutover for the ingestion domain: move every existing collection, document, chunk,
video segment and job into the `ingestion/default` seed hub, rename the physical Qdrant collections to
`default__{name}`, drop `syntraflow_collections.tenant_id`, delete the flat `/api/syntraflow/*` routes,
and prove the result with `tests/test_ingestion_hub.py`.

`migrations/versions/f5e6f7a8b9c0_add_syntraflow_collections.py` created the table with a global unique
index on `name` and a `tenant_id` column; both are replaced here. No back-compat aliases are retained,
per `hubs.md` §6 and §9.

## Actionables

- [ ] Write the Alembic revision (`down_revision` = the S6-04a schema revision) performing, in order:
  - Backfill `syntraflow_collections.hub_id` to the id of the `ingestion/default` seed hub created in
    S6-01e, then `ALTER ... SET NOT NULL`.
  - Backfill `physical_name = 'default__' || lower(regexp_replace(name, '[^a-z0-9_]+', '_', 'g'))`,
    then `SET NOT NULL` and add the unique index.
  - Backfill `hub_id` (and `collection_id`, defaulting to the hub's first collection) on
    `syntraflow_documents`, `syntraflow_chunks`, `syntraflow_video_segments` and `syntraflow_jobs`,
    then `SET NOT NULL`.
  - `op.drop_index(op.f('ix_syntraflow_collections_name'), table_name='syntraflow_collections')` and
    create `UniqueConstraint("hub_id", "name")` in its place.
  - `op.drop_column("syntraflow_collections", "tenant_id")`.
  - Implement `downgrade()` (restore `tenant_id` defaulted to `'default'`, restore the global unique
    index, drop the new columns) and make `upgrade()` idempotent via inspector guards.
- [ ] Write `scripts/migrate_qdrant_collections.py` performing the **physical** rename, since Qdrant has
      no rename primitive:
  - For each `syntraflow_collections` row, if a collection named `{name}` exists and `default__{name}`
    does not, create `default__{name}` with the same `VectorParams` and copy points with
    `scroll(limit=1000, with_vectors=True)` → `upsert(batch_size=100)`.
  - Stamp `hub_id` and `collection_id` into every copied point payload during the copy so the S6-04d
    filters match pre-existing data.
  - Verify `points_count` parity before deleting the source collection; abort and log if it differs.
  - Support `--dry-run` and re-running safely (skip collections already migrated).
- [ ] Delete the flat surfaces:
  - Remove `@router.post("/ingest")`, `/ingest/text`, `/jobs`, `/jobs/{job_id}`, `/documents`,
    `/documents/{doc_id}/chunks`, `/search` and the collection routes from `projects/syntraflow/api.py`,
    leaving only `GET /status`.
  - Remove the `/api/syntraflow` mount for those paths from the gateway's dynamic route loader in
    `gateway/main.py`.
  - Grep the repository for `api/syntraflow/` and update `frontend/src/services/` callers to the
    `/hubs/{hub_id}/...` equivalents.
- [ ] Remove `tenant_id` from every remaining reference: `projects/syntraflow/src/collections/manager.py`
      (already reworked in S6-04a), any Qdrant payload builder in
      `projects/syntraflow/src/ingestion/vector_writer.py`, the `SearchRequest`/response schemas, and
      the MCP tool descriptions in `projects/syntraflow/src/mcp_server.py`.
- [ ] Create `tests/test_ingestion_hub.py` with fixtures creating two ingestion hubs
      (`support-kb`, `eng-docs`) and one user holding `contributor` on the first only.
- [ ] Test per-hub name collision: both hubs create a collection named `policies`; assert both succeed,
      that `physical_name` is `support_kb__policies` and `eng_docs__policies`, and that a third create
      of `policies` within `support-kb` returns `409`.
- [ ] Test hub isolation: a document ingested into `support-kb` is invisible to
      `GET /hubs/{eng_docs_id}/documents`, and `GET /hubs/{eng_docs_id}/documents/{support_doc_id}`
      returns `404` (not `403`); the same for jobs and collections.
- [ ] Test role enforcement per route: a `viewer` gets `403` on `POST /hubs/{id}/documents` and `200`
      on `POST /hubs/{id}/search`; a `contributor` gets `403` on `DELETE /hubs/{id}/collections/{cid}`
      and on the datastore routes; a non-member gets `404` on every route.
- [ ] Test binding encryption and masking: create a binding with credentials, assert the stored
      `credentials_encrypted` value does not contain the plaintext secret, assert the API response has
      no `credentials_encrypted` key and that `connection_uri` is masked, and assert
      `decrypt_credentials(stored)` round-trips.
- [ ] Test cross-hub ingestion rejection: calling `POST /hubs/{eng_docs_id}/documents` with a
      `collection_id` owned by `support-kb` returns `404` and creates no `syntraflow_jobs` row.
- [ ] Test the unreachable-binding path: patch `health_status = "unreachable"` on the hub's default
      qdrant binding and assert `POST /hubs/{id}/search` returns `503` rather than silently querying the
      platform default store.
- [ ] Add the ingestion-domain assertions to the `tests/test_hub_isolation.py` guard from S6-02e: no
      `select(SyntraFlow*)` in `projects/syntraflow/` or `gateway/` may filter by primary key without a
      `hub_id` predicate.
