# S6-07e: Eval Hub API Routes & Dashboard Aggregation

> **Parent:** B6-07 (Eval Hub — Polymorphic Targets & Flow Tracing)  
> **Status:** `[ ]`  
> **Complexity:** 🔴 High  
> **Owner:** `gateway/api`, `projects/evalops`  

---

## Scope

Expose the Eval Hub over nested routes. The V5 surface in
[`projects/evalops/api.py`](file:///c:/Akshat/ContAIned/projects/evalops/api.py) is a flat
`/suites`, `/runs/{agent_id}`, `/dashboard/*` router with no tenancy and an agent-shaped run history.
V6 replaces it with `/hubs/{hub_id}/eval/...`, guarded by `require_hub(hub_type="eval", min_role=...)`,
with run history keyed by the polymorphic target rather than by agent.

The dashboard aggregation is rebuilt so every panel is computed within one eval hub and filterable by
target type, specific target, framework and date range. A trace replay endpoint returns the full ordered
node timeline for any run so the UI can step through a workflow execution.

  | `GET` | `/suites/{suite_id}/export` | `viewer` (`?fmt=csv\|json`) |
  | `POST` | `/generate` | `contributor` |

  Note the case routes are nested under their suite — the flat `/cases/{case_id}` form from V5 is removed so a case can never be reached without its suite's hub check.
- [ ] Implement the run and trace routes:

  | Method | Path | Min role |
  |---|---|---|
  | `POST` | `/runs` | `contributor` (body `{suite_id, framework, async: bool}`) |
  | `GET` | `/runs` | `viewer` (`?target_type=`, `?target_id=`, `?suite_id=`, `?status=`, `?from=`, `?to=`) |
  | `GET` | `/runs/{run_id}` | `viewer` |
  | `GET` | `/runs/{run_id}/metrics` | `viewer` (`?node_only=true` filters to node assertions) |
  | `GET` | `/runs/{run_id}/traces` | `viewer` (trace replay) |
  | `POST` | `/runs/{run_id}/cancel` | `contributor` |
  | `GET` | `/targets` | `viewer` (pickable agents & workflows from linked hubs) |

- [ ] Implement `GET /targets` as the picker feed: list every agent and workflow the eval hub is linked to, grouped by source hub, each entry `{type, hub_id, hub_slug, hub_name, resource_id, name, is_available}`. Compute it from `hub_links` where `source_hub_id = ctx.hub.id` and the direction is `eval → agent` / `eval → workflow`; never enumerate hubs the eval hub is not linked to.
- [ ] Apply the **cross-hub security check** on `POST /suites`, `PUT /suites/{id}` and `POST /runs`: the body's `target.hub_id` must be a hub the eval hub holds a live link to, the target resource must actually belong to that hub, and the link is re-checked at run time by S6-07b. Return `403 HUB_LINK_REQUIRED`, `403 HUB_LINK_REVOKED` or `422 CROSS_HUB_REFERENCE_MISMATCH` accordingly, and never leak the existence of an unlinked hub — an unknown `target.hub_id` returns `422`, not `404`.
- [ ] Implement `POST /runs` with both modes: `async: true` returns `202 {"run_id", "status": "queued"}` and publishes the trigger event via the reworked `publish_eval_trigger_event(...)` (with `hub_id`); `async: false` awaits `dispatch_run` and returns `200` with the completed `EvalRunResponse`. Cap synchronous runs at 50 test cases, returning `413 SYNC_RUN_TOO_LARGE` beyond it.
- [ ] Implement trace replay at `GET /runs/{run_id}/traces`: load the eval run, follow `workflow_run_id`, and return the ordered node timeline
  ```json
  { "run_id": "...", "workflow_run_id": "...", "target": {"type":"workflow","hub_id":"...","id":"...","name":"..."},
    "nodes": [ { "sequence": 0, "node_id": "node_classify", "node_type": "ClassifierNode",
                 "latency_ms": 142.0, "timestamp": "...", "status": "succeeded",
                 "input_state": {}, "output_state": {},
                 "assertions": [ {"case_id":"...","assertion_type":"equals","passed":true,"reason":"..."} ] } ],
    "total_latency_ms": 1820.0 }
  ```
  Default `?include_state=false` returns metadata, latency and assertion outcomes only; `?include_state=true` returns the redacted states. An agent-targeted run returns `{"nodes": [], "reason": "AGENT_TARGET_HAS_NO_TRACES"}` with `200`, not an error.
- [ ] Rebuild dashboard aggregation in `projects/evalops/src/api/dashboard.py` with every query filtered by `EvalRunHistory.hub_id == hub_id` and a shared filter object `DashboardFilters(target_type, target_id, framework, date_from, date_to)`:

  | Route | Returns |
  |---|---|
  | `GET /dashboard/stats` | run counts, pass rate, avg duration, per-metric averages, node-assertion pass rate |
  | `GET /dashboard/trends` | metric averages bucketed by day over the range |
  | `GET /dashboard/comparison` | side-by-side metric comparison across up to 5 targets (mixed agent/workflow) |
  | `GET /dashboard/targets` | per-target rollup: run count, last run, latest scores, `is_available` |

  Every route accepts the same query parameters; `?target_type=` restricts to `agent` or `workflow`; `?from=` / `?to=` are ISO-8601 dates defaulting to the last 30 days; an out-of-range window (> 365 days) returns `422 DATE_RANGE_TOO_LARGE`.
- [ ] Compute aggregations in SQL (`func.avg`, `func.count`, `date_trunc`) rather than by loading rows into Python, and add a covering index `ix_eval_run_history_hub_created` on `(hub_id, created_at)` plus `ix_eval_run_history_target` on `(hub_id, target_type, target_id)`.
- [ ] Map service exceptions centrally: `SuiteNotFound → 404 SUITE_NOT_FOUND`, `EvalTargetMissing → 404 EVAL_TARGET_MISSING`, `HubLinkError → 403`, `HubArchivedError → 409 HUB_ARCHIVED`, duplicate name → `409 SUITE_NAME_TAKEN`, invalid assertion → `422 INVALID_ASSERTION_TYPE`. Write exactly one `audit_log` row for each mutating route (`create`/`update`/`delete` on suites and cases, `import`, `run`).
- [ ] Add `tests/test_eval_routes.py` covering: every route's minimum-role gate; a suite or run id from another eval hub returns `404`; `GET /targets` omits unlinked hubs; `POST /runs` against a revoked link returns `403 HUB_LINK_REVOKED`; dashboard filters narrow correctly by target type and date range; trace replay returns nodes in `sequence` order with assertion outcomes attached.
