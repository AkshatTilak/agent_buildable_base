# S6-03d: Invite Issuance & Redemption Service

> **Parent:** B6-03 (Admin User Management, Invitations & Approval Gate)  
> **Status:** `[ ]`  
> **Complexity:** 🔴 High  
> **Owner:** `gateway/auth`  

---

## Scope

Build `gateway/auth/invites.py` — the single service that issues, previews, redeems, resends, revokes
and expires `user_invites` rows. It owns all raw-token handling: generation, hashing, constant-time
comparison and the one-time return of the raw token to the creating admin when email delivery fails.

It also owns the shared `resolve_signup(...)` branch used by both the password register route (S6-03b)
and the OAuth callback (S6-03c), so the invite / auto-approve / pending decision exists in exactly one
place. The HTTP surface for admins (`/admin/invites`) lives in S6-03f; this subtask exposes only the
two public routes `GET /auth/invite/{token}` and `POST /auth/invite/{token}/accept`.

## Actionables

- [ ] Create `gateway/auth/invites.py` with the token primitives:
  ```python
  def generate_invite_token() -> tuple[str, str]:
      raw = secrets.token_urlsafe(32)                       # 256 bits of entropy
      return raw, hashlib.sha256(raw.encode()).hexdigest()  # (raw, token_hash)

  def token_matches(raw: str, stored_hash: str) -> bool:
      return hmac.compare_digest(hashlib.sha256(raw.encode()).hexdigest(), stored_hash)
  ```
  - The raw token is returned to the caller exactly once at creation and is never persisted, logged,
    or included in an audit `after_json`.
- [ ] Implement `async def create_invites(session, *, emails: list[str], platform_role: str, hub_grants: list[dict], invited_by: str, ttl_hours: int | None = None) -> list[InviteResult]`:
  - Normalise and de-duplicate emails (`strip().lower()`); validate each with `pydantic.EmailStr`.
  - Reject with `409` per-email when an `active`/`pending` user already exists for that address, and
    when a `pending` invite already exists (the partial unique index from S6-03a is the backstop).
  - Validate `platform_role in ("admin", "member")` → `422` otherwise.
  - Validate every `hub_grants[i]["hub_id"]` resolves to a non-archived `hubs` row and
    `hub_role in ("owner", "maintainer", "contributor", "viewer")` → `422` with the offending index.
  - Set `expires_at = now + timedelta(hours=ttl_hours or settings.INVITE_TTL_HOURS)`.
  - Bulk mode is partial-success: return one `InviteResult{email, status, invite_id, delivered, invite_url?}`
    per input so the admin UI can show per-row outcomes.
- [ ] Implement `async def get_invite_preview(session, raw_token: str) -> InvitePreview` backing
      `GET /auth/invite/{token}` (unauthenticated, no side effects):
  - Look up **only** by `token_hash`; never scan by email or id.
  - Return `{email, inviter_display_name, platform_role, hubs: [{id, name, hub_type, hub_role}], expires_at}`.
  - Return `404 {"detail": "Invite not found or expired"}` for missing, `revoked`, `expired` or
    past-`expires_at` rows; return `409 {"detail": "Invite already accepted"}` for `accepted`.
- [ ] Implement `async def redeem_invite(session, *, raw_token: str, email: str, provider: str, provider_id: str, password: str | None = None, display_name: str | None = None, avatar_url: str | None = None) -> User` serving **both** redemption paths:
  - **OAuth path** — called from `resolve_identity` (S6-03c) with the token carried in signed state.
  - **Password path** — called from `POST /auth/invite/{token}/accept` with `{password, display_name?}`,
    validated through `validate_password_policy` from S6-03b.
  - Reject `email != invite.email` with `409 {"detail": "Invite email mismatch"}` before any write.
  - Inside one transaction: create `User(platform_role=invite.platform_role, status="active", approved_by=invite.invited_by, approved_at=now)`,
    insert the `user_identities` row, insert one `hub_members` row per entry in `hub_grants_json`
    (skipping hubs archived since issuance and reporting them in the response), set
    `invite.status="accepted"`, `invite.accepted_at=now`, `invite.accepted_user_id=user.id`.
  - Re-validate `hub_grants_json` against live hub ids at redemption, not only at creation.
  - Use `SELECT ... FOR UPDATE` (or `with_for_update()`) on the invite row so two concurrent
    redemptions cannot both succeed; the loser sees `409`.
- [ ] Implement `async def resolve_signup(session, *, email: str, provider: str, provider_id: str, **profile) -> tuple[User, str]` returning `(user, outcome)` where outcome ∈ `invited | auto_approved | pending`:
  - Matching `pending` invite → delegate to `redeem_invite`.
  - Else domain in `settings.AUTO_APPROVE_EMAIL_DOMAINS` → create `status="active"`.
  - Else create `status="pending"`, `platform_role="member"`.
- [ ] Implement `async def resend_invite(session, invite_id: str, actor_id: str) -> InviteResult`:
  - Rotate the token (new `raw`/`token_hash`) so the previous link is invalidated, extend `expires_at`,
    increment `resend_count`, set `last_sent_at`.
  - Enforce **3 resends per invite per hour** using the shared limiter in
    `common/observability/limiter.py`, keyed `invite_resend:{invite_id}`; over-limit → `429` with
    `Retry-After`.
- [ ] Implement `async def revoke_invite(session, invite_id: str, actor_id: str) -> None` setting
      `status="revoked"` (never deleting the row) and writing an `audit_log` entry
      (`action="delete"`, `resource_type="invite"`).
- [ ] Implement `async def sweep_expired_invites(session) -> int` flipping every `pending` row with
      `expires_at < now` to `expired`, and register it as an `asyncio` background task on the gateway
      lifespan in `gateway/main.py` running every 15 minutes, guarded so a failure logs and retries
      rather than killing the loop.
- [ ] Return the delivery-failure fallback contract unchanged from the mailer (S6-03e): when
      `mailer.send(...)` returns `False`, the API still succeeds and the result carries
      `{"delivered": false, "invite_url": f"{settings.APP_PUBLIC_URL}/auth/invite/{raw}"}`; when it
      succeeds, `invite_url` is omitted entirely.
- [ ] Add `POST /auth/invite/{token}/accept` to `gateway/auth/routes.py` (unauthenticated, rate-limited
      10/hour per IP) wiring the password redemption path and issuing a session immediately on success,
      since the resulting account is already `active`.
