## Scope

Author the first of the two V6 Alembic revisions. Stage 1 is **purely additive and non-breaking**: it
creates the five new tenancy tables (`hubs`, `hub_members`, `hub_links`, `datastore_bindings`,
`audit_log`), adds a **nullable** `hub_id` to every table in
[`hubs.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/logic/hubs.md) §3.6, adds
`syntraflow_collections.physical_name` (nullable) and `users.platform_role` (nullable). Nothing is dropped,
nothing is tightened, and a V5 application can still run against the resulting schema.

All destructive work — seeding, backfilling, `SET NOT NULL`, dropping `tenant_id` / `users.role`, and
rebuilding unique constraints — is deferred to `S6-01e`. Splitting the migration this way means stage 1
can be deployed ahead of the cutover window and rolled back independently.

- [ ] Add idempotency helpers at the top of the module so a partially-applied or re-run migration is a
      no-op (required by `hubs.md` §6):
  ```python
  from alembic import op
  import sqlalchemy as sa

  def _inspector():
      return sa.inspect(op.get_bind())

  def _has_table(name: str) -> bool:
      return name in _inspector().get_table_names()

  def _has_column(table: str, column: str) -> bool:
      return _has_table(table) and column in {c["name"] for c in _inspector().get_columns(table)}
  ```
  Every `create_table` / `add_column` call in `upgrade()` is wrapped in the matching guard.
- [ ] In `upgrade()`, create the five new tables in FK-safe order — `hubs` first (it is referenced by all
      the others), then `hub_members`, `hub_links`, `datastore_bindings`, `audit_log`. Column definitions,
      `ondelete` behaviours, indexes and named unique constraints must match `S6-01a` / `S6-01b`
      byte-for-byte:
  - `hubs`: `uq_hubs_type_slug` on `(hub_type, slug)`; indexes on `slug`, `hub_type`, `owner_id`,
    `is_archived`; `owner_id` FK `users.id` `ON DELETE RESTRICT`.
  - `hub_members`: `uq_hub_members_hub_user` on `(hub_id, user_id)`; index `ix_hub_members_user_hub`.
  - `hub_links`: `uq_hub_links_source_target` on `(source_hub_id, target_hub_id)`; both FKs
    `ON DELETE CASCADE`.
  - `datastore_bindings`: `uq_datastore_bindings_hub_name`; index
    `ix_datastore_bindings_hub_store_type`.
  - `audit_log`: `hub_id` FK `ON DELETE SET NULL`; indexes `ix_audit_log_hub_created`,
    `ix_audit_log_resource`, and on `created_at`.
- [ ] Add the **nullable** `hub_id` column plus its index to each of the 14 tables in `hubs.md` §3.6,
      driven by a table-name list so the loop cannot miss one:
  ```python
  HUB_ID_TABLES = [
      "syntraflow_collections", "syntraflow_documents", "syntraflow_chunks",
      "syntraflow_video_segments", "syntraflow_jobs",
      "agent_definitions", "agent_invocation_log",
      "workflows", "eval_test_suites", "eval_run_history", "eval_flow_traces",
      "api_keys", "mcp_servers", "playground_sessions",
  ]
  for table in HUB_ID_TABLES:
      if not _has_column(table, "hub_id"):
          op.add_column(table, sa.Column("hub_id", sa.String(length=36), nullable=True))
          op.create_index(f"ix_{table}_hub_id", table, ["hub_id"])
          op.create_foreign_key(
              f"fk_{table}_hub_id", table, "hubs", ["hub_id"], ["id"], ondelete="CASCADE",
          )
  ```
  - All columns are created `nullable=True` in stage 1 **regardless** of their final nullability — the
    `SET NOT NULL` happens in `S6-01e` after the backfill.
  - `workflow_versions` and `workflow_runs` are **not** created here; they are introduced by the B6-06
    revision, which chains off stage 2.
  - `user_invites` and `user_identities` are **not** created here; they belong to the B6-03 revision.
- [ ] Add `syntraflow_collections.physical_name` as `sa.String(length=300), nullable=True` with a
      non-unique index `ix_syntraflow_collections_physical_name`. It is populated and made unique in
      stage 2. Leave `tenant_id` untouched.
- [ ] Add `users.platform_role` as `sa.String(length=20), nullable=True` (per `hubs.md` §6 step 2). Leave
      `users.role` in place — stage 2 backfills `platform_role` and drops `role`. This ordering keeps a
      running V5 gateway functional between the two revisions.
- [ ] Do **not** touch any existing unique constraint in this revision. `agent_definitions.endpoint_slug`
      and `syntraflow_collections.name` remain globally unique until stage 2 rebuilds them, so no
      duplicate-name window is opened while the two revisions are being applied.
- [ ] Implement `downgrade()` as the exact inverse, in reverse order, each step guarded by the same
      inspector helpers:
  1. Drop `users.platform_role`.
  2. Drop `syntraflow_collections.physical_name` and its index.
  3. For each table in `HUB_ID_TABLES`: drop the FK constraint, drop `ix_{table}_hub_id`, drop `hub_id`.
  4. Drop `audit_log`, `datastore_bindings`, `hub_links`, `hub_members`, `hubs` (reverse FK order).
