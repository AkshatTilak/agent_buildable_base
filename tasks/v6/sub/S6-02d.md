## Scope

Ship `gateway/api/hubs.py`: the router that lets users create and administer hubs, manage membership, and
grant or revoke cross-hub links. This is the entry point for the whole V6 route tree described in
[`hubs.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/logic/hubs.md) §5.1 — every
feature router in B6-04…B6-08 mounts beneath `/hubs/{hub_id}`.

Two invariants are load-bearing and must be enforced at this layer: a hub always has at least one `owner`
(the last owner can be neither removed nor demoted — ownership transfer is the only path), and every
mutating endpoint writes exactly one `audit_log` row.

- [x] Implement the membership routes, all gated at `maintainer` except the read:
  | Method & path | Min role | Success | Notes |
  |---|---|---|---|
  | `GET /hubs/{hub_id}/members` | `viewer` | `200` `list[HubMemberRead]` | |
  | `POST /hubs/{hub_id}/members` | `maintainer` | `201` `HubMemberRead` | body `HubMemberCreate`; `404` if the user id/email does not resolve to an **active** user; `409 ALREADY_MEMBER` on duplicate |

    otherwise `403 CANNOT_GRANT_OWNER`.
  - A member may always remove **themselves** (`DELETE` where `user_id == ctx.user_id`) regardless of role,
    unless they are the last owner.
  - Resolving an invitee by email must not disclose whether the address exists: return `404` with the
    same body for "no such user" and "user is not active".
- [x] Implement last-owner protection as a single shared guard used by both the `PATCH` and `DELETE`
      member routes and by `DELETE /hubs/{hub_id}`:
  ```python
  async def _assert_not_last_owner(session, *, hub_id: str, user_id: str) -> None:
      """409 {"code": "LAST_OWNER"} when removing/demoting `user_id` would leave the hub ownerless."""
      if member.hub_role == "owner" and await count_owners(session, hub_id=hub_id) <= 1:
          raise HTTPException(409, detail="A hub must retain at least one owner", ...)
  ```
  - The check and the mutation must run in the **same transaction** with `SELECT ... FOR UPDATE` on the
    hub row, otherwise two concurrent demotions can race the hub into an ownerless state.
- [x] Implement ownership transfer, the only sanctioned way to change `hubs.owner_id`:
  - `POST /hubs/{hub_id}/transfer-ownership` — min role `owner`, body `{"new_owner_user_id": str}`.
  - In one transaction: assert the target is an active member of the hub (auto-enrol them if not, at
    `owner`), set their `hub_role = "owner"`, set `hubs.owner_id`, demote the previous owner to
    `maintainer` unless the body sets `"keep_previous_owner": true`.
  - Returns `200 HubRead`. `422` if `new_owner_user_id == ctx.user_id`.

  | `GET /hubs/{hub_id}/links` | `viewer` | `200` `list[HubLinkRead]` | `?direction=outgoing\|incoming\|both`, default `outgoing` |
  | `POST /hubs/{hub_id}/links` | `maintainer` | `201` `HubLinkRead` | `422 INVALID_LINK_DIRECTION`; `403` if the actor lacks ≥ `contributor` on the target hub; `409` on duplicate |
  | `PATCH /hubs/{hub_id}/links/{link_id}` | `maintainer` | `200` `HubLinkRead` | `access_level` only |

- [x] Add `tests/test_hub_api.py`:

  - Duplicate `(hub_type, slug)` → `409`; the same slug under a different `hub_type` → `201`.
  - `PATCH` attempting to change `hub_type` or `owner_id` → `422`.
  - Demoting or removing the sole `owner` → `409 LAST_OWNER`; after transferring ownership the former

    no membership → `403`.
