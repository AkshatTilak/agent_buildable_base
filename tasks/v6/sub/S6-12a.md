# S6-12a: Design Token Extension for Hubs & Status

> **Parent:** B6-12 (UX, Interaction & Accessibility Uplift)  
> **Status:** `[x]`  
> **Complexity:** 🟢 Low  
> **Owner:** `frontend/src`

---

## Scope

Extend the V3/V4 token system in [frontend/src/index.css](frontend/src/index.css) so hub identity,
resource status and layout density are expressed as tokens rather than hard-coded colours scattered
through components. Today the palette stops at five accents (`--accent-emerald`, `--accent-indigo`,
`--accent-amber`, `--accent-cyan`, `--accent-rose`) plus their `*-glow` and `*-soft` variants, with no
notion of a per-hub accent or a status ramp.

Boundary: tokens and their application only — component construction is S6-12b, and
`references/structure/design_system.md` is updated in the same change so the reference never lags the
code.

## Actionables

- [x] Add hub-type accent ramps to `:root` in [frontend/src/index.css](frontend/src/index.css), each with a base, soft and glow variant so existing patterns keep working:
  - [x] `--hub-ingestion: var(--accent-cyan)`, `--hub-agent: var(--accent-indigo)`, `--hub-workflow: var(--accent-emerald)`, `--hub-eval: var(--accent-amber)` plus `--hub-*-soft` and `--hub-*-glow`.
  - [x] A neutral `--hub-archived: var(--text-muted)` used for archived hubs and resources.
- [x] Add the user-selectable accent set backing `hubs.accent` (§3.1): `--accent-violet`, `--accent-teal`, `--accent-pink`, `--accent-lime`, `--accent-slate` with matching `-soft` / `-glow`, and document that a hub's stored `accent` key resolves to `--accent-{key}`.
- [x] Implement accent resolution at the hub-shell level: a `data-hub-accent="{key}"` attribute on the hub shell root sets `--hub-accent`, `--hub-accent-soft`, `--hub-accent-glow`; every hub-scoped component references `var(--hub-accent)` and never a literal hex.
  - [x] Proof: `grep -rnE "#[0-9a-fA-F]{6}" frontend/src/components/hubs` → 0 hits.
- [x] Add status colour tokens covering every status the platform renders — `--status-pending`, `--status-active`, `--status-suspended`, `--status-rejected`, `--status-draft`, `--status-published`, `--status-archived`, `--status-running`, `--status-succeeded`, `--status-failed`, `--status-queued`, `--status-cancelled` — each with a `-soft` background and a `-fg` foreground guaranteed to meet AA on that background.
- [x] Add a density scale as `--density-*` tokens (`comfortable` default, `compact`) toggled by `data-density` on `<body>`: `--row-height`, `--control-height`, `--table-cell-padding-y`, `--section-gap`; wire a density switch into the settings surface and persist it in `frontend/src/store/settingsSlice.ts`.
- [x] Add focus and elevation tokens required by S6-12d: `--focus-ring` (2px outline colour), `--focus-ring-offset`, `--shadow-drawer`, `--shadow-modal`, `--overlay-scrim`.
- [x] Keep every existing V3/V4 token name intact (no renames of `--bg-*`, `--text-*`, `--space-*`, `--radius-*`, `--transition-*`) so the V4 spacing/typography work does not regress; new tokens are additive only.
- [x] Sweep [frontend/src/App.css](frontend/src/App.css) and replace hard-coded status/accent colour literals with the new tokens; delete duplicated colour declarations left over from removed pages.
- [x] Update [`references/structure/design_system.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/structure/design_system.md): add a "Hub Accents", "Status Tokens" and "Density Scale" section under §2/§4, list every new variable with its value and intended usage, and state the rule that components consume tokens, never literals.
- [x] Add a visual token reference page (dev-only route or Storybook-style page) rendering every hub accent, status chip and both density modes side by side for review.
