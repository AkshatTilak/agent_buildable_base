# S6-12c: Loading, Empty & Error State Standardisation

> **Parent:** B6-12 (UX, Interaction & Accessibility Uplift)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend/src`

---

## Scope

Make every async surface behave identically: a skeleton that matches the final layout, a purposeful
empty state with a primary action, and an error state carrying a human-readable message, a trace id and
a retry. Add the single source of truth mapping backend error codes to user-facing copy, and adopt
optimistic updates with rollback for cheap mutations.

Today [frontend/src/components/shared/LoadingSkeleton.tsx](frontend/src/components/shared/LoadingSkeleton.tsx),
[frontend/src/components/shared/EmptyState.tsx](frontend/src/components/shared/EmptyState.tsx) and
[frontend/src/components/shared/ErrorBanner.tsx](frontend/src/components/shared/ErrorBanner.tsx) exist
but are inconsistently used, and several surfaces still render a bare spinner or a raw `detail` string.

## Actionables

- [ ] Rework `LoadingSkeleton.tsx` into layout-aware variants — `variant="table" rows={n} columns={n}`, `"cards"`, `"detail"`, `"canvas"`, `"chart"` — each sized from the S6-12a density tokens so there is **no layout shift** when real content replaces it.
  - [ ] Proof: `grep -rn "Spinner\|<Loader" frontend/src/components | grep -v "shared/\|button" ` → 0 hits for content regions (spinners remain valid only inside buttons).
- [ ] Extend `EmptyState.tsx` to require `title`, `description` and an optional `action`, and author the copy for every V6 list: workflows, runs, suites, cases, results, hubs, hub links, members, collections, documents, jobs, invites, users, audit — e.g. "No collections yet — create your first collection".
  - [ ] Distinguish *empty* from *filtered-empty*: a filtered-empty state says "No results for these filters" and offers **Clear filters**, never the create action.
- [ ] Build `frontend/src/components/shared/ErrorState.tsx` (replacing ad-hoc uses of `ErrorBanner.tsx`) rendering: a mapped human message, the correlation/trace id with a `CopyButton`, a **Retry** action, and an optional "Show technical details" disclosure — raw stack traces and bare status codes never appear as the primary message.
- [ ] Create `frontend/src/services/errorMap.ts` translating backend error codes to `{ title, message, action }`, at minimum:
  - [ ] `HUB_LINK_REQUIRED` → "This hub isn't linked to the source hub yet." + *Request link* (maintainers see *Manage links*).
  - [ ] `HUB_LINK_REVOKED` → "The link to that hub was revoked, so this step can't run." + *Manage links*.
  - [ ] `ACCOUNT_PENDING_APPROVAL` / `ACCOUNT_SUSPENDED` / `ACCOUNT_REJECTED` → route to the matching holding screen rather than a toast.
  - [ ] `HUB_ARCHIVED` (`409`) → "This hub is archived and read-only." + *Unarchive* for owners.
  - [ ] Draft-save `409` → hands off to the conflict dialog from S6-10b rather than showing a generic error.
  - [ ] `403 Insufficient hub role` → names the required role ("You need the maintainer role in this hub").
  - [ ] `404 Hub not found` → neutral copy that does not disclose whether the hub exists.
  - [ ] Unknown codes fall through to a generic message plus the trace id — never `undefined` or `[object Object]`.
- [ ] Capture the correlation id: read the trace/request id header returned by the gateway middleware in the `request()` wrapper in [frontend/src/services/api.ts](frontend/src/services/api.ts), attach it to the thrown error, and surface it in both `ErrorState` and error toasts.
- [ ] Add optimistic updates with rollback for toggles, renames, reorders, archive/unarchive and role changes: apply locally, revert the exact previous value on failure, and show a failure toast describing what was rolled back.
- [ ] Standardise toasts through [frontend/src/components/shared/ToastProvider.tsx](frontend/src/components/shared/ToastProvider.tsx): success toasts state what happened and offer **Undo** where the API supports it; error toasts carry the mapped message plus trace id; identical consecutive toasts collapse into a count.
- [ ] Add a `frontend/src/components/shared/AsyncBoundary.tsx` wrapper accepting `{ loading, error, empty, onRetry, skeleton }` so a surface declares its states once instead of branching inline; adopt it in every hub workspace route.
- [ ] Ensure [frontend/src/components/shared/ErrorBoundary.tsx](frontend/src/components/shared/ErrorBoundary.tsx) renders the same `ErrorState` visual for render-time crashes, includes the route path, and offers *Reload this view* without a full page refresh.
- [ ] Add tests: each error code maps to its expected copy, a failed optimistic rename restores the original name, and the filtered-empty state renders *Clear filters* rather than the create action.
