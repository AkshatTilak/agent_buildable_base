# S6-09a: Ingestion Hub Overview & Collections Workspace

> **Parent:** B6-09 (Frontend — Ingestion & Agent Hub Workspaces)  
> **Status:** `[x]`  
> **Complexity:** 🔴 High  
> **Owner:** `frontend/src`

---

## Scope

Build the first two tabs of the ingestion hub inside `HubShell`: the overview at `/hubs/ingestion/:hubId` and the collections workspace at `/hubs/ingestion/:hubId/collections`. New components land in `frontend/src/components/hubs/ingestion/`.

`CollectionsWorkspace.tsx` replaces [frontend/src/components/collections/CollectionManager.tsx](frontend/src/components/collections/CollectionManager.tsx), which is deleted along with its flat `api.getCollections(tenantId?)` / `createCollection` / `deleteCollection` call sites. The collection detail view absorbs [frontend/src/components/collections/RetrievalTester.tsx](frontend/src/components/collections/RetrievalTester.tsx) as an embedded, collection-scoped tester rather than the current standalone tab inside [frontend/src/components/IngestionPanel.tsx](frontend/src/components/IngestionPanel.tsx). All reads and writes go through the hub-scoped client from S6-08d.

## Actionables

- [ ] Create `frontend/src/components/hubs/ingestion/IngestionOverview.tsx` as the hub index route, built from stat cards on the `--bg-surface` token.
  - [ ] Cards: collection count, document count, total chunks / storage footprint, active jobs, binding health summary (healthy / degraded / unreachable counts).
  - [ ] A recent-activity list combining latest ingest jobs and recently created collections, each row deep-linking into the relevant tab.
  - [ ] Quick actions row — "New collection", "Upload documents", "Add datastore" — each wrapped in the `Gated` component from S6-08b.
- [ ] Create `frontend/src/components/hubs/ingestion/CollectionsWorkspace.tsx` for the collections list.
  - [ ] Row/card per collection showing name, vector count, embedding model id, dimension, retrieval strategy, backing binding names, and last-ingest relative time.
  - [ ] Inline debounced search plus a strategy filter; sort by name, vectors or last ingest.
  - [ ] Show the physical store name (`{hub_slug}__{collection_name}`) in `font-mono` `--text-muted` as a secondary line, since that is what appears in the Qdrant console.
- [ ] Implement the create-collection modal.
  ```ts
  interface CollectionCreateDraft {
    name: string;                      // unique within the hub
    description: string;
    embedding_model_id: string;        // from the platform model registry
    dimension: number;                 // auto-filled from the model, read-only unless overridden
    strategy: "vector" | "graph" | "hybrid";
    binding_ids: string[];             // datastore bindings backing this collection
  }
  ```
  - [ ] Populate the embedding model select from the platform model registry (embedding-role models only) and auto-fill `dimension` on selection, with an explicit "Override dimension" escape hatch that warns it must match the model.
  - [ ] Binding selection lists this hub's `datastore_bindings` grouped by `store_type`, pre-selecting each type's default and surfacing the synthetic read-only "Platform Default" binding when the hub declares none.
  - [ ] Validate name uniqueness within the hub client-side against the loaded list before submitting, and surface the server's uniqueness error inline on the name field.
- [ ] Implement rename and delete:
  - [ ] Rename is inline with the same uniqueness validation as create.
  - [ ] Delete requires typed confirmation of the collection name via [frontend/src/components/shared/ConfirmModal.tsx](frontend/src/components/shared/ConfirmModal.tsx) and states the document/vector counts that will be destroyed.
  - [ ] If the collection is bound by agents in linked agent hubs, list those dependents in the dialog before allowing deletion.
- [ ] Create `frontend/src/components/hubs/ingestion/CollectionDetail.tsx` at `routes.ingestionHub.collection(hubId, collectionId)` with three stacked regions.
  - [ ] **Documents** — the documents belonging to this collection, reusing the hub-scoped document table from S6-09c in a filtered mode rather than duplicating it.
  - [ ] **Strategy configuration** — chunking, embedding and retrieval-strategy settings for the collection, with an explicit dirty-state save/discard bar.
  - [ ] **Retrieval tester** — the embedded, collection-scoped variant of the existing tester.
- [ ] Refactor the retrieval tester into `frontend/src/components/hubs/ingestion/RetrievalTester.tsx` taking `{ hubId, collectionId }` props instead of reading global state.
  - [ ] Query box, strategy override selector, top-k control, and result cards showing score, source document, chunk excerpt and the binding the result came from.
  - [ ] Results are non-mutating, so the tester remains fully usable for `viewer` and inside archived hubs.
- [ ] Route every call through the S6-08d client namespace (`api.ingestion.collections.*`, `api.ingestion.search`), passing `hubId` first; delete [frontend/src/components/collections/CollectionManager.tsx](frontend/src/components/collections/CollectionManager.tsx) and [frontend/src/components/collections/RetrievalTester.tsx](frontend/src/components/collections/RetrievalTester.tsx) once no imports remain in [frontend/src/components/IngestionPanel.tsx](frontend/src/components/IngestionPanel.tsx).
- [ ] Role gating: create, rename, delete and strategy-save controls are wrapped in `Gated` — a `viewer` sees none of them, a `contributor` sees create/edit but not delete (deletion requires `maintainer` per `hubs.md` §4.2), and in an archived hub every control renders disabled with the archived tooltip while search and the retrieval tester stay live.
- [ ] Loading / empty / error expectations:
  - [ ] Overview stat cards render individually as [frontend/src/components/shared/LoadingSkeleton.tsx](frontend/src/components/shared/LoadingSkeleton.tsx) blocks; one failing metric does not blank the page.
  - [ ] Zero collections → [frontend/src/components/shared/EmptyState.tsx](frontend/src/components/shared/EmptyState.tsx) explaining what a collection is, with a create action for permitted roles and no action for a `viewer`.
  - [ ] A collection with zero documents shows an in-detail empty state pointing at the upload flow.
  - [ ] Retrieval returning no hits is an explicit "No matches above the score threshold" state, not an error.
  - [ ] Load failures render a retryable [frontend/src/components/shared/ErrorBanner.tsx](frontend/src/components/shared/ErrorBanner.tsx) scoped to the failing region, keeping the rest of the workspace usable.
