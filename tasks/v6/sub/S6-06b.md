# S6-06b: Version Lifecycle Service

> **Parent:** B6-06 (Workflow Hub — Multi-Workflow Management & Versioning)  
> **Status:** `[ ]`  
> **Complexity:** 🔴 High  
> **Owner:** `projects/guardroute`  

---

## Scope

Implement the draft/publish/restore state machine that governs `workflow_versions`. Editing the canvas
mutates the **draft** version in place; publishing freezes that draft and the next edit opens a fresh
draft. Concurrent editors are separated by an optimistic lock: every draft carries a `version_etag`,
`PUT .../draft` must present a matching `If-Match`, and a stale write returns `409` with the server's
current graph so the UI can render a non-destructive conflict dialog instead of losing work.

All of this lives in a pure service module — `projects/guardroute/src/workflows/version_service.py` —
with no FastAPI imports, so it is unit-testable and reusable by the run orchestrator (S6-06d) and the
import/duplicate paths (S6-06f). Route wiring is S6-06e.

## Actionables

- [ ] Create `projects/guardroute/src/workflows/version_service.py` exposing:
  ```python
  async def get_draft(session, *, hub_id: str, workflow_id: str) -> WorkflowVersion
  async def update_draft(session, *, hub_id: str, workflow_id: str, graph: dict,
                         expected_etag: str | None, actor_id: str,
                         change_note: str | None = None) -> DraftUpdateResult
  async def publish(session, *, hub_id: str, workflow_id: str, actor_id: str,
                    change_note: str | None = None) -> WorkflowVersion
  async def restore(session, *, hub_id: str, workflow_id: str, version_number: int,
                    actor_id: str) -> WorkflowVersion
  async def duplicate(session, *, hub_id: str, workflow_id: str, new_name: str,
                      actor_id: str, target_hub_id: str | None = None) -> WorkflowDefinition
  async def list_versions(session, *, hub_id: str, workflow_id: str) -> list[WorkflowVersion]
  def compute_etag(version: WorkflowVersion) -> str
  def diff_versions(base_graph: dict, head_graph: dict) -> GraphDiff
  ```
  Every function takes `hub_id` as a required keyword and includes it in the `WHERE` clause of the workflow lookup.
- [ ] Implement `compute_etag`:
  ```python
  def compute_etag(version) -> str:
      payload = json.dumps(version.graph_json, sort_keys=True, separators=(",", ":"))
      digest = hashlib.sha256(f"{version.id}:{version.version_number}:{payload}".encode()).hexdigest()
      return f'W/"{digest[:32]}"'
  ```
  The etag changes whenever the graph content or the version identity changes, and is stable across processes and restarts (no timestamps, no `id()`).
- [ ] Implement `get_draft` with lazy draft creation: if `workflow.draft_version_id is None`, create a new `WorkflowVersion` with `version_number = max(version_number) + 1`, `graph_json` copied from the published version (or `{"nodes": [], "edges": []}` for a brand-new workflow), and point `workflow.draft_version_id` at it in the same transaction.
- [ ] Implement `update_draft` optimistic locking:
  - `expected_etag is None` is only permitted when the workflow has never been published; otherwise `428 ETAG_REQUIRED`
  - On mismatch, raise `DraftConflict` carrying the server state; the route layer renders it as `409` with body
    ```json
    { "error": { "code": "VERSION_CONFLICT",
                 "message": "Draft was modified by another editor.",
                 "server_etag": "W/\"…\"",
                 "server_version_number": 7,
                 "server_graph": { "nodes": [], "edges": [] },
                 "updated_by": "user_id", "updated_at": "ISO-8601" } }
    ```
  - On success, mutate the draft row in place (drafts are the **only** mutable versions), re-run graph validation via S6-06c, store `is_valid` and `validation_json`, and return the new etag
- [ ] Implement `publish`:
  - Refuse to publish an invalid graph — raise `WorkflowValidationError` mapped to `422` with the full per-node error list from S6-06c
  - Re-validate every qualified node reference through `hub_resolver` at publish time; a link revoked since the last edit fails with `403 HUB_LINK_REVOKED` naming the offending node
  - Freeze: set `workflow.published_version_id = draft.id`, `workflow.status = "published"`, `workflow.draft_version_id = None`. The next `get_draft` call opens a fresh version — published versions are never mutated
  - Persist `change_note` on the frozen version
- [ ] Implement `restore(version_number)`: copy the target version's `graph_json` into a **new** version numbered `max + 1` with `change_note = f"Restored from v{version_number}"`, set it as the draft, and leave the published pointer untouched. Never renumber or delete history.
- [ ] Implement `duplicate`: create a new `WorkflowDefinition` in `target_hub_id or hub_id` with a unique `(hub_id, slug)`, copy the source's published (or draft, if never published) graph as version 1, set `status="draft"`. When `target_hub_id` differs, delegate reference remapping to S6-06f rather than copying node references blindly.
- [ ] Implement `diff_versions` returning a structured, UI-consumable diff:
  ```python
  @dataclass
  class GraphDiff:
      nodes_added: list[str]
      nodes_removed: list[str]
      nodes_changed: list[NodeChange]     # node_id + list of changed dotted field paths
      edges_added: list[str]              # f"{source}->{target}"
      edges_removed: list[str]
      edges_changed: list[str]
  ```
  Node identity is `node["id"]`; a node is "changed" when its `type` or normalised `data` dict differs. Ignore `position` and `viewport` so a pure canvas re-layout produces an empty diff.
- [ ] Enforce archived-hub semantics: `update_draft`, `publish`, `restore` and `duplicate` raise `HubArchivedError` → `409 HUB_ARCHIVED` when `hub.is_archived`; `get_draft`, `list_versions` and `diff_versions` remain readable.
- [ ] Wrap each mutating operation in a single transaction and re-read the workflow row `WITH FOR UPDATE` (`select(...).with_for_update()`) before comparing etags, so two simultaneous saves cannot both observe a fresh etag.
- [ ] Add `tests/test_workflow_versions.py` covering: draft auto-creation; publish freezes and clears the draft pointer; the post-publish edit opens `v(n+1)`; stale `If-Match` → `DraftConflict` with the server graph; restore creates a new version and preserves history; `diff_versions` ignores position-only moves.
