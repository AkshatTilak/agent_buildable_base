# S6-10e: Eval Results Dashboard & Trace Replay

> **Parent:** B6-10 (Frontend — Workflow & Eval Hub Workspaces + Admin Console)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend/src`

---

## Scope

Build the read side of the eval hub: per-metric aggregates, historical trend charts, per-case
drill-down, and — for workflow-targeted runs — a trace replay view that overlays per-node assertion
pass/fail onto the node timeline from S6-10c. Also deliver the CSV/JSON export controls for results
(suite-level case import/export lives in S6-10d).

This replaces the dashboard blocks in
[frontend/src/components/EvalPanel.tsx](frontend/src/components/EvalPanel.tsx) and the standalone
[frontend/src/components/eval/FlowTraceVisualizer.tsx](frontend/src/components/eval/FlowTraceVisualizer.tsx),
both of which key off a global `agent_id` rather than a hub-scoped run.

## Actionables

- [ ] Create `frontend/src/components/hubs/eval/EvalResults.tsx` at `/hubs/eval/:hubId/runs/:runId`:
  - [ ] Header: suite name, target (type + hub + resource + version), framework(s), started-by, duration, overall pass rate.
  - [ ] Per-metric aggregate cards (mean, median, min, threshold, pass/fail) rendered from `GET /hubs/{hub_id}/eval/runs/{run_id}` metric results — colour **plus** label per S6-12d.
- [ ] Create `frontend/src/components/hubs/eval/MetricTrendChart.tsx`:
  - [ ] Line chart of each metric across the suite's run history with a threshold reference line and a run-count/date-range selector (7 / 30 / 90 days).
  - [ ] Clicking a point navigates to that run; hovering shows run id, score and delta versus the previous run.
- [ ] Create `frontend/src/components/hubs/eval/CaseResultsTable.tsx` on the shared `DataTable`: per-case row with input, expected, actual, per-metric scores, and an overall pass/fail chip; filterable to failures only; expanding a row shows the full actual output with a diff against `expected_output`.
- [ ] Create `frontend/src/components/hubs/eval/TraceReplay.tsx` for workflow-targeted runs:
  - [ ] Reuses `NodeTraceTimeline.tsx` from S6-10c via its `renderNodeBadge` prop rather than duplicating timeline logic.
  - [ ] Overlays each node-level assertion as a pass/fail badge on its node, with the expected vs actual value in the expanded row.
  - [ ] A case selector steps through cases (`[` / `]` shortcuts) re-rendering the timeline for that case's trace.
  - [ ] Nodes with no assertion render neutrally and are visually distinct from "passed".
- [ ] Add a run-comparison view: select two runs of the same suite and render per-metric and per-case deltas, flagging regressions (score dropped below threshold) in a dedicated "Regressions" section.
- [ ] Add export controls on the results view: **Export CSV** (one row per case × metric) and **Export JSON** (full run payload including traces), generated client-side from the loaded run plus a server export endpoint fallback for large runs.
- [ ] Add live progress for an in-flight eval run: a progress bar of cases completed, and the results view populating incrementally rather than blocking on completion.
- [ ] Route all loading/empty/error states through the S6-12c shared components, including an explicit "This run has no traces — the target was an agent, not a workflow" empty state for the replay tab.
- [ ] Ensure every read call is hub-scoped (`/hubs/{hub_id}/eval/...`); remove usage of `getEvalRuns(agentId)`, `getRunMetrics(runId)` and `getEvalDashboard()` from [frontend/src/services/api.ts](frontend/src/services/api.ts) in favour of the hub-scoped replacements.
- [ ] Add tests: assertion badges map to the correct node id, the regression section lists only metrics that crossed a threshold downwards, and CSV export row count equals cases × metrics.

## Dependencies
- S6-10d (runs must be launchable)
- S6-10c (`NodeTraceTimeline`)
- S6-12b, S6-12c (shared table and state components)
