# S6-03f: Admin Users, Invites & Audit API

> **Parent:** B6-03 (Admin User Management, Invitations & Approval Gate)  
> **Status:** `[x]`  
> **Complexity:** 🔴 High  
> **Owner:** `gateway/api/admin_users.py`  

---

## Scope

Expose the platform-admin console API: the full user lifecycle (list, detail, update, approve, reject,
suspend, reinstate, delete), invite management (create/bulk, list, resend, revoke) and the audit-log
reader. This replaces the thin `/auth/users` endpoints currently sitting at the bottom of
`gateway/auth/routes.py`, which are guarded by the V5 `require_role("admin")` helper and operate on the
removed `role` / `is_active` columns.

Every mutating route writes exactly one `audit_log` row and enforces the server-side guardrails from
`user_management.md` §4 — an admin cannot demote, suspend or delete themselves, the system never drops
to zero active admins, and a hub owner cannot be deleted before ownership is transferred.

## Actionables

- [x] Create `gateway/api/admin_users.py` with `router = APIRouter(prefix="/admin", tags=["admin"])`
      and a router-level `dependencies=[Depends(require_platform_admin)]` (the narrowed `admin`/`member`
      dependency from S6-02a); register it in `gateway/main.py` next to the existing API routers.
- [x] Implement the user read routes:
  - `GET /admin/users` — offset/limit pagination (`limit` max 200), filters `status`, `platform_role`,
    `hub_id` (join `hub_members`), free-text `q` matched with `ILIKE` against `email` and
    `display_name`; returns `{items, total, limit, offset}`.
  - `GET /admin/users/pending` — `status = "pending"` ordered by `created_at ASC`, plus a `count` field
    that the sidebar badge polls.
  - `GET /admin/users/{id}` — `UserDetail` including `identities`, `hub_memberships`
    (hub name/type/role) and the 20 most recent `audit_log` rows where `actor_user_id = id`.
- [x] Implement `PATCH /admin/users/{id}` accepting `{display_name?, platform_role?}`:
  - `platform_role` must be `admin` or `member` → `422` otherwise.
  - Demoting `admin → member` revokes all of that user's `UserSession` rows.
  - Blocked by the self-action and last-admin guardrails below.
- [x] Implement the lifecycle transitions, each rejecting an illegal source state with
      `409 {"detail": "Invalid state transition"}`:
  - `POST /admin/users/{id}/approve` — body `{platform_role?, hub_grants?: [{hub_id, hub_role}]}`;
    requires `status == "pending"`; sets `status="active"`, `approved_by=<actor>`, `approved_at=now`,
    creates the `hub_members` rows, sends the `approved` template.
  - `POST /admin/users/{id}/reject` — body `{reason?}`; requires `status == "pending"`; sets
    `status="rejected"`, deletes all sessions, sends the `rejected` template with the reason.
  - `POST /admin/users/{id}/suspend` — requires `status == "active"`; sets `status="suspended"` and
    deletes every `UserSession` row for the user in the same transaction.
  - `POST /admin/users/{id}/reinstate` — requires `status == "suspended"`; sets `status="active"`.
  - `DELETE /admin/users/{id}` — hard delete; `409 {"detail": "User owns hubs; transfer ownership first", "hubs": [...]}` when
    `SELECT id FROM hubs WHERE owner_id = :id` is non-empty.
- [x] Implement the guardrails as reusable helpers at the top of the module, called by every mutating
      user route before any write:
  ```python
  def assert_not_self(actor_id: str, target_id: str, action: str) -> None:
      """409 ACTION_ON_SELF for demote / suspend / reject / delete."""

  async def assert_admin_floor(session, target_id: str) -> None:
      """409 LAST_ACTIVE_ADMIN if the change would leave zero users with
      platform_role='admin' AND status='active'."""
  ```
  - `assert_admin_floor` must count with `SELECT count(*) ... FOR UPDATE`-equivalent locking (or a
    serialisable transaction) so two concurrent demotions cannot both pass.
- [x] Implement the invite routes as thin wrappers over `gateway/auth/invites.py` (S6-03d):
  - `POST /admin/invites` — body `{emails: list[str], platform_role: str = "member", hub_grants: list = [], ttl_hours?: int}`;
    returns `201` with the per-email `InviteResult` list including the one-time `invite_url` when
    `delivered` is `false`.
  - `GET /admin/invites` — filter by `status`, paginated; the response **never** contains `token_hash`.
  - `POST /admin/invites/{id}/resend` — `429` when the 3/hour/invite limit trips.
  - `DELETE /admin/invites/{id}` — revoke (soft), returns `204`.
- [x] Implement `GET /admin/audit` reading `audit_log` with filters `actor_user_id`, `hub_id`,
      `resource_type`, `action`, `from`/`to` (ISO-8601 dates), `limit`/`offset`, ordered
      `created_at DESC`, capped at 500 rows per page.
- [x] Add `async def write_audit(session, *, actor, action, resource_type, resource_id, summary, before, after, request, hub_id=None) -> None`
      to `gateway/api/admin_users.py` (or reuse the S6-02e helper if it already exists) and call it on
      every mutating route in this module.
  - Capture `ip_address` from `X-Forwarded-For` (first hop) falling back to `request.client.host`.
  - `before_json`/`after_json` must be redacted dictionaries — never include `password_hash`,
    `token_hash` or raw tokens.
- [x] Rate-limit `POST /admin/invites` to 60/hour per admin using
      `common/observability/limiter.py`, keyed `admin_invites:{actor_id}`.
- [x] Delete the superseded admin endpoints from `gateway/auth/routes.py`
      (`GET /auth/users`, the role-update and activation handlers) and remove `UserRoleUpdate`; update
      `frontend/src/services/` callers to the new `/admin/*` paths.
