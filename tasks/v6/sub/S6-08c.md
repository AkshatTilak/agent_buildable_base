# S6-08c: Sidebar, Hub Switcher & Command Palette

> **Parent:** B6-08 (Frontend — Hub Shell, Information Architecture & Navigation)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend/src`

---

## Scope

Rebuild global navigation around hubs. [frontend/src/components/Sidebar.tsx](frontend/src/components/Sidebar.tsx) currently hardcodes a flat eight-item `navItems` array pointing at `/ingestion`, `/workflow`, `/agents` and `/evalops`; that array is replaced by three semantic groups — **Hubs** (four expandable type groups listing the user's hubs), **Platform**, and **Admin** (platform admins only, with a live pending-approval badge).

This subtask also adds `frontend/src/components/layout/HubSwitcher.tsx`, a `Cmd+K`-reachable fuzzy switcher over every hub the user belongs to with localStorage-backed recents, and extends the existing [frontend/src/components/layout/CommandPalette.tsx](frontend/src/components/layout/CommandPalette.tsx) with hub-aware actions that operate on the currently active hub. The `Cmd+K` handler currently lives in [frontend/src/App.tsx](frontend/src/App.tsx) and must be reworked to arbitrate between the two surfaces rather than duplicated.

## Actionables

- [ ] Rework [frontend/src/components/Sidebar.tsx](frontend/src/components/Sidebar.tsx) into three collapsible groups, deleting the existing flat `navItems` const and its `⌘1–⌘8` shortcut labels.
  - [ ] **Hubs** — one expandable row per `hub_type` (Ingestion, Agent, Workflow, Eval) showing the user's hubs of that type, each with its `accent` dot and `icon`.
  - [ ] **Platform** — Playground, MCP Registry (renamed from the current "MCP Hub" label), Model Registry, Infrastructure, System.
  - [ ] **Admin** — Users, Invites, Approvals, Audit Log; the entire group is absent for non-admins, not disabled.
- [ ] Drive every sidebar destination through the `routes` builders from `frontend/src/routes.ts`; no path string literals remain in the sidebar.
- [ ] Persist per-group expanded/collapsed state and the collapsed-rail state together in [frontend/src/store/settingsSlice.ts](frontend/src/store/settingsSlice.ts) alongside the existing `sidebarCollapsed` flag.
  - [ ] Auto-expand the type group containing the active hub on navigation.
  - [ ] In the 20-unit collapsed rail, hub groups reduce to type icons with a hover flyout listing that type's hubs.
- [ ] Show a "+ New hub" affordance at the foot of the Hubs group, hidden when the user is a `member` and `ALLOW_MEMBER_HUB_CREATION` is disabled (flag surfaced on the session payload).
- [ ] Add a live pending-approval count badge on the Admin group header, polled from the admin approvals endpoint and rendered in `--amber-soft` when greater than zero; the badge is suppressed entirely for non-admins.
- [ ] Replace the sidebar Quick Actions block (currently navigating to `/ingestion` and `/agents`) with hub-contextual actions that only appear when a hub is active and `can("create_resource")` passes.
- [ ] Create `frontend/src/components/layout/HubSwitcher.tsx`.
  ```ts
  interface HubSwitcherProps {
    isOpen: boolean;
    onClose: () => void;
  }

  interface HubSwitcherEntry {
    hubId: string;
    hubType: HubType;
    name: string;
    slug: string;
    accent: string | null;
    icon: string | null;
    isArchived: boolean;
    hubRole: HubRole;
    lastVisitedAt: number | null;
  }
  ```
  - [ ] Fuzzy match over `name`, `slug` and `hub_type` with subsequence scoring; matched substrings are highlighted in the result row.
  - [ ] Group results by hub type with the user's `hub_role` shown as a trailing caption badge.
  - [ ] Archived hubs are excluded by default and revealed by an "Include archived" toggle inside the dialog.
  - [ ] Full keyboard model: `↑`/`↓` to move, `Enter` to jump, `Esc` to close, and no mouse requirement.
- [ ] Track recents in `localStorage` under a versioned key (e.g. `contained.hub.recents.v1`) holding at most 8 `{ hubId, hubType, lastVisitedAt }` entries, written by `HubShell` on mount and surfaced above search results when the query is empty.
  - [ ] Recents referencing hubs the user no longer belongs to are silently dropped on read.
- [ ] Rework the global keyboard handler in [frontend/src/App.tsx](frontend/src/App.tsx) so `Cmd/Ctrl+K` opens the Hub Switcher and `Cmd/Ctrl+Shift+P` opens the Command Palette, with only one dialog open at a time and focus returned to the previously focused element on close.
- [ ] Extend [frontend/src/components/layout/CommandPalette.tsx](frontend/src/components/layout/CommandPalette.tsx) with a hub-aware command set, replacing the current static `commands` array's flat navigation entries.
  - [ ] Global: "Create hub", "Go to Hub Directory", "Open Playground", "Open MCP Registry", "Invite user" (admin only).
  - [ ] Contextual, only registered when a hub is active and gated by `useHubPermissions()`: "New collection in {hub}", "New agent in {hub}", "New workflow in {hub}", "New eval suite in {hub}", "Manage members", "Manage links".
  - [ ] Jump-to-resource entries that search collections/agents/workflows within the active hub and navigate straight to the resource route.
  - [ ] A `Hub` category section header so contextual commands are visually distinct from global ones.
- [ ] Role gating and archived behaviour across all three surfaces: a `viewer` sees no "New …" entries in the sidebar, switcher or palette; when the active hub is archived those entries render disabled with the "This hub is archived and is read-only" tooltip in the palette and are omitted from the sidebar.
- [ ] Loading / empty / error expectations:
  - [ ] Sidebar hub lists render three skeleton rows per type group while the hub list request is in flight.
  - [ ] A type group with no hubs renders an inline "No {type} hubs yet" caption plus a create link (or nothing at all for a member without creation rights).
  - [ ] A failed hub list request renders a compact inline retry row in the sidebar and leaves Platform/Admin navigation fully usable.
  - [ ] The switcher shows "No hubs match '{query}'" for empty search results and a distinct "You are not a member of any hub yet" state when the user has zero hubs.
