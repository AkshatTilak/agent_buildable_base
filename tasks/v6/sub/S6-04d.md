# S6-04d: Hub-Scoped Retrieval & Strategy Config

> **Parent:** B6-04 (Ingestion Hub — Collections & Datastore Bindings)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `projects/syntraflow`  

---

## Scope

Make retrieval hub-aware. `projects/syntraflow/src/retrieval.py::RetrievalEngine` currently searches a
hard-coded `"syntraflow_chunks_v1"` Qdrant collection with no tenancy filter, takes a `VectorClient`
injected by the caller, and picks its strategy from the global `settings.RAG_STRATEGY`. In V6 every
query is bound to a hub, targets one or more of that hub's collections by `physical_name`, applies a
mandatory `hub_id` payload filter, and honours the per-collection `retrieval_config_json` written in
S6-04a.

The boundary is the retrieval engine and its strategy resolution; the HTTP surface
(`POST /hubs/{hub_id}/search`) is S6-04e.

## Actionables

- [x] Change `RetrievalEngine.__init__` to `def __init__(self, db: AsyncSession, hub_id: str) -> None`
      and obtain its clients internally via `resolve_vector_client(db, hub_id)` /
      `resolve_graph_client(db, hub_id)` — the caller no longer supplies a `VectorClient`.
- [x] Add the mandatory hub filter helper and apply it to **every** Qdrant query:
  ```python
  def _hub_filter(hub_id: str, collection_ids: list[str] | None,
                  metadata: dict | None) -> qdrant_models.Filter:
      must = [qdrant_models.FieldCondition(key="hub_id",
              match=qdrant_models.MatchValue(value=hub_id))]
      ...
  ```
  - The `hub_id` condition is non-optional and is merged with, never replaced by, a caller-supplied
    `query_filter`; assert this in a unit test that passes a hostile filter.
- [x] Rewrite `search_vector` to take `*, collection_ids: list[str], query_vector, limit, metadata_filter=None`
      and iterate the resolved collections' `physical_name` values instead of `"syntraflow_chunks_v1"`.
- [x] Add `async def resolve_targets(self, collection_ids: list[str] | None) -> list[SyntraFlowCollection]`
      that loads collections `where(SyntraFlowCollection.hub_id == self.hub_id)`:
  - `None` → every collection in the hub (fan-in).
  - An id belonging to another hub → `404 {"detail": "Collection not found"}`, never a silent skip.
- [x] Implement per-collection strategy dispatch driven by `retrieval_config_json`:
  - `dense` → Qdrant vector search with `score_threshold` when configured.
  - `sparse` → BM25 keyword search over the collection's sparse vectors; when the collection has no
    sparse index, return `409 {"detail": "Collection has no sparse index"}` rather than degrading silently.
  - `hybrid` → dense + sparse fused with Reciprocal Rank Fusion using the config's `rrf_k` (default 60).
  - `graph` → Neo4j traversal bounded by `graph_depth`, filtered on the node `hub_id` property.
  - A request-level `strategy` override is allowed but must be validated against the same enum; when
    absent, the collection's stored config wins, and only then `settings.RAG_STRATEGY`.
- [x] Implement multi-collection fan-in in `async def search(self, *, query: str, collection_ids=None, strategy=None, limit=5, metadata_filter=None) -> list[dict]`:
  - Execute per-collection searches concurrently with `asyncio.gather(..., return_exceptions=True)`.
  - Fuse the per-collection result lists with RRF, then truncate to `limit`.
  - Tag every hit with `collection_id`, `collection_name` and `hub_id` so the caller can attribute results.
  - A single failing collection degrades to a partial result plus a `warnings: [...]` entry; it must not
    fail the whole query — except for a `DatastoreUnavailableError`, which propagates as `503`.
- [x] Support metadata filtering on the standard payload keys from `syntraflow.md` §4
      (`document_id`, `tags`, `timestamp`, `access_level`) via a `metadata_filter: dict` translated into
      `FieldCondition` / `MatchAny` / `DatetimeRange` conditions; reject unknown keys with `422` so a
      caller cannot smuggle a `hub_id` override.
- [x] Update `search_graph` to run parameterised Cypher only, keeping
      `common/clients/neo4j.py::enforce_read_only_query`, and to include
      `WHERE n.hub_id = $hub_id` in every traversal.
- [x] Update the MCP tools in `projects/syntraflow/src/mcp_server.py` (`retrieve_documents`,
      `retrieve_video_segments`, `query_database`, `query_graph`) to require a `hub_id` argument bound
      from the calling agent's hub context and to reject calls without it, so the MCP surface cannot
      bypass tenancy.
- [x] Move `projects/syntraflow/src/retrieval.py` into the existing `projects/syntraflow/src/retrieval/`
      package (merging with `engine.py`) and update the `from projects.syntraflow.src.retrieval import RetrievalEngine`
      import in `projects/syntraflow/api.py`; remove the duplicate top-level module.
- [x] Add a retrieval unit test asserting that a query issued with hub A's id returns zero hits for a
      document ingested into hub B, even when both hubs have a collection with the same friendly name.
