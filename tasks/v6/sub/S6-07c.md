# S6-07c: Workflow Trace Capture & Node Assertions

> **Parent:** B6-07 (Eval Hub — Polymorphic Targets & Flow Tracing)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `projects/evalops`

## Scope

Make intermediate workflow state assertable. A workflow-targeted eval run produces an ordered set of
`eval_flow_traces` rows (written by S6-06d); this subtask consumes them, evaluates each test case's
node-level assertion against the matching node's captured state, and persists a pass/fail row into the
existing `eval_metric_results` table so node assertions show up in the same reports as RAGAS and
DeepEval scores.

The V5 engine in
[`projects/evalops/src/runner/block_assertion_engine.py`](file:///c:/Akshat/ContAIned/projects/evalops/src/runner/block_assertion_engine.py)
already implements `equals`, `contains`, `regex`, `threshold` and `json_schema` against a dotted
`field_path`. It is extended — not replaced — to cover the V6 assertion vocabulary
(`contains`, `equals`, `regex`, `json_path`, `not_contains`, `latency_under`) and to be driven from the
`eval_test_cases` columns added in S6-07a.

## Actionables

- [x] Add `projects/evalops/src/runner/trace_reader.py` with hub-scoped loaders:
  ```python
  async def load_run_traces(session, *, hub_id: str, run_id: str) -> list[TraceRecord]
  def index_by_node(traces: list[TraceRecord]) -> dict[str, list[TraceRecord]]
  ```
  `load_run_traces` filters on both `EvalFlowTrace.hub_id == hub_id` and `run_id`, ordered by `sequence, timestamp`. A `run_id` belonging to another hub returns an empty list — never rows.
- [x] Define `TraceRecord` as a frozen dataclass carrying `node_id`, `node_type`, `sequence`, `input_state`, `output_state`, `latency_ms`, `timestamp`. Loops that fan out (a node visited more than once) produce multiple records for the same `node_id`; `index_by_node` preserves execution order.
- [x] Extend `BlockAssertionEngine` with the six V6 assertion types, keeping the existing V5 operators working:

  | `assertion_type` | Semantics | Config keys |
  |---|---|---|
  | `equals` | normalised string / scalar equality against the extracted value | `field_path`, `case_sensitive` |
  | `contains` | substring for strings, membership for lists/sets | `field_path`, `case_sensitive` |
  | `not_contains` | logical negation of `contains`; passes when the value is absent **and** when the field is missing | `field_path`, `case_sensitive` |
  | `regex` | `re.search(expected, str(actual))`, compiled with `re.DOTALL` | `field_path`, `flags` |
  | `json_path` | evaluate a JSONPath expression against `output_state`; passes when the result set is non-empty and, if `expected_value` is set, when it matches | `json_path` |
  | `latency_under` | `trace.latency_ms < float(expected_value)` | — |

- [x] Guard `regex` against catastrophic backtracking: compile with a length cap on the pattern (256 chars) and execute the match under a bounded worker with a 1-second budget; on timeout the assertion fails with reason `REGEX_TIMEOUT` rather than hanging the run.
- [x] Default `field_path` to `output_state` when unset, so a simple `contains` assertion works without the author knowing the state schema. Keep the existing `_extract_field_value` dotted-path traversal and make a missing path yield `None` rather than raising.
- [x] Add the evaluation entry point:
  ```python
  async def evaluate_node_assertions(session, *, hub_id: str, run_id: str,
                                     eval_run_id: str, cases: list[EvalTestCase],
                                     outcome_by_case: dict[str, EvalCaseOutcome]) -> list[EvalMetricResult]
  ```
  For every case with a non-null `node_id`, look up the matching traces and produce one `EvalMetricResult` per case.
- [x] Define the resolution rules for missing or repeated nodes explicitly:
  - `node_id` not present in the trace set → a **failed** result with `metric_reason = "NODE_NOT_EXECUTED: node '<id>' did not run"`; never a silent pass
  - `node_id` executed multiple times → assert against the **last** occurrence by default; honour `assertion_config["occurrence"]` when it is `first`, `last` or `all` (`all` requires every occurrence to pass)
  - The target run failed before reaching the node → failed result with `metric_reason = "RUN_FAILED_BEFORE_NODE"`
  - The suite targets an agent (no traces exist) but a case carries `node_id` → failed result with `metric_reason = "NODE_ASSERTION_ON_AGENT_TARGET"`, and surface the same condition as a `422` warning when the case is created
- [x] Persist each outcome as an `EvalMetricResult` with `run_id = eval_run_id`, `test_case_id`, `node_id`, `assertion_type`, `metric_name = f"node_assertion.{node_id}.{assertion_type}"`, `framework = "node_assertion"`, `metric_score = 1.0 | 0.0`, `passed`, and a human-readable `metric_reason` naming the expected and actual values (truncated to 500 characters).
- [x] Fold node-assertion results into the run rollup: `EvalRunHistory.passed_count` / `failed_count` count node assertions alongside metric-threshold outcomes, and `details_json["node_assertions"]` records `{"total": n, "passed": n, "failed": n}` so the dashboard can separate the two families.
- [x] Do not re-read secrets: trace state is already redacted at write time by S6-06d; assert on the redacted value and, when an assertion targets a redacted field, fail with `metric_reason = "FIELD_REDACTED"` instead of reporting a spurious mismatch.
- [x] Add `tests/test_node_assertions.py` covering each of the six assertion types against a synthetic trace set, plus: a missing node fails rather than passes; `occurrence="all"` fails when any visit fails; `latency_under` compares against `trace.latency_ms`; a node assertion on an agent-targeted suite fails with the documented reason; traces from another hub are not readable.
