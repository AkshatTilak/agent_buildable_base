# S6-07b: Target Resolution & Runner Dispatch

> **Parent:** B6-07 (Eval Hub — Polymorphic Targets & Flow Tracing)  
> **Status:** `[x]`  
> **Complexity:** 🔴 High  
> **Owner:** `projects/evalops`  

---

## Scope

With targets now polymorphic, an eval run must decide *what to execute* before it can score anything.
This subtask adds `projects/evalops/src/runner/dispatch.py`: a single entry point that resolves the
suite's `(target_type, target_hub_id, target_id)` through `hub_resolver`, selects the agent runner or
the workflow runner, executes every test case against it, and normalises both runners' output into one
`EvalCaseOutcome` shape that feeds the **existing** RAGAS and DeepEval pipelines in
[`projects/evalops/src/metrics/`](file:///c:/Akshat/ContAIned/projects/evalops/src/metrics) unchanged.

The metric implementations themselves are not touched — the whole point is that both target types
converge on the same `(query, actual_output, retrieval_context, expected_output)` tuple before scoring.

## Actionables

- [x] Create `projects/evalops/src/runner/dispatch.py` exposing:
  ```python
  @dataclass
  class ResolvedTarget:
      target_type: Literal["agent", "workflow"]
      hub_id: str            # the target's own hub
      resource_id: str
      name: str
      resource: Any          # AgentDefinition | WorkflowDefinition

  @dataclass
  class EvalCaseOutcome:
      test_case_id: str
      query: str
      actual_output: str
      retrieval_context: list[str]
      expected_output: str | None
      latency_ms: float
      traces: list[dict]          # empty for agent targets
      workflow_run_id: str | None
      error: dict | None          # {"code","message"}

  async def resolve_target(session, *, eval_hub_id: str, suite: EvalTestSuite) -> ResolvedTarget
  async def dispatch_run(session, *, eval_hub_id: str, suite: EvalTestSuite,
                         cases: list[EvalTestCase], run_id: str,
                         concurrency: int = 4) -> list[EvalCaseOutcome]
  ```
- [x] Implement `resolve_target` with the **cross-hub security check** applied on every run, not only at suite creation:
  - Call `common/services/hub_resolver.py::resolve_linked(session, source_hub_id=eval_hub_id, target_resource_type=suite.target_type, target_resource_id=suite.target_id)`
  - Assert the resolved resource's own `hub_id` equals `suite.target_hub_id`; a mismatch is `422 CROSS_HUB_REFERENCE_MISMATCH` (the suite row was tampered with or the resource moved)
  - Assert the link direction is `eval → agent` or `eval → workflow`; nothing may link *into* an eval hub, per [`hubs.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/logic/hubs.md) §3.3
  - Assert the target hub is not archived → `409 HUB_ARCHIVED`
  - Missing link → `403 HUB_LINK_REQUIRED`; link present at save time but gone now → `403 HUB_LINK_REVOKED`; target deleted → `404 EVAL_TARGET_MISSING`
- [x] Implement the agent branch: for each test case call the hub-scoped agent invocation path from S6-05c with `hub_id=target.hub_id`, `agent_id=target.resource_id`, `prompt=case.input_query`, `stream=False`. Map the response into `EvalCaseOutcome` with `retrieval_context` taken from the invocation's collection-binding metadata (`AgentInvocationLog.metadata_json["collection_bindings"]`) and `traces=[]`.
- [x] Implement the workflow branch: call `run_service.start_run(...)` from S6-06d with `trigger="eval"`, `input_json={"prompt": case.input_query}`, `use_draft=False`, and await terminal status. Then:
  - Set `workflow_run_id` on the outcome and persist it on `eval_run_history.workflow_run_id`
  - Load the run's `eval_flow_traces` (filtered by `hub_id` and `run_id`, ordered by `sequence`) into `outcome.traces`
  - Derive `actual_output` from the terminal node's `output_state` (`final_message` / `synthesis` / `gather` / `action` per the V5 `TERMINAL_NODE_TYPES`), falling back to `workflow_runs.output_json`
  - Derive `retrieval_context` by concatenating the `output_state` documents of every `RetrievalNode` trace
  - A run finishing `failed` or `cancelled` produces an outcome with `error` set and `actual_output=""`; it is scored as a failure, not silently skipped
- [x] Bound concurrency with an `asyncio.Semaphore(concurrency)` and per-case exception isolation: one failing case must not abort the suite. Capture per-case errors into `EvalCaseOutcome.error` and count them in `EvalRunHistory.failed_count`.
- [x] Feed the unified pipeline: pass the `EvalCaseOutcome` list into `run_ragas_evaluation(...)` in [`projects/evalops/src/metrics/ragas_runner.py`](file:///c:/Akshat/ContAIned/projects/evalops/src/metrics/ragas_runner.py) and `run_deepeval_evaluation(...)` in [`projects/evalops/src/metrics/deepeval_runner.py`](file:///c:/Akshat/ContAIned/projects/evalops/src/metrics/deepeval_runner.py) via a thin adapter `def to_metric_inputs(outcomes) -> list[dict]`. Do not change either runner's signature or scoring logic.
- [x] Persist the run envelope: create the `EvalRunHistory` row up front with `hub_id`, the target triple, `run_status="running"`; on completion write `framework_used`, `total_test_cases`, `passed_count`, `failed_count`, `duration_sec`, the aggregate metric columns and `run_status="completed"`. Always set a terminal status in a `finally` block so a crash cannot leave a run pinned at `running`.
- [x] Rework [`projects/evalops/src/runner/consumer.py`](file:///c:/Akshat/ContAIned/projects/evalops/src/runner/consumer.py):
  - Rename `process_agent_eval_run` to `process_eval_run` and route it through `dispatch_run`
  - `publish_eval_trigger_event(...)` gains required `hub_id` and `suite_id` fields and drops the implicit agent assumption
  - Reject any event lacking `hub_id` with a logged warning rather than falling back to a global scope
- [x] Add `tests/test_eval_dispatch.py` covering: an agent-targeted suite dispatches to the agent runner; a workflow-targeted suite dispatches to the workflow runner and records `workflow_run_id`; a suite whose link was revoked fails the run with `HUB_LINK_REVOKED` before any case executes; a `target_id` from a hub other than `target_hub_id` fails with `CROSS_HUB_REFERENCE_MISMATCH`; one failing case does not abort the remaining cases.
