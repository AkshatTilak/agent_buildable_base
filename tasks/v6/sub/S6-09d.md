# S6-09d: Agent Hub Overview & Agent Library

> **Parent:** B6-09 (Frontend — Ingestion & Agent Hub Workspaces)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend/src`

---

## Scope

Build the agent hub's landing surfaces: an overview at `/hubs/agent/:hubId` and an agent library at `/hubs/agent/:hubId/agents`, both under `frontend/src/components/hubs/agent/`.

`AgentLibrary.tsx` replaces [frontend/src/components/AgentHub.tsx](frontend/src/components/AgentHub.tsx), which today is a single ~700-line component holding the list, an inline create/edit modal with a hardcoded `availableModels` array, an invoke modal and per-agent stats fetching, all against flat `api.getAgents()` / `createAgent()` / `deleteAgent()` endpoints. This subtask keeps only list-level concerns — detail, configuration and invocation move to S6-09e — and sources the model list from the platform model registry instead of the hardcoded array. Note the component name `AgentHub` is retired entirely: in V6 "Hub" is reserved for the tenancy construct.

## Actionables

- [ ] Create `frontend/src/components/hubs/agent/AgentOverview.tsx` as the hub index route.
  - [ ] Stat cards: total agents (active vs disabled split), invocation volume over the selected window, error rate, and p95 latency.
  - [ ] A time-window selector (24h / 7d / 30d) that drives every metric on the page and is reflected in the query string.
  - [ ] A "Top agents" table ranked by invocation count with per-row invocations, error rate and average latency, each row linking to that agent's detail route.
  - [ ] A linked-hub summary strip listing the ingestion hubs this agent hub consumes, with a link to the Links tab when `can("manage_links")`.
- [ ] Create `frontend/src/components/hubs/agent/AgentLibrary.tsx` for the list view.
  - [ ] Row contents: agent name and role, model id, enabled/disabled status via [frontend/src/components/shared/StatusBadge.tsx](frontend/src/components/shared/StatusBadge.tsx), `endpoint_slug` in `font-mono`, bound collection count, last-invoked relative time.
  - [ ] Debounced search over name, role and slug; filters for status and model; sort by name, last-invoked or invocation count.
  - [ ] Row click navigates to `routes.agentHub.agent(hubId, agentId)`; the row itself never opens a modal.
- [ ] Implement the create-agent modal, replacing the inline form in [frontend/src/components/AgentHub.tsx](frontend/src/components/AgentHub.tsx).
  ```ts
  interface AgentCreateDraft {
    name: string;
    role: string;
    endpoint_slug: string;       // auto-derived from name, unique within the hub
    model_id: string;            // from the platform model registry
    system_prompt: string;
    temperature: number;
    max_tokens: number;
    tools: string[];
  }
  ```
  - [ ] Populate `model_id` from the model registry (completion-role models), removing the hardcoded `availableModels` array; show provider and local/cloud origin per option.
  - [ ] Auto-derive `endpoint_slug` from the name until manually edited, validate `^[a-z0-9][a-z0-9-]{1,63}$`, and check uniqueness **within the hub** — `endpoint_slug` is now `UNIQUE (hub_id, endpoint_slug)`, so the same slug may legitimately exist in another agent hub.
  - [ ] Keep the create modal minimal: name, role, model, slug and an optional starter prompt. Everything else is configured in the detail workspace.
- [ ] Implement duplicate: opens the create modal pre-filled from the source agent with `name` suffixed "(copy)" and a cleared slug, copying prompt, model, tool and collection-binding settings.
  - [ ] Collection bindings are only copied when the required hub links still exist; any dropped binding is listed in a warning before submit.
- [ ] Implement enable/disable as an inline row toggle that immediately reflects the returned state, with a confirmation when disabling an agent that has received invocations in the last 24h (its endpoint will start rejecting traffic).
- [ ] Implement delete with typed confirmation of the agent name, listing dependents before proceeding — workflow nodes in linked workflow hubs and eval suites in linked eval hubs that target this agent.
- [ ] Remove the invoke modal and per-agent `getAgentStats` fetching from the library; ad-hoc invocation lives in the detail workspace's Test tab (S6-09e), and list-level stats come from a single batched metrics call rather than one request per row.
- [ ] Delete [frontend/src/components/AgentHub.tsx](frontend/src/components/AgentHub.tsx) once the library is wired, and remove its import from [frontend/src/App.tsx](frontend/src/App.tsx).
- [ ] Role gating: create, duplicate, enable/disable and delete are wrapped in `Gated` — a `viewer` sees the library, overview and metrics but no mutating controls and no row overflow menu; a `contributor` may create, edit and duplicate but not delete. In an archived hub every mutating control renders disabled with the "This hub is archived and is read-only" tooltip.
- [ ] Loading / empty / error expectations:
  - [ ] Overview cards and the library table render independent skeletons; a failing metrics call must not prevent the agent list from rendering.
  - [ ] Zero agents → [frontend/src/components/shared/EmptyState.tsx](frontend/src/components/shared/EmptyState.tsx) describing what an agent is with a create action for permitted roles and no action for a `viewer`.
  - [ ] Filters yielding nothing → "No agents match these filters" with a clear-filters action.
  - [ ] Agents with no invocations show an em-dash for last-invoked and error rate rather than a misleading `0%`.
  - [ ] Load failures render a retryable [frontend/src/components/shared/ErrorBanner.tsx](frontend/src/components/shared/ErrorBanner.tsx) scoped to the failing region.
