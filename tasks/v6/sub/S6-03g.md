# S6-03g: Auth Hardening & Test Coverage

> **Parent:** B6-03 (Admin User Management, Invitations & Approval Gate)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `gateway/auth`  

---

## Scope

Close out B6-03 with the cross-cutting security controls that span every auth surface — rate limits,
centralised session revocation, and email normalisation — and prove the whole lifecycle with
`tests/test_auth_v6.py`.

The boundary: no new product behaviour. This subtask adds enforcement wrappers around the routes built
in S6-03b/c/d/f and the test suite that pins their contracts, including the negative cases
(enumeration resistance, lockout, last-admin protection, cross-account invite abuse).

## Actionables

- [x] Apply the rate limits from `user_management.md` §7 using `common/observability/limiter.py`,
      each returning `429` with a `Retry-After` header:
  - `POST /auth/login` — 10/min per client IP.
  - `POST /auth/register` — 5/hour per client IP.
  - `POST /auth/forgot-password` — 3/hour per **normalised email** (not per IP).
  - `POST /auth/invite/{token}/accept` — 10/hour per IP.
  - `POST /admin/invites` — 60/hour per admin id.
  - Resolve the client IP from `X-Forwarded-For` first hop, falling back to `request.client.host`, in a
    shared `gateway/auth/utils.py::client_ip(request)` helper so every limiter keys identically.
- [x] Add `async def revoke_sessions(session, user_id: str, *, keep_token_hash: str | None = None) -> int`
      to `gateway/auth/utils.py`, deleting `UserSession` rows for the user, and call it from **every**
      revocation trigger: password change (keeping the current session), password reset, suspension,
      rejection, `admin → member` demotion, and hard delete.
- [x] Add a normalisation guard: a single `normalize_email(value: str) -> str`
      (`value.strip().lower()`) in `gateway/auth/utils.py`, used by every write and every lookup in
      `routes.py`, `identities.py`, `invites.py` and `admin_users.py`.
- [x] Extend the middleware in `gateway/auth/middleware.py` to re-check `users.status` on each request
      (cached per request), so a suspended user holding an unexpired JWT is rejected with
      `403 {"reason": "ACCOUNT_SUSPENDED"}` rather than being served from the token claims alone.
- [x] Create `tests/test_auth_v6.py` with an async `httpx.AsyncClient` fixture against the FastAPI app,
      a per-test transactional database fixture, and a stub mailer capturing sent messages
      (`monkeypatch` of `gateway.services.mailer.get_mailer`).
- [x] Cover the invite → OAuth acceptance path: admin creates an invite with `platform_role="member"`
      and one `hub_grants` entry; a stubbed Google profile with the matching verified email completes
      `/auth/callback/google` with the invite token in signed state; assert the user is `active`, the
      `hub_members` row exists with the granted role, the invite is `accepted`, and a session was issued.
- [x] Cover the invite → password acceptance path via `POST /auth/invite/{token}/accept`; assert the
      `user_identities` row has `provider="password"` and that a **second** call with the same token
      returns `409`.
- [x] Cover the email-mismatch rejection: an invite for `a@example.com` redeemed by an OAuth profile
      for `b@example.com` returns `409 Invite email mismatch` and creates **no** user, identity or
      membership row.
- [x] Cover the approval gate end-to-end:
  - Self sign-up with no invite → user is `pending`, response carries `ACCOUNT_PENDING_APPROVAL`, and
    `/auth/me` with any issued credential is refused.
  - `POST /admin/users/{id}/approve` with inline `hub_grants` → `active`, memberships created,
    `approved_by` set, `approved` email queued.
  - `POST /admin/users/{id}/reject` → `rejected`, all sessions gone, subsequent login returns
    `ACCOUNT_REJECTED`.
  - A `AUTO_APPROVE_EMAIL_DOMAINS="acme.com"` signup from `x@acme.com` skips the gate and is `active`.
- [x] Cover suspension revoking sessions: log in, capture the token, suspend via `/admin/users/{id}/suspend`,
      assert the `user_sessions` row count for that user is `0` and the captured token now returns
      `403 ACCOUNT_SUSPENDED`.
- [x] Cover brute-force lockout: five wrong passwords set `locked_until ≈ now + 15min`; the sixth
      attempt — **even with the correct password** — returns `423`; a successful login after the lock
      expires resets `failed_login_count` to `0`.
- [x] Cover enumeration resistance: `/auth/login` for an unknown email and for a known email with a
      wrong password return byte-identical status and body; `/auth/forgot-password` and
      `/auth/register` return `202` for both known and unknown addresses. Assert the mean wall-clock
      difference over 20 paired requests stays within a 30% band.
- [x] Cover the admin guardrails: the sole admin cannot demote, suspend or delete themselves (`409`);
      demoting the last remaining active admin is refused (`409 LAST_ACTIVE_ADMIN`); deleting a hub
      owner returns `409` listing the owned hub ids.
- [x] Add a static guard test asserting no response model in `gateway/` serialises `password_hash` or
      `token_hash`: walk every `APIRoute.response_model` on the app and assert those field names are
      absent from `model_fields`.
