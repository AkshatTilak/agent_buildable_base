# S6-03c: Multi-Provider OAuth Linking & Approval Gate

> **Parent:** B6-03 (Admin User Management, Invitations & Approval Gate)  
> **Status:** `[x]`  
> **Complexity:** 🔴 High  
> **Owner:** `gateway/auth`  

---

## Scope

Rework the OAuth flow so that Google, GitHub and password credentials all resolve to **one** account
keyed by verified email. `gateway/auth/routes.py::oauth_callback` currently looks a user up by email,
creates them with `provider`/`provider_id`/`role` columns that no longer exist, auto-activates them,
and hard-codes the frontend redirect to `http://localhost:5173`. All of that is replaced by the
identity-resolution algorithm in `user_management.md` §3.1, PKCE + signed state in
`gateway/auth/providers.py`, and the approval gate.

This subtask also defines the machine-readable holding-screen contract
(`ACCOUNT_PENDING_APPROVAL` / `ACCOUNT_SUSPENDED` / `ACCOUNT_REJECTED`) that both the OAuth callback
and the password routes from S6-03b return.

## Actionables

- [x] Harden `gateway/auth/providers.py`:
  - Register Google with `client_kwargs={"scope": "openid email profile", "code_challenge_method": "S256"}`
    and GitHub with `{"scope": "read:user user:email"}`.
  - Add `build_state(payload: dict) -> str` / `parse_state(state: str) -> dict` that sign a compact
    JSON payload (`{"nonce": ..., "invite_token": ..., "redirect": ..., "exp": ...}`) with
    `settings.JWT_SECRET_KEY` using HS256 and a 10-minute expiry; reject unsigned or expired state with
    `400 {"detail": "Invalid OAuth state"}`.
  - Store the PKCE `code_verifier` in the server-side session (Authlib's `authorize_redirect` handles
    generation when `code_challenge_method` is set); assert it is present on callback.
- [x] Rewrite `GET /auth/login/{provider}` to accept optional `?invite_token=` and `?redirect=` query
      params, embed them into the signed state, and validate `redirect` against
      `settings.APP_PUBLIC_URL` (reject open redirects with `400`).
- [x] Add `gateway/auth/identities.py` with the profile normaliser:
  ```python
  @dataclass
  class OAuthProfile:
      provider: str        # google | github
      provider_id: str
      email: str           # already trimmed + lowercased
      email_verified: bool
      display_name: str | None
      avatar_url: str | None

  async def fetch_profile(provider: str, client, token) -> OAuthProfile: ...
  ```
  - Google: require `userinfo["email_verified"] is True`.
  - GitHub: call `GET user/emails` and select the entry with `primary and verified`; a GitHub account
    with no verified primary email is rejected.
  - Unverified email → redirect to `{APP_PUBLIC_URL}/login?error=email_not_verified`; never link an
    unverified address to an existing account (account-takeover vector).
- [x] Implement `resolve_identity(session, profile, invite_token=None) -> tuple[User, bool]` in
      `gateway/auth/identities.py` following `user_management.md` §3.1 step 3, in this exact order:
  - `user_identities` row matching `(provider, provider_id)` → load its user, touch `last_used_at`.
  - Else a `users` row with the same lowercased email → **link**: insert a new `user_identities` row
    for this provider, keep the existing `platform_role` and `status`.
  - Else `invite_token` present or a `pending` `user_invites` row matches the email → hand off to
    `redeem_invite(...)` from S6-03d (creates an `active` user with the invite's `platform_role` and
    `hub_grants_json`).
  - Else create `User(platform_role="member", status="pending")` plus its identity row.
  - Bootstrap exception: if `SELECT count(*) FROM users` is `0`, create the account with
    `platform_role="admin"`, `status="active"` and `approved_at=now` so the deployment is reachable.
- [x] Apply `AUTO_APPROVE_EMAIL_DOMAINS` inside the "no invite" branch: if the email's domain is in the
      CSV setting (case-insensitive, trimmed), create the user with `status="active"` and
      `approved_by=None`, and audit it as `action="approve"`, `summary="auto-approved by domain rule"`.
- [x] Enforce the invite-email match: when the signed state carries an `invite_token` and
      `profile.email != invite.email`, abort **before** creating anything and redirect to
      `{APP_PUBLIC_URL}/auth/invite/{token}?error=email_mismatch`; the JSON API equivalent
      (`POST /auth/invite/{token}/accept`) returns `409 {"detail": "Invite email mismatch"}`.
- [x] Rewrite `GET /auth/callback/{provider}` to: exchange the code, `fetch_profile`, `resolve_identity`,
      then gate on status via a shared helper:
  ```python
  def gate_status(user: User) -> None:
      """Raises HTTPException(403) with a machine-readable reason for non-active users."""
      # pending   -> {"reason": "ACCOUNT_PENDING_APPROVAL", "email": user.email}
      # suspended -> {"reason": "ACCOUNT_SUSPENDED"}
      # rejected  -> {"reason": "ACCOUNT_REJECTED"}
  ```
  - Export `gate_status` from `gateway/auth/identities.py` and call it from the password routes in
    S6-03b so both surfaces emit an identical contract.
  - Non-active OAuth users are redirected to `{APP_PUBLIC_URL}/auth/pending?reason=<REASON>` rather
    than receiving an error page.
- [x] Only for `status == "active"`: mint the JWT with `create_access_token(user.id, user.email, user.platform_role)`,
      insert the `UserSession` row, set the `auth_token` cookie with
      `httponly=True, secure=(settings.APP_ENV == "production"), samesite="lax"`, and redirect to
      `{settings.APP_PUBLIC_URL}/auth/callback?token=...` — remove the hard-coded `localhost:5173`.
- [x] Rework `GET /auth/me` to return `platform_role`, `status`, `identities` (provider + `last_used_at`,
      never `provider_id` secrets) and `hub_memberships`; delete the `local-admin-id` synthetic branch's
      `provider`/`role`/`is_active` fields and replace them with `platform_role="admin"`, `status="active"`.
- [x] Add `POST /auth/identities/{provider}/unlink` (authenticated) that removes a `user_identities`
      row, rejecting with `409 {"detail": "Cannot unlink the only sign-in method"}` when it is the
      user's last identity and `password_hash IS NULL`.
- [x] Write an `audit_log` row for every account creation (`action="create"`, `resource_type="user"`)
      and every identity link (`action="update"`, `summary="linked <provider> identity"`), including
      `ip_address` from `request.client.host` / `X-Forwarded-For`.
