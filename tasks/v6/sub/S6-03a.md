# S6-03a: User, Identity & Invite Models + Migration

> **Parent:** B6-03 (Admin User Management, Invitations & Approval Gate)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `common/models`  

---

## Scope

Reshape the V5 authentication schema into the V6 account model. `common/models/database.py` currently
defines `User` with `provider`, `provider_id`, `role` and `is_active` columns — a single-provider,
boolean-activation assumption. This subtask replaces those with `platform_role`, `status`,
`password_hash` and the approval/lockout bookkeeping columns, and adds the two new tables
`user_identities` (multi-provider linking) and `user_invites` (admin-issued invitations).

The boundary is **schema only**: SQLAlchemy models, the Alembic revision (including the backfill of
existing users into `user_identities`), and the Pydantic schemas that describe these rows. No route,
service or auth-flow behaviour changes here — those land in S6-03b/c/d/f.

## Actionables

- [ ] Rewrite `class User(Base)` in `common/models/database.py` to match `user_management.md` §2.1 exactly:
  ```python
  class User(Base):
      __tablename__ = "users"

      id = Column(String(36), primary_key=True, default=lambda: str(uuid.uuid4()))
      email = Column(String(255), unique=True, index=True, nullable=False)
      display_name = Column(String(100), nullable=True)
      avatar_url = Column(String(500), nullable=True)
      platform_role = Column(String(20), nullable=False, default="member")   # admin | member
      status = Column(String(20), nullable=False, default="pending")         # pending|active|suspended|rejected
      password_hash = Column(String(255), nullable=True)                     # argon2id; null = SSO-only
      password_updated_at = Column(DateTime, nullable=True)
      approved_by = Column(String(36), ForeignKey("users.id", ondelete="SET NULL"), nullable=True)
      approved_at = Column(DateTime, nullable=True)
      failed_login_count = Column(Integer, default=0, nullable=False)
      locked_until = Column(DateTime, nullable=True)
      created_at = Column(DateTime, default=datetime.utcnow)
      last_login = Column(DateTime, nullable=True)
  ```
  - Delete the `provider`, `provider_id`, `role` and `is_active` columns outright — no aliases, no properties.
- [ ] Add `class UserIdentity(Base)` (`__tablename__ = "user_identities"`) per §2.2 with
      `user_id` FK `users.id ON DELETE CASCADE` (indexed), `provider` (`google|github|password`),
      `provider_id`, `email`, `created_at`, `last_used_at`, and
      `__table_args__ = (UniqueConstraint("provider", "provider_id", name="uq_user_identity_provider"),)`.
  - For `provider = "password"`, `provider_id` equals the owning `user_id`.
- [ ] Add `class UserInvite(Base)` (`__tablename__ = "user_invites"`) per §2.3 with `email` (indexed,
      stored lowercased), `token_hash` (String(255), indexed), `platform_role` (default `"member"`),
      `hub_grants_json` (JSON, default `list`), `invited_by` FK `users.id`, `status`
      (`pending|accepted|revoked|expired`), `expires_at`, `accepted_at`, `accepted_user_id` FK
      `users.id`, `resend_count` (default 0), `last_sent_at`, `created_at`.
  - Never add a raw-token column. Only the SHA-256 hex digest is persisted.
- [ ] Add a `PasswordResetToken` model (`__tablename__ = "password_reset_tokens"`) with `id`,
      `user_id` FK CASCADE, `token_hash` String(64) indexed, `expires_at`, `used_at` nullable,
      `created_at` — used by S6-03b's forgot/reset flow, single-use enforced by `used_at IS NULL`.
- [ ] Write the Alembic revision under `migrations/versions/` (`down_revision` = the V6 hub migration
      head from S6-01e) performing, in order:
  - `op.create_table("user_identities", ...)` and `op.create_table("user_invites", ...)` and
    `op.create_table("password_reset_tokens", ...)`.
  - `op.add_column("users", ...)` for `platform_role`, `status`, `password_hash`,
    `password_updated_at`, `approved_by`, `approved_at`, `failed_login_count`, `locked_until`.
  - Backfill `platform_role` from `role` using the mapping in `hubs.md` §4.1
    (`admin → admin`, `editor → member`, `viewer → member`).
  - Backfill `status`: `is_active = true → 'active'`, `is_active = false → 'suspended'`.
  - Backfill `user_identities` from the legacy columns:
    ```sql
    INSERT INTO user_identities (id, user_id, provider, provider_id, email, created_at)
    SELECT gen_random_uuid()::text, id, provider, provider_id, lower(email), created_at
    FROM users WHERE provider IS NOT NULL AND provider_id IS NOT NULL;
    ```
  - `UPDATE users SET email = lower(trim(email));` before adding constraints.
  - `op.alter_column("users", "platform_role", nullable=False)` and the same for `status`.
  - `op.drop_column` for `role`, `is_active`, `provider`, `provider_id`.
- [ ] Create the partial unique index guaranteeing one open invite per address:
      `op.create_index("uq_user_invites_open_email", "user_invites", ["email"], unique=True, postgresql_where=sa.text("status = 'pending'"))`.
- [ ] Implement `downgrade()` fully (re-add the four dropped columns, repopulate `provider`/`provider_id`
      from the first `user_identities` row per user, map `platform_role` back to `role`, drop the three
      new tables) and make `upgrade()` idempotent by guarding every DDL step with an inspector check
      (`sa.inspect(op.get_bind()).has_table(...)` / column presence) so a re-run is a no-op.
- [ ] Add Pydantic schemas in `common/schemas/api.py`: `UserSummary`, `UserDetail` (with
      `identities: list[IdentitySummary]` and `hub_memberships: list[HubMembershipSummary]`),
      `InviteCreate`, `InviteSummary`.
  - `UserDetail` must **never** declare `password_hash`; add a unit assertion that
    `"password_hash" not in UserDetail.model_fields`.
- [ ] Add module-level constants next to the models: `PLATFORM_ROLES = ("admin", "member")`,
      `USER_STATUSES = ("pending", "active", "suspended", "rejected")`,
      `IDENTITY_PROVIDERS = ("google", "github", "password")`,
      `INVITE_STATUSES = ("pending", "accepted", "revoked", "expired")`.
- [ ] Update every existing reference to the removed columns so the codebase imports cleanly:
      `gateway/auth/routes.py` (`UserResponse.provider/role/is_active`, the callback branch),
      `gateway/auth/dependencies.py` (`ROLE_HIERARCHY`), `gateway/auth/middleware.py`, and
      `tests/test_auth.py` — mechanical rename only; behaviour is reworked in S6-03b/c.
- [ ] Run `alembic upgrade head` then `alembic downgrade -1` then `alembic upgrade head` against a
      scratch database and confirm no residual `users.role` / `users.is_active` columns remain.
