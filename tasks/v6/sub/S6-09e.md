# S6-09e: Agent Detail Workspace

> **Parent:** B6-09 (Frontend — Ingestion & Agent Hub Workspaces)  
> **Status:** `[ ]`  
> **Complexity:** 🔴 High  
> **Owner:** `frontend/src`

---

## Scope

Build `frontend/src/components/hubs/agent/AgentDetail.tsx` at `/hubs/agent/:hubId/agents/:agentId`, a five-tab workspace nested inside `HubShell`: **Configuration**, **Knowledge**, **Endpoint**, **Invocations** and **Test**. This absorbs and replaces the inline edit form and invoke modal that live in [frontend/src/components/AgentHub.tsx](frontend/src/components/AgentHub.tsx) today.

The Knowledge tab is the frontend expression of `hubs.md` §5.4 cross-hub resolution: an agent may only bind collections from ingestion hubs its own hub explicitly links to, links are not transitive, and revoking a link breaks bindings at execution time. The picker therefore groups options by linked ingestion hub and offers a "Request link" affordance rather than silently listing unreachable collections. The Configuration tab's prompt editor carries unsaved-change protection across tab switches, route changes and browser unload.

## Actionables

- [ ] Create `frontend/src/components/hubs/agent/AgentDetail.tsx` with an inner tab bar (distinct from the `HubShell` tabs), where the active tab is a URL segment so tabs are linkable and survive reload.
  - [ ] A sticky detail header shows agent name, model, enabled/disabled toggle, `endpoint_slug` and an overflow menu (duplicate, delete) mirroring the S6-09d gating.
- [ ] **Configuration tab** — system prompt, model, temperature, max tokens, and tool selection.
  - [ ] Prompt editor on a `font-mono` `--bg-input` surface with line numbers, soft wrap and a resizable height persisted per user.
  - [ ] Live character count and an estimated token count with the estimation method labelled as approximate.
  - [ ] Model select sourced from the platform model registry; changing the model shows an inline note when the new model's context window is smaller than the current prompt estimate.
  - [ ] Temperature and max-tokens controls with the model's valid ranges enforced, and tool checkboxes sourced from the registry rather than a hardcoded list.
  - [ ] A sticky dirty-state bar with Save and Discard, disabled until the form is dirty.
- [ ] Implement unsaved-change protection for the Configuration tab.
  - [ ] Block in-app navigation (inner tab switch, `HubShell` tab, sidebar, hub switcher) with a confirm dialog offering Save, Discard and Cancel.
  - [ ] Register a `beforeunload` handler while dirty and remove it on save/discard/unmount.
  - [ ] Never auto-save the prompt; the dirty state must survive an inner-tab switch when the user chooses Cancel.
- [ ] **Knowledge tab** — collection bindings resolved across hub links.
  ```ts
  interface CollectionBindingOption {
    collectionId: string;
    collectionName: string;
    ingestionHubId: string;
    ingestionHubName: string;
    accessLevel: HubAccessLevel;   // from the hub_link
    embeddingModelId: string;
    dimension: number;
    documentCount: number;
  }
  ```
  - [ ] The picker groups options under a header per linked ingestion hub and lists **no** collections from unlinked hubs.
  - [ ] Show an inline "Request link" affordance when the hub has no ingestion links, or when the user searches for a collection in an unlinked hub: for `owner`/`maintainer` it deep-links to the Links tab pre-filtered to that target hub; for `contributor`/`viewer` it renders explanatory copy naming who can create the link, with no action.
  - [ ] Bound collections render as rows with their source hub, embedding model and dimension; flag a dimension mismatch against the agent's retrieval expectation as a warning rather than blocking.
  - [ ] A binding whose link has been revoked renders in a `--rose-soft` "Link revoked" state with an unbind action and a note that invocations using it will fail at execution time.
  - [ ] Handle a `HUB_LINK_REVOKED` / `HUB_LINK_REQUIRED` error from S6-08d by refreshing the link list and surfacing the same affordance rather than a generic error toast.
- [ ] **Endpoint tab** — the agent's externally callable surface.
  - [ ] Show the hub-qualified identifier (`{hub_slug}/{endpoint_slug}`) prominently in `font-mono` with a copy button, and explain that slugs are only unique within a hub.
  - [ ] Render a copy-ready `curl` snippet against `/hubs/{hub_id}/agents/{agent_id}/invoke` with a placeholder API key, an example JSON body, and a note pointing at `/settings/api-keys` for key creation.
  - [ ] Offer a language toggle for the snippet (curl / Python `requests` / TypeScript `fetch`) rendered through the existing syntax highlighter.
  - [ ] Never render a real API key value in the snippet — always a `$CONTAINED_API_KEY` placeholder.
  - [ ] Slug editing lives here, reusing the hub-scoped uniqueness check, with a warning that changing it breaks existing callers.
- [ ] **Invocations tab** — server-paginated log for this agent.
  - [ ] Columns: timestamp, status, latency, model, prompt/completion tokens, cost estimate, caller (API key or user), and a truncated prompt preview.
  - [ ] Filters for status, time window and caller; sort by timestamp or latency.
  - [ ] Row click opens a drill-down drawer with the full prompt, full completion, tool calls, retrieved chunks with their source collection and hub, and the raw request/response JSON with a copy action.
  - [ ] Failed invocations show the error class and message, and link the trace id to the telemetry surface where one exists.
- [ ] **Test tab** — inline invocation with streaming output.
  - [ ] Prompt input, optional session id, and per-run overrides for temperature and max tokens that are **not** persisted to the agent config.
  - [ ] Stream tokens into a markdown-rendered output pane, with a stop control while streaming.
  - [ ] A meta header showing latency, token counts, model used and retrieved-chunk count, plus an expandable retrieved-context panel.
  - [ ] Keep the last N runs of the session in local component state for comparison; nothing here is persisted server-side beyond the normal invocation log.
- [ ] Role gating: Configuration save, Knowledge bind/unbind, slug edit, Test invocation and the header's enable/disable and delete actions are all wrapped in `Gated`.
  - [ ] A `viewer` sees Configuration, Knowledge, Endpoint and Invocations strictly read-only — form fields disabled, no Save bar, no bind/unbind, and the Test tab hidden entirely since invocation is a mutating operation.
  - [ ] A `contributor` may edit, bind and test but not delete the agent.
  - [ ] In an archived hub every mutating control including Test renders disabled with the "This hub is archived and is read-only" tooltip; the Invocations log stays fully browsable.
- [ ] Loading / empty / error expectations:
  - [ ] Detail header and the active tab render skeletons independently; switching tabs must not refetch the agent itself.
  - [ ] Zero bound collections → an empty state explaining the agent will answer without retrieval, with a bind action for permitted roles.
  - [ ] No linked ingestion hubs → a distinct empty state that leads to the Links tab rather than showing an empty picker.
  - [ ] Zero invocations → "This agent has not been invoked yet" with a pointer to the Test tab.
  - [ ] Save failures keep the form dirty and show the server message inline on the offending field; a streaming failure in Test renders partial output plus an error footer rather than discarding what was received.
  - [ ] A `404` on the agent renders an in-shell not-found that keeps the hub tabs intact and links back to the agent library.
