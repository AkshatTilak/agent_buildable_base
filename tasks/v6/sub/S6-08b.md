# S6-08b: Hub Shell Layout, Context & Role Gating

> **Parent:** B6-08 (Frontend — Hub Shell, Information Architecture & Navigation)  
> **Status:** `[x]`  
> **Complexity:** 🔴 High  
> **Owner:** `frontend/src`

---

## Scope

Build `frontend/src/components/hubs/HubShell.tsx`, the persistent frame that wraps every hub workspace. The shell owns the single hub fetch for the route, renders the hub header (name, type badge, accent, slug, archived banner), the per-type tab bar, breadcrumbs, and an `<Outlet />` for the active workspace. No child view may re-fetch the hub or re-derive the caller's role.

The shell also establishes the authorisation surface for the whole frontend: a `HubContext` exposing `{ hub, hubRole, can(action) }` plus a `useHubPermissions()` hook that encodes the `hubs.md` §4.2 capability matrix once. Every mutating control in every hub workspace asks this hook rather than comparing role strings inline. Archived hubs are rendered read-only through the same mechanism, so a single code path covers both "insufficient role" and "hub archived".

## Actionables

- [ ] Create `frontend/src/components/hubs/HubShell.tsx` as the layout element for the `ROUTE_PATTERNS.hubShell` route from S6-08a.
  - [ ] Read `hubType` and `hubId` from `useParams()`, fetch the hub once via the hub-scoped client (S6-08d), and store it in `hubSlice` as the active hub.
  - [ ] Re-fetch only when `hubId` changes; tab navigation inside the hub must not trigger a refetch.
  - [ ] Assert the fetched `hub.hub_type` matches the `hubType` URL segment; on mismatch render `HubNotFound` (the API also treats this as `404`).
- [ ] Create `frontend/src/components/hubs/HubContext.tsx` providing the context value consumed by every hub workspace.
  ```ts
  export type HubRole = "owner" | "maintainer" | "contributor" | "viewer";

  export type HubAction =
    | "view"
    | "run_readonly"
    | "create_resource"
    | "edit_resource"
    | "execute"
    | "delete_resource"
    | "manage_datastores"
    | "manage_members"
    | "manage_links"
    | "rename_hub"
    | "archive_hub"
    | "transfer_ownership"
    | "hard_delete_hub";

  export interface HubContextValue {
    hub: Hub;
    hubRole: HubRole;
    isPlatformAdmin: boolean;
    isArchived: boolean;
    can: (action: HubAction) => boolean;
    /** Why an action is unavailable — drives tooltips. */
    denyReason: (action: HubAction) => "role" | "archived" | null;
  }
  ```
- [ ] Create `frontend/src/hooks/useHubPermissions.ts` exporting `useHubPermissions()` (throws if used outside a `HubShell`) and a pure `evaluate(role, action, isArchived)` function that is unit-testable without React.
  - [ ] Encode the ordered role ladder `owner(4) > maintainer(3) > contributor(2) > viewer(1)` and the §4.2 matrix in one lookup table.
  - [ ] A platform `admin` short-circuits to `owner` for every check.
  - [ ] Archived hubs return `false` for every mutating action regardless of role, with `denyReason() === "archived"`; read-only actions (`view`, `run_readonly`) stay `true`.
- [ ] Define a per-type tab configuration table in `frontend/src/components/hubs/hubTabs.ts` mapping `HubType → { label, icon, to }[]`, built with the S6-08a route builders.
  - [ ] `ingestion`: Overview, Collections, Datastores, Documents, Jobs, Search.
  - [ ] `agent`: Overview, Agents.
  - [ ] `workflow`: Overview, Workflows.
  - [ ] `eval`: Overview, Suites, Runs, Traces.
  - [ ] All four additionally get Members, Links and Settings tabs, right-aligned and visually separated from the workspace tabs.
- [ ] Render the hub header using the design tokens: hub `name` in `font-display`, a type badge coloured by `hub.accent` (falling back to a per-type default accent), the `lucide` icon named by `hub.icon`, and the `{hub_type}/{slug}` identifier in `font-mono` `--text-muted`.
- [ ] Render an archived banner above the tab bar when `hub.is_archived` is true.
  - [ ] Amber `--amber-soft` surface, explicit copy that the hub is read-only, and an "Unarchive" button visible only when `can("archive_hub")` would pass on role grounds (i.e. `owner`).
- [ ] Replace the current path-derived logic in [frontend/src/components/layout/Breadcrumbs.tsx](frontend/src/components/layout/Breadcrumbs.tsx) with hub-aware crumbs: `Hubs / {Hub Type} / {Hub Name} / {Tab} / {Resource}`, where the hub name comes from context rather than the URL id.
- [ ] Export a `<Gated action="create_resource">` wrapper component (in `frontend/src/components/hubs/Gated.tsx`) implementing the two-mode gating contract used platform-wide:
  - [ ] Denied for role reasons → the control is **not rendered at all** (a `viewer` must never see a create/edit/delete affordance).
  - [ ] Denied because the hub is archived → the control renders `disabled` with a tooltip reading "This hub is archived and is read-only".
- [ ] Keep the shell's own chrome resilient: the header, tabs and outlet must render even when a child workspace throws, by wrapping only the `<Outlet />` in [frontend/src/components/shared/ErrorBoundary.tsx](frontend/src/components/shared/ErrorBoundary.tsx).
- [ ] Loading / empty / error expectations:
  - [ ] Pending hub fetch → header and tab bar render as [frontend/src/components/shared/LoadingSkeleton.tsx](frontend/src/components/shared/LoadingSkeleton.tsx) blocks with the outlet showing a matching skeleton; no layout shift when data lands.
  - [ ] `404` → `HubNotFound` replaces the whole shell (no tabs for a hub the user cannot see).
  - [ ] `403` on a nested resource → in-outlet forbidden state that keeps the shell chrome intact.
  - [ ] Network/`5xx` → retryable `ErrorBanner` inside the shell with a "Retry" that re-issues only the hub fetch.
- [ ] Add unit tests for `evaluate(role, action, isArchived)` covering every cell of the §4.2 matrix plus the archived override and the platform-admin short-circuit.
