## Scope

Rework the dataset layer in
[`projects/evalops/src/datasets/manager.py`](file:///c:/Akshat/ContAIned/projects/evalops/src/datasets/manager.py)
so every suite and test-case operation is hub-scoped. Today every function there — `create_suite`,
`get_suite`, `update_suite`, `delete_suite`, `clone_suite`, `add_test_case`, `list_test_cases`,
`update_test_case`, `delete_test_case`, `import_cases_from_csv`, `import_cases_from_json` — takes a bare
id and queries by primary key, which is an IDOR across hub boundaries once tenancy exists.

The subtask also makes CSV/JSON import & export reject cross-hub suite ids outright, and retargets
synthetic test generation in
[`projects/evalops/src/generation/synthetic.py`](file:///c:/Akshat/ContAIned/projects/evalops/src/generation/synthetic.py)
so it can seed cases from either an agent or a workflow target.

## Actionables

- [x] Change every function in [`projects/evalops/src/datasets/manager.py`](file:///c:/Akshat/ContAIned/projects/evalops/src/datasets/manager.py) to take `hub_id` as a **required keyword-only** argument and include it in the `WHERE` clause, per [`hubs.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/logic/hubs.md) §5.3:
  ```python
  async def create_suite(db, *, hub_id: str, name: str, description: str | None,
                         target: SuiteTarget, created_by: str) -> EvalTestSuite
  async def list_suites(db, *, hub_id: str, target_type: str | None = None,
                        target_id: str | None = None) -> list[EvalTestSuite]
  async def get_suite(db, *, hub_id: str, suite_id: str) -> EvalTestSuite | None
  async def update_suite(db, *, hub_id: str, suite_id: str, **fields) -> EvalTestSuite
  async def delete_suite(db, *, hub_id: str, suite_id: str) -> bool
  async def clone_suite(db, *, hub_id: str, suite_id: str, new_name: str,
                        target: SuiteTarget | None = None) -> EvalTestSuite
  ```
  Test-case helpers resolve their suite through `get_suite(db, hub_id=..., suite_id=...)` first and operate on `EvalTestCase.suite_id` only after that check passes — a case id is never trusted on its own.
- [x] Enforce per-hub unique suite names in application code as well as by constraint: a duplicate returns `409 {"error": {"code": "SUITE_NAME_TAKEN", "message": "A suite named '<n>' already exists in this hub."}}`. `clone_suite` auto-suffixes `(copy)`, `(copy 2)`… to stay unique.
- [x] Apply the **cross-hub security check** whenever a suite's target is set or changed: `create_suite`, `update_suite` and `clone_suite` call `hub_resolver.resolve_linked(db, source_hub_id=hub_id, target_resource_type=target.type, target_resource_id=target.id)`, confirm the resolved resource's own `hub_id` equals `target.hub_id`, confirm the direction is `eval → agent` or `eval → workflow`, and confirm the target hub is not archived. Failures return `403 HUB_LINK_REQUIRED` / `422 CROSS_HUB_REFERENCE_MISMATCH` / `409 HUB_ARCHIVED`.
- [x] Allow a suite's target to be **retargeted** (agent → workflow and back) via `update_suite`, but reject the change with `409 SUITE_HAS_RUNS_RETARGET_BLOCKED` when `eval_run_history` already holds completed runs for that suite — history would otherwise be uninterpretable. Cloning to a new target is the supported path.
- [x] Rewrite CSV import to be hub-scoped and cross-hub safe in `import_cases_from_csv(db, *, hub_id, suite_id, file_bytes)`:
  - Resolve the suite with `hub_id` first; a suite id from another hub returns `404 SUITE_NOT_FOUND`
  - Required header columns: `input_query`; optional: `expected_output`, `expected_context`, `node_id`, `assertion_type`, `expected_value`, `assertion_config`
  - If the file carries a `suite_id` column, every value must equal the path `suite_id`; any mismatch aborts the whole import with `422 {"error": {"code": "CROSS_HUB_SUITE_ID", "row": n, "value": "..."}}`
  - Reject `assertion_type` values outside `NODE_ASSERTION_TYPES` with `422 INVALID_ASSERTION_TYPE` naming the row
  - Cap at 5000 rows / 5 MB → `413 IMPORT_TOO_LARGE`; import is all-or-nothing inside one transaction
- [x] Apply the same rules to `import_cases_from_json`, accepting either a bare list of case objects or `{"suite": {...}, "cases": [...]}`; when a `suite` block is present its `hub_id` must match the destination hub or the import is rejected with `422 CROSS_HUB_SUITE_ID`.
- [x] Implement export symmetrically: `async def export_suite(db, *, hub_id, suite_id, fmt: Literal["csv","json"]) -> bytes`. The JSON form includes the suite's `target` block and every case including node-assertion columns; the CSV form emits the flat column set above. Set `Content-Disposition: attachment; filename="{suite_slug}.{fmt}"` at the route layer (S6-07e).
- [x] Retarget synthetic generation in [`projects/evalops/src/generation/synthetic.py`](file:///c:/Akshat/ContAIned/projects/evalops/src/generation/synthetic.py):
  ```python
  async def generate_synthetic_test_cases(db, *, hub_id: str, target: SuiteTarget,
                                          count: int = 10, seed_documents: list[str] | None = None,
                                          persist_to_suite_id: str | None = None) -> list[EvalTestCaseCreate]
  ```
  - Agent targets seed the generator with the agent's `system_prompt`, `role` and the sampled content of its bound collections (resolved through the agent's own bindings from S6-05b)
  - Workflow targets seed it with the published version's node summary and the collections referenced by its `RetrievalNode`s, and may additionally emit node-level assertion cases for terminal and router nodes
  - The same `hub_resolver` check runs before generation so generation cannot read a hub the eval hub is not linked to
  - `count` is capped at 100 → `422 GENERATION_LIMIT_EXCEEDED`
- [x] Add `async def suite_health(db, *, hub_id: str) -> list[SuiteIssue]` reporting suites whose target is missing, inactive, or whose hub link has been revoked — consumed by the Eval Hub overview so broken suites are visible without running them.
- [x] Add `tests/test_eval_datasets.py` covering: a suite id from another hub returns `404` on every manager function; duplicate names collide per hub but not across hubs; CSV import with a foreign `suite_id` column is rejected wholesale with no partial writes; export→import round trip preserves node-assertion columns; retargeting a suite with existing runs is blocked; synthetic generation works for both target types and refuses an unlinked target.
