# S6-10f: Admin Console & Auth Screens

> **Parent:** B6-10 (Frontend — Workflow & Eval Hub Workspaces + Admin Console)  
> **Status:** `[x]`  
> **Complexity:** 🔴 High  
> **Owner:** `frontend/src`

---

## Scope

Build `frontend/src/components/admin/` — the platform-admin console for users, approvals, invitations
and the audit log — and extend `frontend/src/components/auth/` with the screens the new account
lifecycle requires: registration, invite acceptance, pending approval, suspended/rejected holding
states and password reset. This replaces
[frontend/src/components/settings/UserManagement.tsx](frontend/src/components/settings/UserManagement.tsx),
which only listed users and swapped the V5 `admin`/`editor`/`viewer` role.

Every destructive or self-affecting control must mirror the server guardrails in `user_management.md`
§4 in the UI, with an explanatory tooltip rather than a silent failure.

## Actionables

- [ ] Create `frontend/src/components/admin/UserDirectory.tsx` at `/admin/users` on the shared `DataTable`:
  - [ ] Columns: avatar + display name + email, status chip (`pending` / `active` / `suspended` / `rejected`), platform-role selector (`admin` / `member`), hub-membership summary chips (`+n more` overflow), identities (google / github / password icons), last login.
  - [ ] Free-text `q` search, status filter, platform-role filter and hub filter wired to `GET /admin/users`.
  - [ ] Row actions: view detail drawer, suspend, reinstate, reject, delete — delete uses the destructive `ConfirmModal` requiring the typed email.
  - [ ] Bulk selection with bulk suspend / bulk approve, showing a per-row result summary when some rows fail.
- [ ] Enforce the self-action guardrails client-side: the current user's own row has role change, suspend and delete **disabled with a tooltip** ("You cannot change your own account"); a delete of the last active admin, or of a hub owner, is disabled with "Transfer hub ownership first".
- [ ] Create `frontend/src/components/admin/ApprovalQueue.tsx` at `/admin/users/pending`:
  - [ ] Card/row per pending user with sign-up method, email domain and requested-at.
  - [ ] **Approve** opens an inline form assigning `platform_role` plus one or more hub grants (hub picker + `hub_role` select) submitted in the single `POST /admin/users/{id}/approve` call.
  - [ ] **Reject** captures an optional reason forwarded to `POST /admin/users/{id}/reject`.
  - [ ] Feeds the sidebar pending-approval badge from `GET /admin/users/pending`, polled every 60 s and invalidated immediately after any approve/reject.
- [ ] Create `frontend/src/components/admin/InviteManager.tsx` at `/admin/invites`:
  - [ ] Single-invite form: email, `platform_role`, repeatable hub grants.
  - [ ] Bulk mode: a paste-a-list textarea accepting newline/comma/semicolon separated addresses, deduplicated and normalised (trimmed + lowercased) before submit, with per-address validation chips and a shared role + hub-grant assignment applied to all.
  - [ ] Table of invites with status (`pending` / `accepted` / `revoked` / `expired`), invited-by, expiry countdown, `resend_count`; actions **Resend** (`POST /admin/invites/{id}/resend`, disabled with a tooltip once the 3-per-hour limit is hit) and **Revoke** (`DELETE /admin/invites/{id}`).
  - [ ] When the create response returns `{"delivered": false, "invite_url": …}`, render a prominent **Copy invite link** control together with a warning banner ("Email delivery is not configured — send this link manually. It is shown only once."); the raw link is never persisted to the store or logged.
- [ ] Create `frontend/src/components/admin/AuditLogViewer.tsx` at `/admin/audit`:
  - [ ] Virtualised list over `GET /admin/audit` (S6-12f) handling tens of thousands of rows.
  - [ ] Filters: actor, hub, `resource_type`, `action`, date range, free text; filters are reflected in the URL query string so a view is shareable.
  - [ ] Each row expands to a before/after diff rendered from `before_json` / `after_json` with added / removed / changed keys highlighted, plus actor IP and timestamp.
- [ ] Create the auth screens under `frontend/src/components/auth/`:
  - [ ] `RegisterPage.tsx` at `/auth/register` — email + password with a live strength meter enforcing the 12-character minimum, and a non-enumerating success state that is identical whether or not the email already exists.
  - [ ] `InviteAccept.tsx` at `/auth/invite/:token` — previews the invite via `GET /auth/invite/{token}` (inviter, role, hub names) and offers **both** *Continue with Google/GitHub* and *Set a password*; renders `409 Invite email mismatch` and expired-invite states explicitly.
  - [ ] `PendingApproval.tsx` at `/auth/pending` — holding screen polling `GET /auth/me` every 30 s, auto-redirecting on approval, with a "contact your administrator" affordance.
  - [ ] `AccountBlocked.tsx` covering `ACCOUNT_SUSPENDED` and `ACCOUNT_REJECTED` reasons with distinct copy.
  - [ ] `ResetPassword.tsx` at `/auth/reset-password/:token` plus a forgot-password entry on `LoginPage.tsx`, both with constant, non-enumerating confirmation copy.
- [ ] Update [frontend/src/components/auth/AuthGuard.tsx](frontend/src/components/auth/AuthGuard.tsx) and [frontend/src/components/auth/RoleGuard.tsx](frontend/src/components/auth/RoleGuard.tsx) to branch on `status` + `platform_role` (`admin` / `member`) and route each `403` `reason` to the matching holding screen; delete every `editor` / `viewer` platform-role branch.
- [ ] Add `frontend/src/store/adminSlice.ts` (`users`, `pendingCount`, `invites`, `auditPage`) and `/admin` API helpers in [frontend/src/services/api.ts](frontend/src/services/api.ts), removing `listUsers()`, `updateUserRole()` and `deactivateUser()` which target the removed `/auth/users` endpoints.
- [ ] Delete [frontend/src/components/settings/UserManagement.tsx](frontend/src/components/settings/UserManagement.tsx) and its tab entry in [frontend/src/components/SettingsPage.tsx](frontend/src/components/SettingsPage.tsx); add the Admin sidebar group in [frontend/src/components/Sidebar.tsx](frontend/src/components/Sidebar.tsx), visible only to platform admins.
- [ ] Add tests: self-row actions are disabled, bulk invite dedupes addresses, the copy-link banner appears only when `delivered === false`, and the audit diff renders changed keys only.
