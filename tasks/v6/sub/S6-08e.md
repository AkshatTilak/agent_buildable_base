# S6-08e: Hub Directory & Creation Wizard

> **Parent:** B6-08 (Frontend — Hub Shell, Information Architecture & Navigation)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend/src`

---

## Scope

Build the two entry points to the hub system: `frontend/src/components/hubs/HubDirectory.tsx` at `/hubs` — the landing page that replaces the old `/system` default destination in [frontend/src/App.tsx](frontend/src/App.tsx) — and `frontend/src/components/hubs/HubCreateWizard.tsx` at `/hubs/new`.

The directory presents every hub the user belongs to, grouped by the four types, with search, type filtering, an archived toggle, resource counts, member avatars and last-activity. The wizard collects type, name, slug, description, accent/icon, initial members and initial links in a stepped flow, enforcing the `hubs.md` §3.3 direction matrix while picking initial links so an invalid grant can never be submitted.

## Actionables

- [ ] Create `frontend/src/components/hubs/HubDirectory.tsx` rendered at `routes.hubs.directory()`.
  - [ ] Four sections in fixed order — Ingestion, Agent, Workflow, Eval — each with a section header, count, and a per-section "New" button gated on creation rights.
  - [ ] Card grid using the standard `--bg-surface` card with `--space-xl` padding and `--space-lg` grid gap.
- [ ] Implement the hub card contents:
  - [ ] Hub `icon` in an accent-tinted tile, `name` in `font-display`, `{hub_type}/{slug}` in `font-mono` `--text-muted`, truncated description.
  - [ ] Resource counts from `hub.resource_counts` rendered as compact `mono-data` chips with type-appropriate labels (collections/documents for ingestion, agents for agent, workflows/runs for workflow, suites/runs for eval).
  - [ ] Overlapping member avatar stack capped at five with a `+N` overflow chip; hovering shows names.
  - [ ] Relative last-activity timestamp and the caller's own `my_role` as a caption badge.
  - [ ] An `Archived` badge and reduced-opacity treatment for archived hubs.
- [ ] Implement directory controls in a sticky toolbar:
  - [ ] Debounced text search over name, slug and description.
  - [ ] Type filter chips (multi-select) that hide non-matching sections entirely.
  - [ ] "Show archived" toggle, default off, persisted in [frontend/src/store/settingsSlice.ts](frontend/src/store/settingsSlice.ts).
  - [ ] Sort control: Last activity (default), Name, Created.
  - [ ] Reflect search/filter state in the query string so a filtered directory is linkable and survives reload.
- [ ] Clicking a card navigates to `routes.hubs.shell(hub.hub_type, hub.id)`; a per-card overflow menu offers Members, Links and Settings, each entry rendered only when the corresponding `can(...)` check passes for that hub's `my_role`.
- [ ] Create `frontend/src/components/hubs/HubCreateWizard.tsx` at `routes.hubs.create()` as a four-step flow with a persistent step rail and back/next navigation.
  ```ts
  interface HubCreateDraft {
    hub_type: HubType;            // step 1 — immutable after creation
    name: string;                 // step 2
    slug: string;                 // step 2 — auto-derived, editable
    description: string;          // step 2
    accent: string;               // step 3
    icon: string;                 // step 3
    members: { user_id: string; hub_role: Exclude<HubRole, "owner"> }[]; // step 4
    links: { target_hub_id: string; access_level: HubAccessLevel }[];    // step 4
  }
  ```
- [ ] Step 1 — type selection: four large cards describing what each type owns (per `hubs.md` §2), with explicit copy that the type is fixed at creation and cannot be changed later.
- [ ] Step 2 — identity: name field, slug auto-derived by lowercasing/hyphenating the name until the user edits it manually.
  - [ ] Live uniqueness check against `api.hubs.checkSlug(hub_type, slug)`, debounced ~400ms, with three visible states: checking (spinner), available (emerald check), taken (rose message).
  - [ ] Make the "unique within hub type, not globally" rule explicit in helper text — `ingestion/support-kb` and `agent/support-kb` may coexist.
  - [ ] Client-side slug validation (`^[a-z0-9][a-z0-9-]{1,63}$`) before any network call, and Next disabled while the check is pending or failing.
- [ ] Step 3 — appearance: accent picker limited to the design-system accent tokens (emerald, indigo, amber, cyan, rose) and a searchable `lucide` icon picker, with a live preview of the hub card and shell header.
- [ ] Step 4 — access: optional initial members (existing users only, searched by email/name, role selector excluding `owner`) and optional initial links.
  - [ ] The link target picker only lists hubs that are a legal target for the chosen source type per the §3.3 matrix — `agent→ingestion`, `workflow→agent`, `workflow→ingestion`, `eval→workflow`, `eval→agent` — and shows an explanatory caption when the matrix yields no options (e.g. an ingestion hub, which may not link out).
  - [ ] Only hubs where the creator holds at least `contributor` are selectable as targets; ineligible hubs are listed disabled with the reason.
  - [ ] `access_level` selector (`read` / `use`) with one-line explanations of each.
- [ ] On submit, create the hub, then apply members and links; if a follow-up call fails, the hub still exists — navigate into the new hub and surface a non-blocking warning naming exactly which members/links were not applied, rather than rolling back or silently succeeding.
- [ ] Role gating: the wizard route and all "New hub" affordances are hidden entirely for a `member` when `ALLOW_MEMBER_HUB_CREATION` is disabled; directory card overflow actions follow the per-hub `my_role`, and every action on an archived hub is disabled with the archived tooltip rather than hidden.
- [ ] Loading / empty / error expectations:
  - [ ] Directory renders a skeleton card grid while `hubListStatus === "loading"`.
  - [ ] Zero hubs overall → full-page [frontend/src/components/shared/EmptyState.tsx](frontend/src/components/shared/EmptyState.tsx) explaining hubs and offering create (or "ask an administrator to add you to a hub" when creation is not permitted).
  - [ ] A type section with no hubs renders a slim inline empty row, not a full empty state.
  - [ ] Search yielding nothing renders "No hubs match '{query}'" with a clear-filters action.
  - [ ] Load failure renders a retryable [frontend/src/components/shared/ErrorBanner.tsx](frontend/src/components/shared/ErrorBanner.tsx); wizard submission failures keep all entered form state intact.
