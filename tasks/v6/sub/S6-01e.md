# S6-01e: Migration Stage 2 — Seed, Backfill & Constrain

> **Parent:** B6-01 (Hub Domain Model & Tenancy Foundation)  
> **Status:** `[ ]`  
> **Complexity:** 🔴 High  
> **Owner:** `migrations`

---

## Scope

Author the cutover revision that turns the additive stage-1 schema into the real V6 tenancy model. It
performs steps 3–9 of [`hubs.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/logic/hubs.md)
§6: seed the four default hubs, seed the allowed links between them, enrol every existing active user with
the mapped hub role, backfill `hub_id` on every row, tighten those columns to `NOT NULL`, populate
`physical_name` and rename the physical Qdrant collections, drop `syntraflow_collections.tenant_id` and
`users.role`, and rebuild the uniqueness constraints per §3.7.

This is a **hard cutover** — after it runs, the V5 gateway can no longer start. It must be idempotent when
re-run against an already-migrated database and must implement a working `downgrade()` that restores a
V5-compatible schema.

## Actionables

- [ ] Create `migrations/versions/b7c2d3e4f5a6_v6_hub_tenancy_stage2_cutover.py` with
      `revision = "b7c2d3e4f5a6"` and `down_revision = "a6b1c2d3e4f5"` (stage 1). Reuse the
      `_has_table` / `_has_column` inspector helpers from `S6-01d`, plus:
  ```python
  def _has_constraint(table: str, name: str) -> bool: ...
  def _scalar(sql: str, **params): return op.get_bind().execute(sa.text(sql), params).scalar()
  ```
- [ ] **(§6 step 3) Resolve the bootstrap owner, then seed the four default hubs.** Deterministic UUIDs
      make the whole revision replay-safe:
  ```python
  SEED_HUBS = [
      ("00000000-0000-0000-0000-0000000000a1", "ingestion", "default", "Default Ingestion Hub"),
      ("00000000-0000-0000-0000-0000000000a2", "agent",     "default", "Default Agent Hub"),
      ("00000000-0000-0000-0000-0000000000a3", "workflow",  "default", "Default Workflow Hub"),
      ("00000000-0000-0000-0000-0000000000a4", "eval",      "default", "Default Eval Hub"),
  ]
  ```
  - Owner resolution: first `users` row with `role = 'admin'` (or `platform_role = 'admin'` if stage 1's
    backfill already ran), ordered by `created_at ASC`.
  - If no admin exists, insert a synthetic user `system@contained.local` with
    `platform_role = 'admin'`, `provider = 'system'`, `provider_id = 'system'` and a deterministic id
    `00000000-0000-0000-0000-00000000000f`. The synthetic account must have **no** credential material —
    it is not loginable.
  - Guard every insert with `INSERT ... WHERE NOT EXISTS (SELECT 1 FROM hubs WHERE id = :id)` (or an
    explicit `_scalar` existence check) so a re-run inserts nothing.
- [ ] **(§6 step 2 completion) Backfill `users.platform_role` and drop `users.role`:**
  - `UPDATE users SET platform_role = CASE role WHEN 'admin' THEN 'admin' ELSE 'member' END WHERE platform_role IS NULL;`
    (`admin → admin`, `editor → member`, `viewer → member`, per §4.1.)
  - `ALTER TABLE users ALTER COLUMN platform_role SET NOT NULL` and set the server default `'member'`.
  - `op.drop_column("users", "role")` — guarded by `_has_column`.
  - Delete all rows from `user_sessions`: dropped role claims invalidate every issued token, and a stale
    session carrying `role` must not be honoured after cutover.
- [ ] **(§6 step 5) Seed `hub_links` between the four default hubs along every allowed direction** in
      §3.3, so existing agent→collection, workflow→agent and eval→agent references keep working:
  | source | target | `access_level` |
  |---|---|---|
  | `agent/default` | `ingestion/default` | `read` |
  | `workflow/default` | `agent/default` | `use` |
  | `workflow/default` | `ingestion/default` | `read` |
  | `eval/default` | `workflow/default` | `use` |
  | `eval/default` | `agent/default` | `use` |
  - `created_by` = the resolved bootstrap owner. Guard on the `(source_hub_id, target_hub_id)` unique key.
- [ ] **(§6 step 6) Enrol every existing user in all four seed hubs** with the mapped hub role, reading
      from the pre-drop `role` value captured before the previous step (snapshot it into a temp dict
      first):
  - old `admin` → `owner`, old `editor` → `contributor`, old `viewer` → `viewer`.
  - Skip users whose V5 `is_active` is false.
  - `INSERT ... ON CONFLICT (hub_id, user_id) DO NOTHING` for idempotency.
- [ ] **(§6 step 4) Backfill `hub_id` on every table**, mapping each table to its seed hub by owning
      module, then `SET NOT NULL`:
  ```python
  BACKFILL = {
      "ingestion": ["syntraflow_collections", "syntraflow_documents", "syntraflow_chunks",
                    "syntraflow_video_segments", "syntraflow_jobs"],
      "agent":     ["agent_definitions", "agent_invocation_log"],
      "workflow":  ["workflows"],
      "eval":      ["eval_test_suites", "eval_run_history", "eval_flow_traces"],
  }
  ```
  - Run `UPDATE {table} SET hub_id = :hub_id WHERE hub_id IS NULL` for each.
  - Then `op.alter_column(table, "hub_id", nullable=False)` for all 11 tables.
  - Before each `SET NOT NULL`, assert `SELECT count(*) FROM {table} WHERE hub_id IS NULL` is `0` and
    raise a descriptive `RuntimeError` naming the table if not — a silent failure here would produce an
    unusable database.
  - `api_keys`, `mcp_servers` and `playground_sessions` are **left NULL** (platform-scoped) and stay
    nullable.
- [ ] **(§6 step 7) Populate `physical_name` and rename the physical Qdrant collections:**
  - `UPDATE syntraflow_collections SET physical_name = 'default__' || name WHERE physical_name IS NULL;`
  - `ALTER COLUMN physical_name SET NOT NULL` and add
    `uq_syntraflow_collections_physical_name`.
  - Qdrant has no in-place rename: for each collection create an alias `default__{name}` pointing at the
    existing physical collection via the client in `common/clients/qdrant.py`
    (`update_collection_aliases` with a `CreateAliasOperation`). Record in the module docstring that a
    true rename requires snapshot → restore under the new name and is an out-of-band operation.
  - Gate the vector-store work behind `if os.getenv("V6_SKIP_QDRANT_ALIAS") != "1":` and wrap it in
    `try/except` that logs a warning and continues — the SQL migration must never fail because Qdrant is
    unreachable from the migration runner (e.g. in CI).
- [ ] **(§6 step 8) Drop `syntraflow_collections.tenant_id`** — guarded by `_has_column`. Nothing reads it
      after `S6-01c`.
- [ ] **(§6 step 9) Rebuild the unique constraints per §3.7.** V5 constraint names are Postgres
      auto-generated, so discover them via the inspector rather than hard-coding:
  - Drop the single-column unique on `agent_definitions.endpoint_slug`; create
    `uq_agent_definitions_hub_slug` on `(hub_id, endpoint_slug)`.
  - Drop the single-column unique on `syntraflow_collections.name`; create
    `uq_syntraflow_collections_hub_name` on `(hub_id, name)`.
  - Create `uq_workflows_hub_name` on `workflows (hub_id, name)`.
  - Create `uq_eval_test_suites_hub_name` on `eval_test_suites (hub_id, name)`.
  - Before creating each composite constraint, run a duplicate probe
    (`SELECT hub_id, name FROM ... GROUP BY 1,2 HAVING count(*) > 1`) and abort with a message listing the
    offending rows rather than letting `CREATE UNIQUE INDEX` fail opaquely.
- [ ] Write one `audit_log` row per seeded artefact (`action='create'`, `resource_type='hub'` /
      `'hub_link'` / `'hub_member'`, `summary='V6 migration seed'`, `actor_user_id` = bootstrap owner) so
      the audit trail starts at the cutover rather than at the first user action.
- [ ] Implement `downgrade()` restoring a working V5 schema, in reverse order:
  1. Drop the four composite unique constraints; recreate the single-column uniques on
     `agent_definitions.endpoint_slug` and `syntraflow_collections.name`.
  2. Re-add `syntraflow_collections.tenant_id` as `String(255) NOT NULL DEFAULT 'default'`.
  3. Drop `physical_name`'s unique constraint and set the column nullable again.
  4. `ALTER ... SET NULL` (drop the NOT NULL) on all 11 `hub_id` columns.
  5. Re-add `users.role` as `String(20) NOT NULL DEFAULT 'viewer'` and backfill it as
     `admin → admin`, `member → editor`.
  6. Delete the seeded `hub_members`, `hub_links` and `hubs` rows by their deterministic ids, and the
     synthetic `system@contained.local` user if it was created here.
  - Do **not** drop the hub tables themselves — that is stage 1's `downgrade()`.
- [ ] Add `tests/test_migration_v6_stage2.py` proving the acceptance criteria:
  - Against a fixture database seeded with V5 rows (2 collections, 2 agents, 1 workflow, 1 eval suite,
    3 users with roles `admin`/`editor`/`viewer`): after upgrade, every row has the correct `hub_id`, the
    four hubs and five links exist, and all three users are members of all four hubs with roles
    `owner`/`contributor`/`viewer`.
  - Re-running `upgrade` is a no-op: hub, link and member counts are unchanged.
  - `downgrade` then `upgrade` round-trips without error and yields the same row counts.
  - `users.role` and `syntraflow_collections.tenant_id` no longer exist after upgrade.
