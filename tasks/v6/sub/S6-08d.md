# S6-08d: `hubSlice` & Hub-Scoped API Client

> **Parent:** B6-08 (Frontend — Hub Shell, Information Architecture & Navigation)  
> **Status:** `[ ]`  
> **Complexity:** 🔴 High  
> **Owner:** `frontend/src`

---

## Scope

Deliver the V6 state and transport layer. [frontend/src/services/api.ts](frontend/src/services/api.ts) currently exposes ~78 flat helpers (`getAgents()`, `getCollections(tenantId?)`, `getDocuments()`, `getJobs()`, `listSuites()`, `getWorkflows()`, …) that hit un-scoped endpoints. Every one of those that touches a hub-scoped table is rewritten to take `hubId` as an explicit first argument and target the `/hubs/{hub_id}/...` prefix from `hubs.md` §5.1; the flat variants are deleted, not aliased.

Alongside it, `frontend/src/store/hubSlice.ts` becomes the new home for hub lists, the active hub, membership and links. Existing domain slices — [frontend/src/store/agentSlice.ts](frontend/src/store/agentSlice.ts), [frontend/src/store/ingestionSlice.ts](frontend/src/store/ingestionSlice.ts) and [frontend/src/store/workflowSlice.ts](frontend/src/store/workflowSlice.ts) — stop holding a single global array and instead key their data by `hubId`, which also removes the singleton `currentWorkflow` assumption called out in `hubs.md` §9.

  export type HubType = "ingestion" | "agent" | "workflow" | "eval";
  export type HubRole = "owner" | "maintainer" | "contributor" | "viewer";
  export type HubAccessLevel = "read" | "use";

  export interface Hub {

- [ ] Delete the flat hub-scoped helpers outright: `getAgents`, `getAgent`, `createAgent`, `updateAgent`, `deleteAgent`, `toggleAgentActive`, `getAgentStats`, `invokeAgent`, `getWorkflows`, `getActiveWorkflow`, `createWorkflow`, `activateWorkflow`, `ingestDocument`, `getDocuments`, `getJobs`, `getJobStatus`, `getDocumentChunks`, `deleteDocument`, `getCollections`, `createCollection`, `getCollectionDetails`, `deleteCollection`, `queryRetrievalEngine`, and the whole flat `/api/evalops/*` suite/run/case set.
  - [ ] Drop the `tenantId` parameter from the collections calls entirely — `syntraflow_collections.tenant_id` no longer exists.
  - [ ] Keep the existing `request()` wrapper (retries, timeout, `FormData` handling) unchanged; only the endpoint construction and signatures change.
- [ ] Add a `hubPath(hubId, ...segments)` internal helper so no hub endpoint is assembled by ad-hoc template literals, and assert in review that no hub-scoped call can be made without a `hubId`.
- [ ] Implement typed error mapping in the client so hub failures surface as structured errors rather than raw strings.
  ```ts
  export type HubErrorCode =
    | "HUB_NOT_FOUND"
    | "HUB_ROLE_INSUFFICIENT"
    | "HUB_ARCHIVED"
    | "HUB_LINK_REQUIRED"
    | "HUB_LINK_REVOKED";

  export class HubApiError extends Error {
    code: HubErrorCode;
    hubId?: string;
    targetHubId?: string;
    status: number;
  }
  ```
  - [ ] `HUB_LINK_REQUIRED` / `HUB_LINK_REVOKED` carry the target hub id so the UI can offer a direct "Request link" / "Restore link" action (consumed by S6-09e).
  - [ ] `HUB_ARCHIVED` (`409`) is rendered as an inline banner explaining the hub is read-only, never as a generic failure toast.
  - [ ] `HUB_ROLE_INSUFFICIENT` (`403`) should be treated as a bug in gating — log a console warning in dev, since gated UI should have prevented the call.
- [ ] Re-key the domain slices by hub:
  - [ ] [frontend/src/store/agentSlice.ts](frontend/src/store/agentSlice.ts): `agents: Agent[]` → `agentsByHub: Record<string, Agent[]>`.
  - [ ] [frontend/src/store/ingestionSlice.ts](frontend/src/store/ingestionSlice.ts): collections, documents and jobs keyed by `hubId`; ingestion settings remain user-level.
  - [ ] [frontend/src/store/workflowSlice.ts](frontend/src/store/workflowSlice.ts): remove `currentWorkflow` as the single workflow; store `workflowsByHub` plus an explicit `openWorkflowId`.
  - [ ] Provide `selectAgentsForHub(hubId)`-style selectors so components never index the record maps directly.
- [ ] Evict a hub's cached slice data on archive, on membership loss, and on `HUB_NOT_FOUND`, so a revoked user cannot keep seeing stale resources from a previous session.
- [ ] Role gating contract exposed by this layer: the client never decides permissions, but every mutating method is documented as requiring a prior `can(...)` check from S6-08b; the store must not optimistically apply a mutation before the server confirms for `delete` and `archive` operations.
- [ ] Loading / empty / error expectations:
  - [ ] `hubListStatus` drives the sidebar and directory skeletons; components read status rather than inferring loading from an empty array.
  - [ ] Empty is a first-class state — `hubsByType[type] = []` after a successful load means "no hubs", distinct from `"loading"`.
  - [ ] `hubListError` holds a user-facing message and the failed request is retryable without a page reload.
- [ ] Verify the whole frontend still type-checks with zero errors after the signature changes; any remaining call site using a deleted helper must be migrated by its owning subtask, not shimmed here.
