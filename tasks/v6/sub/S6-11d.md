# S6-11d: Migration Dry-Run & Rollback Harness

> **Parent:** B6-11 (Legacy Decommission, Data Migration & Verification)  
> **Status:** `[x]`  
> **Complexity:** 🔴 High  
> **Owner:** `scripts`, `migrations`

---

## Scope

Prove the V6 migration chain against real V5 data before it is ever run on a live deployment. Build
`scripts/migration_dryrun.py`, which restores a representative V5 dump into a throwaway database, runs
`alembic upgrade head` through the full V6 chain, and asserts the outcome described in `hubs.md` §6 —
row counts preserved, four seed hubs created, hub links seeded, `hub_id` backfilled everywhere,
constraints rebuilt. It must also exercise `downgrade` back to the V5 head and an idempotent re-`upgrade`.

Boundary: this subtask does not author the migrations themselves (B6-01 … B6-07 do); it verifies them.

## Actionables

- [x] Create `scripts/migration_dryrun.py` with a CLI: `--dump <path.sql>`, `--database-url`, `--keep` (retain the scratch DB on failure), `--skip-downgrade`.
  - [x] Creates a scratch database (`contained_dryrun_<timestamp>`), restores the dump, and drops it in a `finally` block unless `--keep`.
  - [x] Never touches the URL in `common/config/settings.py` unless it is explicitly passed; refuses to run if the target database name lacks the `dryrun` prefix.
- [x] Add `scripts/fixtures/v5_reference_dump.sql` (or a documented generator) containing a representative V5 dataset: ≥3 users across `admin`/`editor`/`viewer`, ≥2 collections with documents/chunks/jobs, ≥3 agent definitions with invocation logs, ≥2 workflows with `graph_json` containing bare `agent_id` node references, ≥2 eval suites with cases, runs, metric results and flow traces, and ≥1 API key and MCP server.
- [x] Snapshot pre-migration counts for every table in `hubs.md` §3.6 and assert post-migration parity (no row lost, no row duplicated) — report a per-table before/after table on failure.
- [x] Assert seed-hub creation: exactly four rows in `hubs` with `(hub_type, slug)` of `('ingestion','default')`, `('agent','default')`, `('workflow','default')`, `('eval','default')`, each owned by the first `admin` user, or by a synthetic `system@contained.local` admin when the dump has no admin (cover both cases with two fixture variants).
- [x] Assert seeded `hub_links`: one row for every allowed direction in §3.3 between the four seed hubs (`agent→ingestion`, `workflow→agent`, `workflow→ingestion`, `eval→workflow`, `eval→agent`), and assert that **no** link targets an `eval` hub.
- [x] Assert `hub_id` backfill and nullability: for every table in §3.6 marked NOT NULL, `SELECT count(*) WHERE hub_id IS NULL` = 0 **and** the column's `is_nullable` is `NO` in `information_schema.columns`.
- [x] Assert membership migration: every previously active user is a member of all four seed hubs with the mapped role (`admin→owner`, `editor→contributor`, `viewer→viewer`), and `users.platform_role` is `admin` or `member` with the `role` column dropped.
- [x] Assert workflow migration per `workflow_v6.md` §6: each legacy workflow has a `workflow_versions` row with `version_number = 1`, referenced by both `draft_version_id` and `published_version_id`, `status = 'published'`, `workflows.graph_json` column dropped, and every bare `agent_id` node reference rewritten to a qualified `{type, hub_id, agent_id}` object pointing at the `agent/default` hub.
- [x] Assert constraint rebuild via `information_schema.table_constraints`: `UNIQUE (hub_type, slug)` on `hubs`, `UNIQUE (hub_id, endpoint_slug)` on `agent_definitions`, `UNIQUE (hub_id, name)` on `syntraflow_collections`, `UNIQUE (hub_id, name)` on `workflows` and `eval_test_suites`, `UNIQUE (workflow_id, version_number)` on `workflow_versions`, and that `syntraflow_collections.tenant_id` no longer exists.
- [x] Assert Qdrant physical renaming logic: `syntraflow_collections.physical_name` equals `default__{name}` for every migrated row; run against a live Qdrant when `--with-qdrant` is passed and assert the renamed collections exist and the old names do not.
- [x] Exercise rollback: run `alembic downgrade <v5_head>`, assert the V5 columns (`users.role`, `users.is_active`, `syntraflow_collections.tenant_id`, `workflows.graph_json`) are back and the V6 tables are gone, then run the V5 test suite against the downgraded schema.
- [x] Exercise idempotency: run `alembic upgrade head` twice in a row and assert the second run is a clean no-op — no duplicate seed hubs, no duplicate links, no constraint errors, exit code 0.
- [x] Wire the script into CI as a scheduled/manual job and document invocation in [`references/deployment/deployment_guide.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/deployment/deployment_guide.md) with the exact command and expected output.
