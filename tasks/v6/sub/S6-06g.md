## Scope

Complete the Workflow Hub cutover. The schema move happened in S6-06a; this subtask handles the
*semantic* migration that S6-06a could not do until the parser existed: rewriting legacy bare agent
references inside migrated `graph_json` into qualified `{type, hub_id, resource_id}` objects pointing at
the `agent/default` seed hub, and seeding the `workflow/default → agent/default` hub link so those
rewritten references actually resolve.

It then deletes the V5 singleton workflow surface — the `/workflows` CRUD block and the
`is_active`-based "active workflow" concept in
[`projects/guardroute/api.py`](file:///c:/Akshat/ContAIned/projects/guardroute/api.py) — and lands
`tests/test_workflow_hub.py`, the acceptance suite for B6-06.

## Actionables

- [x] Add Alembic revision `migrations/versions/<rev>_workflow_reference_rewrite.py` (depends on the S6-06a revision) that, for every `workflow_versions` row:
  - Loads `graph_json`, walks `nodes`, and for each node whose type is in `NODE_REFERENCE_REQUIREMENTS` (S6-06c) rewrites the legacy field into a qualified reference:
    - `data.agent_id` / `data.agent` → `data.reference = {"type": "agent", "hub_id": <agent/default id>, "resource_id": <agent_id>}`
    - `data.collection` / `data.collection_name` → resolve the collection by name within `ingestion/default` and emit `{"type": "collection", "hub_id": <ingestion/default id>, "resource_id": <collection_id>}`
    - `MultiAgentNode.data.agents[]` → `data.references[]` with the same shape
  - Removes the legacy keys after rewriting so no node carries both forms
  - Records unrewritable nodes (agent id not found, collection name ambiguous) into `workflow_versions.validation_json` with code `MIGRATION_UNRESOLVED_REFERENCE` and sets `is_valid = false`, rather than failing the migration
- [x] Seed the required links if S6-01e did not already: `workflow/default → agent/default` (`access_level='use'`) and `workflow/default → ingestion/default` (`access_level='read'`), each guarded by an existence check so the revision is idempotent.
- [x] Write a migration report to the log and to `audit_log` (`action="migrate"`, `resource_type="workflow"`, `hub_id=<workflow/default>`) summarising counts: versions scanned, references rewritten, references unresolved.
- [x] Implement `downgrade()` that reverses the rewrite by flattening `data.reference.resource_id` back into `data.agent_id` / `data.collection`.
- [x] Delete the legacy workflow surface from [`projects/guardroute/api.py`](file:///c:/Akshat/ContAIned/projects/guardroute/api.py):

  - The `WorkflowCreatePayload` and `WorkflowResponse` models defined inline in that file
  - Every `update(WorkflowDefinition).values(is_active=False)` "deactivate all others" statement — the singleton-active concept is gone in V6
- [x] Remove the singleton store slice usage on the client: delete `currentWorkflow`, `nodes` and `edges` from `frontend/src/store/workflowSlice.ts` and repoint `frontend/src/services` calls from `/workflows*` to `/hubs/{hubId}/workflows*`, matching the store contract in [`workflow_v6.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/logic/workflow_v6.md) §5. - [x] Create `tests/test_workflow_hub.py` with fixtures for two workflow hubs (`workflow/alpha`, `workflow/beta`), one agent hub (`agent/bots`) linked only to `alpha`, and users at each hub role. Cover:
