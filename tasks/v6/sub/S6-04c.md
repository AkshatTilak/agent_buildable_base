# S6-04c: Hub-Scoped Ingestion Pipeline & Jobs

> **Parent:** B6-04 (Ingestion Hub — Collections & Datastore Bindings)  
> **Status:** `[ ]`  
> **Complexity:** 🔴 High  
> **Owner:** `projects/syntraflow`  

---

## Scope

Thread `hub_id` and the target collection through the ingestion pipeline so that every persisted row
and every vector/graph write is attributable to exactly one hub. Today
`projects/syntraflow/src/ingestion/pipeline.py::ingest_document_pipeline` and `ingest_video_pipeline`
receive a bare `vector_client: VectorClient` and write `SyntraFlowDocument` rows with no tenancy
column, and `projects/syntraflow/src/worker.py::process_ingestion_job` constructs `VectorClient()`
directly.

After this subtask, both pipelines require `hub_id` and `collection_id`, stamp `hub_id` onto documents,
chunks, video segments and jobs, reject a collection that belongs to another hub, and route every write
through the clients returned by the S6-04b resolver.

## Actionables

- [ ] Add `hub_id = Column(String(36), ForeignKey("hubs.id", ondelete="CASCADE"), nullable=False, index=True)`
      to `SyntraFlowDocument`, `SyntraFlowChunk`, `SyntraFlowVideoSegment` and `SyntraFlowJob` in
      `projects/syntraflow/src/database/models.py`, plus
      `collection_id = Column(String(36), ForeignKey("syntraflow_collections.id", ondelete="CASCADE"), nullable=False, index=True)`
      on `SyntraFlowDocument` and `SyntraFlowJob`.
  - `hub_id` on chunks and video segments is denormalised from the parent document, per `hubs.md` §3.6.
  - Add composite indexes `(hub_id, collection_id)` on documents and `(hub_id, status)` on jobs.
- [ ] Change the pipeline signatures in `projects/syntraflow/src/ingestion/pipeline.py`:
  ```python
  async def ingest_document_pipeline(
      file_bytes: bytes, filename: str, db: AsyncSession,
      inference_client: InferenceClient,
      *, hub_id: str, collection_id: str,
      job_id: Optional[Any] = None, chunker_type: Optional[str] = None,
      chunk_size: int = 512, chunk_overlap: int = 64,
      pre_processors: Optional[List[str]] = None,
      post_processors: Optional[List[str]] = None,
  ) -> Any
  ```
  - Apply the same change to `ingest_video_pipeline`.
  - Remove the `vector_client: VectorClient` parameter; obtain the client internally via
    `await resolve_vector_client(db, hub_id)` so a caller can never inject a foreign store.
- [ ] Add `async def assert_collection_in_hub(db, hub_id: str, collection_id: str) -> SyntraFlowCollection`
      to `projects/syntraflow/src/ingestion/pipeline.py` and call it as the **first** statement of both
      pipelines:
  - Query `select(SyntraFlowCollection).where(id == collection_id, hub_id == hub_id)`.
  - Missing → `HTTPException(404, "Collection not found")`; belonging to another hub → the identical
    `404` (never `403`, to match the enumeration policy in `hubs.md` §5.2).
- [ ] Stamp tenancy on every insert:
  - `SyntraFlowDocument(hub_id=hub_id, collection_id=collection_id, ...)`.
  - Each `SyntraFlowChunk` and `SyntraFlowVideoSegment` inherits `hub_id` from the document.
  - `update_job(...)` keeps its signature but every job row is created with `hub_id` and `collection_id`
    by the caller in `projects/syntraflow/api.py`.
- [ ] Scope duplicate detection to the hub: the SHA-256 `file_hash` check must be
      `where(SyntraFlowDocument.file_hash == h, SyntraFlowDocument.hub_id == hub_id, SyntraFlowDocument.collection_id == collection_id)`
      — the same file ingested into two hubs produces two independent documents.
- [ ] Route vector writes through the resolved client and the hub's physical collection name:
  - Replace the hard-coded `"syntraflow_chunks_v1"` collection name with
    `collection.physical_name` from S6-04a everywhere in `projects/syntraflow/src/ingestion/vector_writer.py`.
  - Every upserted point payload must include `hub_id`, `collection_id`, `document_id`, `tags`,
    `timestamp` and `access_level`; keep the 100-vectors-per-upsert batching.
  - Use the embedding model and `vector_dimension` recorded on the collection row, and fail with
    `409 {"detail": "Embedding dimension mismatch"}` when the inference client returns a different width.
- [ ] Route graph writes through `resolve_graph_client(db, hub_id)`:
  - Every `SyntraFlow_*` node created by the entity/relationship extraction pass carries
    `hub_id` and `collection_id` properties.
  - Deduplication `MERGE` keys must include `hub_id` so two hubs never collapse into a shared entity node.
- [ ] Update `projects/syntraflow/src/worker.py::process_ingestion_job` to accept
      `hub_id: str, collection_id: str`, drop its direct `VectorClient()` construction, and pass both
      through to the pipelines; include `hub_id` and `collection_id` in the Kafka message payload
      published to `syntraflow-ingestion-jobs` and validate them on consume.
  - A job message missing `hub_id` is dead-lettered with an explicit log line, never processed against
    a default hub.
- [ ] Propagate `hub_id` into observability: add it as a span attribute in
      `common/observability/tracing.py` spans opened by the pipeline and as a structured log field in
      the `syntraflow.ingestion` logger, so per-hub ingestion volume is measurable.
- [ ] Update all pipeline call sites (`projects/syntraflow/api.py` ingest routes, the MCP server in
      `projects/syntraflow/src/mcp_server.py`, and `tests/fixtures/`) to the new keyword-only signature;
      the flat route rewrite itself is S6-04e.
