# S6-01a: Hub, HubMember & HubLink Models

> **Parent:** B6-01 (Hub Domain Model & Tenancy Foundation)  
> **Status:** `[x] Completed`  
> **Complexity:** 🟡 Medium  
> **Owner:** `common/models`

---

## Scope

Land the three core tenancy tables — `hubs`, `hub_members` and `hub_links` — as SQLAlchemy models on the
shared `Base` in `common/models/database.py`, exactly as specified in
[`hubs.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/logic/hubs.md) §3.1–§3.3. Alongside
the models, publish a single canonical constants module that defines the four hub types, the four hub
roles with their ordering, the two link access levels, and the allowed cross-hub link-direction matrix.
Every other V6 subtask imports these constants rather than re-declaring string literals.

This subtask is **model-layer only**. No Alembic revision is authored here (that is `S6-01d`), no Pydantic
schemas (`S6-01f`), and no FastAPI dependency (`S6-02b`). The models must import cleanly and
`Base.metadata` must contain the three new tables when `common.models.database` is imported.

## Actionables

- [ ] Create `common/models/hub_enums.py` as the single source of truth for hub vocabulary — no other
      module may hard-code these strings:
  ```python
  """Canonical hub type / role / link constants (hubs.md §2, §3.3, §4.2)."""
  from typing import Final

  HUB_TYPE_INGESTION: Final = "ingestion"
  HUB_TYPE_AGENT: Final = "agent"
  HUB_TYPE_WORKFLOW: Final = "workflow"
  HUB_TYPE_EVAL: Final = "eval"
  HUB_TYPES: Final[tuple[str, ...]] = (
      HUB_TYPE_INGESTION, HUB_TYPE_AGENT, HUB_TYPE_WORKFLOW, HUB_TYPE_EVAL,
  )

  HUB_ROLE_OWNER: Final = "owner"
  HUB_ROLE_MAINTAINER: Final = "maintainer"
  HUB_ROLE_CONTRIBUTOR: Final = "contributor"
  HUB_ROLE_VIEWER: Final = "viewer"
  HUB_ROLE_ORDER: Final[dict[str, int]] = {
      HUB_ROLE_OWNER: 4,
      HUB_ROLE_MAINTAINER: 3,
      HUB_ROLE_CONTRIBUTOR: 2,
      HUB_ROLE_VIEWER: 1,
  }
  HUB_ROLES: Final[tuple[str, ...]] = tuple(HUB_ROLE_ORDER)

  LINK_ACCESS_READ: Final = "read"
  LINK_ACCESS_USE: Final = "use"
  LINK_ACCESS_ORDER: Final[dict[str, int]] = {LINK_ACCESS_READ: 1, LINK_ACCESS_USE: 2}
  ```
- [ ] In the same module add the ordering helpers used by every authorisation check:
  ```python
  def hub_role_rank(role: str | None) -> int:
      """Return the numeric rank of a hub role; 0 for unknown/None."""
      return HUB_ROLE_ORDER.get(role or "", 0)

  def hub_role_satisfies(actual: str | None, required: str) -> bool:
      """True when `actual` is at least as privileged as `required` (owner >= maintainer >= ...)."""
      return hub_role_rank(actual) >= hub_role_rank(required)

  def link_access_satisfies(actual: str | None, required: str) -> bool:
      return LINK_ACCESS_ORDER.get(actual or "", 0) >= LINK_ACCESS_ORDER.get(required, 99)
  ```
  - `hub_role_satisfies("owner", "contributor")` → `True`; `hub_role_satisfies("viewer", "contributor")` → `False`.
  - `hub_role_rank` must return `0` (never raise) for `None` or garbage so a missing membership can never
    accidentally satisfy a check.
- [ ] Add the module-level allowed link-direction matrix, transcribed verbatim from `hubs.md` §3.3, plus
      its validator. Nothing may link *into* an `eval` hub, and links are never transitive:
  ```python
  ALLOWED_LINK_DIRECTIONS: Final[frozenset[tuple[str, str]]] = frozenset({
      (HUB_TYPE_AGENT,    HUB_TYPE_INGESTION),  # agents retrieve from linked collections
      (HUB_TYPE_WORKFLOW, HUB_TYPE_AGENT),      # workflow nodes instantiate linked agents
      (HUB_TYPE_WORKFLOW, HUB_TYPE_INGESTION),  # workflow retrieval nodes query linked collections
      (HUB_TYPE_EVAL,     HUB_TYPE_WORKFLOW),   # eval suites target linked workflows
      (HUB_TYPE_EVAL,     HUB_TYPE_AGENT),      # eval suites target linked agents
  })

  def is_link_direction_allowed(source_hub_type: str, target_hub_type: str) -> bool:
      return (source_hub_type, target_hub_type) in ALLOWED_LINK_DIRECTIONS
  ```
- [ ] Add `Hub` to `common/models/database.py` with the columns, index and constraint from `hubs.md` §3.1:
  ```python
  class Hub(Base):
      """A typed, isolated workspace that owns resources and members (hubs.md §3.1)."""

      __tablename__ = "hubs"

      id = Column(String(36), primary_key=True, default=lambda: str(uuid.uuid4()))
      slug = Column(String(64), nullable=False, index=True)
      name = Column(String(120), nullable=False)
      hub_type = Column(String(20), nullable=False, index=True)  # immutable after creation
      description = Column(Text, nullable=True)
      accent = Column(String(20), nullable=True)   # design-token key
      icon = Column(String(40), nullable=True)     # lucide icon name
      settings_json = Column(JSON, nullable=False, default=dict)
      owner_id = Column(String(36), ForeignKey("users.id", ondelete="RESTRICT"), nullable=False, index=True)
      is_archived = Column(Boolean, nullable=False, default=False, index=True)
      created_at = Column(DateTime, default=datetime.utcnow)
      updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)

      __table_args__ = (
          UniqueConstraint("hub_type", "slug", name="uq_hubs_type_slug"),
      )
  ```
  - `owner_id` uses `ON DELETE RESTRICT` deliberately: a user who owns a hub cannot be deleted until
    ownership is transferred (see `S6-02d`).
  - `slug` is unique **within** `hub_type`, not globally — `ingestion/support-kb` and `agent/support-kb`
    are two distinct hubs.
- [ ] Add `HubMember` per `hubs.md` §3.2, with cascade deletes on both foreign keys and the composite
      uniqueness that makes a user's membership in a hub single-valued:
  ```python
  class HubMember(Base):
      __tablename__ = "hub_members"

      id = Column(String(36), primary_key=True, default=lambda: str(uuid.uuid4()))
      hub_id = Column(String(36), ForeignKey("hubs.id", ondelete="CASCADE"), nullable=False, index=True)
      user_id = Column(String(36), ForeignKey("users.id", ondelete="CASCADE"), nullable=False, index=True)
      hub_role = Column(String(20), nullable=False)
      invited_by = Column(String(36), ForeignKey("users.id", ondelete="SET NULL"), nullable=True)
      created_at = Column(DateTime, default=datetime.utcnow)

      __table_args__ = (
          UniqueConstraint("hub_id", "user_id", name="uq_hub_members_hub_user"),
          Index("ix_hub_members_user_hub", "user_id", "hub_id"),
      )
  ```
  - The `(user_id, hub_id)` covering index exists so "list my hubs" and the per-request membership lookup
    in `S6-02b` are both index-only scans.
- [ ] Add `HubLink` per `hubs.md` §3.3 — the only mechanism by which one hub may reference another hub's
      resources:
  ```python
  class HubLink(Base):
      __tablename__ = "hub_links"

      id = Column(String(36), primary_key=True, default=lambda: str(uuid.uuid4()))
      source_hub_id = Column(String(36), ForeignKey("hubs.id", ondelete="CASCADE"), nullable=False, index=True)
      target_hub_id = Column(String(36), ForeignKey("hubs.id", ondelete="CASCADE"), nullable=False, index=True)
      access_level = Column(String(20), nullable=False, default="read")  # read | use
      created_by = Column(String(36), ForeignKey("users.id", ondelete="SET NULL"), nullable=True)
      created_at = Column(DateTime, default=datetime.utcnow)

      __table_args__ = (
          UniqueConstraint("source_hub_id", "target_hub_id", name="uq_hub_links_source_target"),
      )
  ```
- [ ] Declare SQLAlchemy relationships so hub deletion semantics and eager loading are explicit:
  - `Hub.members = relationship("HubMember", backref="hub", cascade="all, delete-orphan", lazy="selectin")`
  - `Hub.outgoing_links = relationship("HubLink", foreign_keys="HubLink.source_hub_id", cascade="all, delete-orphan")`
  - `Hub.incoming_links = relationship("HubLink", foreign_keys="HubLink.target_hub_id", cascade="all, delete-orphan")`
  - Both link relationships must set `foreign_keys=` explicitly — without it SQLAlchemy raises
    `AmbiguousForeignKeysError` because `hub_links` has two FKs to `hubs.id`.
- [ ] Extend the imports at the top of `common/models/database.py` to include `Index` and
      `UniqueConstraint` from `sqlalchemy` and `relationship` from `sqlalchemy.orm` (the file currently
      imports neither).
- [ ] Add application-level validation helpers on the model module (DB-level `CHECK` constraints are
      **not** used, to keep the migration portable):
  - `Hub.__init__` / a `@validates("hub_type")` hook rejecting any value not in `HUB_TYPES`.
  - A `@validates("hub_type")` guard that raises `ValueError("hub_type is immutable")` when the attribute
    is reassigned on an already-persisted instance.
  - `@validates("hub_role")` on `HubMember` rejecting values outside `HUB_ROLES`.
  - `@validates("access_level")` on `HubLink` rejecting values outside `("read", "use")`.
  - A `HubLink` `@validates("target_hub_id")` guard rejecting `source_hub_id == target_hub_id`
    (self-links are meaningless and would otherwise silently widen access).
- [ ] Export the new symbols from `common/models/__init__.py`: `Hub`, `HubMember`, `HubLink`, and the
      whole of `hub_enums` (`HUB_TYPES`, `HUB_ROLES`, `HUB_ROLE_ORDER`, `hub_role_satisfies`,
      `ALLOWED_LINK_DIRECTIONS`, `is_link_direction_allowed`).
- [ ] Add `tests/test_hub_models.py` covering, against an in-memory SQLite engine created from
      `Base.metadata`:
  - `hub_role_satisfies` for all 16 (actual, required) role pairs.
  - `is_link_direction_allowed` returns `True` for exactly the five documented pairs and `False` for all
    other 11 combinations — in particular every `(*, "eval")` pair.
  - Inserting two hubs with the same `(hub_type, slug)` raises `IntegrityError`; the same slug under a
    different `hub_type` succeeds.
  - Inserting a duplicate `(hub_id, user_id)` into `hub_members` raises `IntegrityError`.
  - Deleting a `Hub` cascades away its `hub_members` and both directions of its `hub_links`.
