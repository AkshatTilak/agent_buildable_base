# S6-10a: Workflow Hub Overview & Workflow Library

> **Parent:** B6-10 (Frontend — Workflow & Eval Hub Workspaces + Admin Console)  
> **Status:** `[ ]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend/src`

---

## Scope

Build the two landing surfaces of a workflow hub: `WorkflowHubOverview.tsx` (counts, recent runs,
validation health) and `WorkflowLibrary.tsx` — the multi-workflow list that replaces the V5 assumption
that the platform holds exactly one editable graph. The library must comfortably render dozens of
workflows per hub with search, tag filtering, status chips, last-run status and per-row actions.

Boundary: this subtask owns the routes `/hubs/workflow/:hubId` and
`/hubs/workflow/:hubId/workflows`, the list/create/duplicate/export/archive/delete call sites, and the
`workflowsByHub` slice of the rewritten store. The editor canvas itself is S6-10b; the runs table is
S6-10c. Nothing here may read the legacy `getWorkflows()` / `getActiveWorkflow()` helpers in
[frontend/src/services/api.ts](frontend/src/services/api.ts).

## Actionables

- [ ] Create `frontend/src/components/hubs/workflow/WorkflowHubOverview.tsx` mounted at `/hubs/workflow/:hubId`:
  - [ ] Stat tiles for total workflows, published vs draft counts, runs in the last 24h, and failed-run count, sourced from `GET /hubs/{hub_id}/workflows` and `GET /hubs/{hub_id}/workflows/{wf_id}/runs` aggregates.
  - [ ] "Recent runs" list (last 10 across the hub) linking into `WorkflowRuns.tsx`.
  - [ ] A hub-links summary card showing linked agent/ingestion hubs with a link through to `HubLinksPanel.tsx`.
- [ ] Create `frontend/src/components/hubs/workflow/WorkflowLibrary.tsx` mounted at `/hubs/workflow/:hubId/workflows`, built on the shared `DataTable` from S6-12b (do **not** hand-roll a `<table>`):
  - [ ] Columns: name (+ description subtitle, truncate-with-tooltip), tags, status chip (`draft` / `published` / `archived`), version (`v{n}`), last run status + relative time, updated-by, updated-at.
  - [ ] Debounced (250 ms) free-text search over name and description, and a multi-select tag filter driven by `tags_json`.
  - [ ] Status filter segmented control with an `Archived` toggle that is off by default.
- [ ] Implement row actions as an overflow menu: **Open**, **Duplicate** (`POST /hubs/{hub_id}/workflows/{wf_id}/duplicate`), **Export JSON** (`GET .../export`, downloads `{slug}.workflow.json`), **Archive** (`PATCH .../{wf_id}` with `status: "archived"`), **Delete** (`DELETE .../{wf_id}`).
  - [ ] Delete uses the destructive `ConfirmModal` variant requiring the typed workflow name (S6-12b).
  - [ ] Archive/Delete are hidden — not merely disabled — below `maintainer` hub role; `contributor` sees Open/Duplicate/Export only.
- [ ] Implement multi-select with a bulk-action bar exposing **Archive selected** and **Export selected**, with a single confirmation and an aggregate success/failure toast.
- [ ] Build `frontend/src/components/hubs/workflow/CreateWorkflowDialog.tsx`: name, description, tags, and a template chooser (`Blank`, `RAG Q&A`, `Classifier → Agent`, `Multi-Agent Fan-Out`) whose seed graphs live in `frontend/src/components/hubs/workflow/templates/`; on success `POST /hubs/{hub_id}/workflows` then navigate straight to `/hubs/workflow/:hubId/workflows/:wfId`.
- [ ] Add an **Import** control accepting a `.json` file, posting to `POST /hubs/{hub_id}/workflows/import`, and surfacing per-node reference errors returned by the server (unresolvable agent/collection references from another deployment).
- [ ] Add `workflowsByHub: Record<string, WorkflowSummary[]>` reads/writes to `frontend/src/store/workflowSlice.ts` (shape defined in S6-10b) plus `listWorkflows`, `createWorkflow`, `duplicateWorkflow`, `archiveWorkflow`, `deleteWorkflow`, `exportWorkflow`, `importWorkflow` helpers in [frontend/src/services/api.ts](frontend/src/services/api.ts), each taking `hubId` as its first argument.
- [ ] Wire empty, loading and error states through the shared components from S6-12c: skeleton rows matching the final column layout, an empty state reading "No workflows yet — create your first workflow" with the create action, and a `HUB_ARCHIVED` banner that puts the whole library into read-only mode.
- [ ] Add keyboard navigation: `↑`/`↓` move row focus, `Enter` opens, `Space` toggles selection, `/` focuses search, `n` opens the create dialog.
- [ ] Add `frontend/tests/workflow-library.spec.ts` (or the project's existing frontend test location) asserting: search filters rows, tag filter intersects, archived rows hidden by default, and delete is blocked until the name is typed exactly.
