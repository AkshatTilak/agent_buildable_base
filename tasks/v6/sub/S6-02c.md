# S6-02c: Cross-Hub Resolver & Link Enforcement

> **Parent:** B6-02 (Hub Access Control, Scoping & RBAC v2)  
> **Status:** `[x] Completed`  
> **Complexity:** 🔴 High  
> **Owner:** `common/services`, `gateway/api`

---

## Scope

Implement `common/services/hub_resolver.py`, the only sanctioned path by which a resource in hub *A* may
reach a resource in hub *B*, per
[`hubs.md`](file:///c:/Akshat/ContAIned/agent_buildable_base/references/logic/hubs.md) §5.4. It loads the
target resource, discovers its owning hub, and asserts that a `hub_links` row exists from the source hub to
that hub with a sufficient `access_level` — enforcing the allowed-direction matrix from §3.3 and the
explicit **non-transitivity** rule.

Link validity is re-checked **at execution time**, not only when a reference is saved. Revoking a link must
immediately break dependent agent invocations, workflow runs and eval runs with a descriptive,
machine-readable error rather than silently continuing to serve another hub's data.

## Actionables

- [x] Create `common/services/hub_resolver.py` with the resource-type registry that maps the wire-level
      `target_resource_type` string onto its model. This is the only place the mapping exists:
  ```python
  RESOURCE_TYPE_MODELS: dict[str, type] = {
      "collection": SyntraFlowCollection,
      "document":   SyntraFlowDocument,
      "agent":      AgentDefinition,
      "workflow":   WorkflowDefinition,
      "eval_suite": EvalTestSuite,
  }
  # Which hub_type owns each resource type — used to validate the link direction.
  RESOURCE_TYPE_HUB_TYPE: dict[str, str] = {
      "collection": "ingestion", "document": "ingestion",
      "agent": "agent", "workflow": "workflow", "eval_suite": "eval",
  }
  ```
- [x] Define the error vocabulary in the same module, carrying machine-readable codes the frontend can
      branch on:
  ```python
  class HubLinkError(Exception):
      def __init__(self, code: str, message: str, *, source_hub_id: str, target_hub_id: str | None = None):
          ...
  HUB_LINK_REQUIRED = "HUB_LINK_REQUIRED"   # no link has ever existed
  HUB_LINK_REVOKED  = "HUB_LINK_REVOKED"    # a stored reference points at a hub that is no longer linked
  HUB_LINK_INSUFFICIENT = "HUB_LINK_INSUFFICIENT"  # link exists but access_level is `read` where `use` is needed
  ```
  - Register a handler in `common/observability/exceptions.py` mapping `HubLinkError` → **`403`** with
    body `{"detail": <message>, "code": <code>, "source_hub_id": ..., "target_hub_id": ...}`.
  - `403` (not `404`) is correct here: the caller demonstrably has access to the *source* hub, so there is
    no enumeration surface — the target hub id is already in their own stored configuration.
- [x] Implement the primary resolver with the signature from `hubs.md` §5.4:
  ```python
  async def resolve_linked(
      session: AsyncSession,
      source_hub_id: str,
      target_resource_type: str,
      target_resource_id: str,
      *,
      required_access: str = "read",
  ) -> Any:
      """Load the target resource, then assert a hub_link exists from source_hub_id to the
      target's hub_id with a sufficient access_level. Raises HubLinkError (403) otherwise."""
  ```
  Resolution order:
  1. Look up the model via `RESOURCE_TYPE_MODELS`; unknown type → `ValueError` (a programming error, not
     a user error).
  2. Load the row **by primary key only** — this is the one allowlisted unscoped read in the codebase,
     because the hub is not yet known; annotate it with `# hub-resolver: allowlisted unscoped read`.
  3. If the row is missing → raise `HubLinkError(HUB_LINK_REQUIRED, ...)`, **not** a 404, so a caller
     cannot distinguish "does not exist" from "exists in an unlinked hub".
  4. **Same-hub fast path:** if `row.hub_id == source_hub_id`, return immediately — no link is needed for
     intra-hub references.
  5. Validate the direction: `is_link_direction_allowed(source_hub.hub_type, target_hub.hub_type)`; a
     disallowed pairing raises `HubLinkError(HUB_LINK_REQUIRED, ...)` (the link could never legally exist).
  6. Fetch the link via `hub_repository.get_link(session, source_hub_id=..., target_hub_id=row.hub_id)`;
     missing → `HUB_LINK_REVOKED` (a stored reference implies a link once existed).
  7. `link_access_satisfies(link.access_level, required_access)` → else `HUB_LINK_INSUFFICIENT`.
  8. Return the row.
- [x] Add the batch and assertion variants used by hot paths so a workflow with twenty agent nodes issues
      a bounded number of queries:
  ```python
  async def resolve_linked_many(session, source_hub_id, target_resource_type,
                                target_resource_ids: Sequence[str], *, required_access="read") -> dict[str, Any]: ...
  async def assert_link(session, *, source_hub_id: str, target_hub_id: str, required_access: str = "read") -> HubLink: ...
  async def list_linked_hub_ids(session, *, source_hub_id: str, target_hub_type: str,
                                required_access: str = "read") -> list[str]: ...
  ```
  - `list_linked_hub_ids` is what "which collections can this agent choose from?" pickers call — it must
    return only directly linked hubs.
- [x] Implement the creation-time validator used by the link management API in `S6-02d`:
  ```python
  async def validate_link_creation(session, *, source_hub_id: str, target_hub_id: str,
                                   access_level: str, actor_user_id: str, is_platform_admin: bool) -> None:
      """422 InvalidLinkDirectionError when the (source_type, target_type) pair is not in
      ALLOWED_LINK_DIRECTIONS or when source == target; 403 when the actor lacks
      owner/maintainer on the source hub or at least contributor on the target hub."""
  ```
  - The dual-hub permission requirement from `hubs.md` §3.3 is essential: without the target-side check a
    maintainer could unilaterally grant themselves read access to a hub they have no standing in.
  - A platform admin satisfies both sides.
- [x] Enforce **non-transitivity** explicitly. `resolve_linked` must never traverse more than one link hop;
      add an assertion comment and make the implementation structurally incapable of recursion (no loop,
      no recursive call). Document the canonical example inline: *workflow hub W → agent hub A, and
      A → ingestion hub I, does **not** grant W access to I; W must declare its own W → I link.*
- [x] Wire execution-time re-validation into the three consuming paths (each also owned by a later base
      task, but the hook belongs here):
  - Agent invocation: before retrieval, `resolve_linked(..., "collection", collection_id, required_access="read")`
    for every collection bound to the agent — in `common/services/agent_runtime.py` /
    `gateway/api/agent_invoke.py`.
  - Workflow run: for each agent node, `resolve_linked(..., "agent", node.agent_id, required_access="use")`
    at node instantiation time, not at graph-save time.
  - Eval run: for the suite's target, `resolve_linked(..., "workflow"|"agent", target_id, required_access="use")`
    at run start.
  - In each case the failure must abort the operation with the `HubLinkError` code intact so the UI can
    render "a required hub link was revoked" rather than a generic 500.
- [x] Cache link lookups **within a single request/run only**: an optional
      `link_cache: dict[tuple[str, str], HubLink | None]` parameter threaded through the resolver, created
      per request in `require_hub` (`S6-02b`) or per workflow run. A process-global cache is forbidden —
      revocation must take effect on the next operation, not after a restart.
- [x] Add `tests/test_hub_resolver.py`:
  - Same-hub reference resolves without any `hub_links` row.
  - Cross-hub reference with a valid link resolves; after deleting the link the identical call raises
    `HubLinkError` with `code == "HUB_LINK_REVOKED"` and the endpoint returns `403`.
  - `read`-level link where `use` is required → `HUB_LINK_INSUFFICIENT`.
  - Disallowed direction (e.g. `ingestion → agent`, and anything → `eval`) → `HUB_LINK_REQUIRED` even when
    a row is force-inserted into `hub_links`.
  - **Non-transitivity:** with links W→A and A→I present and no W→I link, resolving a collection in I from
    W raises `HubLinkError`.
  - A missing target id and a target in an unlinked hub produce identical response bodies.
  - `validate_link_creation` rejects `source_hub_id == target_hub_id` with `422`, and rejects an actor who
    is `owner` on the source but has no membership on the target with `403`.
