# S6-09c: Hub-Scoped Documents & Job Tracker

> **Parent:** B6-09 (Frontend — Ingestion & Agent Hub Workspaces)  
> **Status:** `[x]`  
> **Complexity:** 🟡 Medium  
> **Owner:** `frontend/src`

---

## Scope

Rework the two existing ingestion views into standalone hub-scoped workspaces. [frontend/src/components/ingestion/DocumentLibrary.tsx](frontend/src/components/ingestion/DocumentLibrary.tsx) and [frontend/src/components/ingestion/JobTracker.tsx](frontend/src/components/ingestion/JobTracker.tsx) are currently rendered as tabs inside the monolithic [frontend/src/components/IngestionPanel.tsx](frontend/src/components/IngestionPanel.tsx) and call the un-scoped `api.getDocuments()` / `api.getJobs()` helpers. They move to `frontend/src/components/hubs/ingestion/` as the Documents and Jobs tabs of the ingestion hub, reading `hubId` from `HubContext` and paging through `api.ingestion.documents.*` / `api.ingestion.jobs.*`.

The upload surface from `IngestionPanel` — drag-and-drop queue, size validation, chunking/preprocessing settings — is folded into the Documents workspace as an upload drawer targeting a chosen collection in the current hub, after which `IngestionPanel.tsx` is deleted.

- [ ] Create `frontend/src/components/hubs/ingestion/DocumentsWorkspace.tsx`, porting the table, pagination and chunk-preview logic out of [frontend/src/components/ingestion/DocumentLibrary.tsx](frontend/src/components/ingestion/DocumentLibrary.tsx) and dropping its direct global-store reads in favour of hub-keyed selectors.
  - [ ] Columns: selection checkbox, filename with type icon, collection, MIME/type, size, chunk count, ingest status, created time, row actions.
  - [ ] Server-side pagination with page-size control; the current page, filters and sort are reflected in the query string.
- [ ] Implement the filter bar: collection select (populated from the hub's collections), document type filter, status filter (`pending` / `processing` / `completed` / `failed`), and debounced filename search.
  - [ ] When mounted from the S6-09a collection detail view, the collection filter is locked to that collection and rendered as a non-removable chip.
- [ ] Implement bulk operations driven by row selection with a sticky action bar showing the selected count.
  - [ ] **Bulk re-index** — confirms, enqueues one job per document, and hands off to the Jobs tab with a link to watch progress.
  - [ ] **Bulk delete** — typed confirmation stating the exact document and chunk counts to be removed; partial failures are reported per document rather than as a single opaque error.
  - [ ] "Select all matching filters" as an explicit second step beyond "select all on page", with the true match count shown.
- [ ] Build the chunk preview drawer opened from a row.
  - [ ] Paginated chunk list with chunk index, token/character count, embedding status and the raw chunk text in a `font-mono` surface.
  - [ ] Copy-chunk action, and a "Search this chunk's neighbours" action that opens the S6-09a retrieval tester pre-seeded with the chunk text.
  - [ ] For video-derived documents, show segment timestamps alongside chunk text.
- [ ] Add the upload drawer, migrating the queue and validation behaviour from [frontend/src/components/IngestionPanel.tsx](frontend/src/components/IngestionPanel.tsx).
  - [ ] Required target-collection selector scoped to the current hub — uploads can no longer be submitted without an explicit collection.
  - [ ] Preserve the existing drag-and-drop queue, the 500 MB per-file guard and the per-file error rows.
  - [ ] Keep the chunking / preprocessing / postprocessing settings accordions, sourced from [frontend/src/store/ingestionSlice.ts](frontend/src/store/ingestionSlice.ts).
  - [ ] On submit, close the drawer and surface the created jobs inline with a link to the Jobs tab.
- [ ] Create `frontend/src/components/hubs/ingestion/JobsWorkspace.tsx` from [frontend/src/components/ingestion/JobTracker.tsx](frontend/src/components/ingestion/JobTracker.tsx), scoped to the hub.
  - [ ] Rows show job id (`font-mono`, truncated), source document, collection, stage, progress bar, duration, and status via [frontend/src/components/shared/StatusBadge.tsx](frontend/src/components/shared/StatusBadge.tsx).
  - [ ] Status and collection filters plus an "Active only" quick toggle.
- [ ] Implement live job status streaming instead of the current fixed-interval refetch.
  - [ ] Subscribe through the existing telemetry channel in `frontend/src/services/telemetry.ts`, filtered to the active `hubId`, and fall back to polling when the socket is disconnected.
  - [ ] Unsubscribe on unmount and on hub change so a background hub never streams.
  - [ ] Progress and stage updates must patch rows in place without resetting scroll position or clearing the current selection.
- [ ] Implement per-job **retry** (available for `failed` jobs) and **cancel** (available for `pending` / `processing` jobs), each confirming once and then reflecting the new state from the stream rather than optimistically.
  - [ ] Expose a failed job's error detail in an expandable row region with the failing stage and a copyable message.
- [ ] Delete [frontend/src/components/IngestionPanel.tsx](frontend/src/components/IngestionPanel.tsx), [frontend/src/components/ingestion/DocumentLibrary.tsx](frontend/src/components/ingestion/DocumentLibrary.tsx) and [frontend/src/components/ingestion/JobTracker.tsx](frontend/src/components/ingestion/JobTracker.tsx) once the new workspaces are wired, and confirm no import of them remains.
- [ ] Role gating: upload, re-index, delete, retry and cancel are wrapped in `Gated` — a `viewer` sees the tables, filters, chunk preview and job history but no mutating controls and no selection checkboxes; deletion additionally requires `maintainer` or above. In an archived hub all of these render disabled with the archived tooltip while browsing and preview remain fully functional.
- [ ] Loading / empty / error expectations:
