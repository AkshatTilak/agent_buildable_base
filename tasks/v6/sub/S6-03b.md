# S6-03b: Local Password Authentication

> **Parent:** B6-03 (Admin User Management, Invitations & Approval Gate)  
> **Status:** `[ ]`  
> **Complexity:** 🔴 High  
> **Owner:** `gateway/auth`  

---

## Scope

Add email + password authentication alongside the existing Google/GitHub SSO. This subtask delivers the
password primitives (`gateway/auth/passwords.py`), the five password routes on the existing
`APIRouter(prefix="/auth")` in `gateway/auth/routes.py`, and the brute-force lockout bookkeeping that
uses `users.failed_login_count` / `users.locked_until` from S6-03a.

The boundary: password credential handling and session issuance only. The invite/pending branching
logic that `/auth/register` calls into is implemented in S6-03d and consumed here through a single
helper; OAuth identity resolution is S6-03c.

## Actionables

- [ ] Add `argon2-cffi (>=23.1.0,<24.0.0)` to the gateway dependency group in `pyproject.toml`.
- [ ] Create `gateway/auth/passwords.py` exposing:
  ```python
  from argon2 import PasswordHasher
  from argon2.exceptions import VerifyMismatchError, VerificationError, InvalidHashError

  _hasher = PasswordHasher(time_cost=3, memory_cost=65536, parallelism=4, hash_len=32, salt_len=16)

  def hash_password(plain: str) -> str: ...
  def verify_password(plain: str, stored_hash: str | None) -> bool: ...
  def needs_rehash(stored_hash: str) -> bool: ...
  def validate_password_policy(plain: str, email: str) -> None:  # raises PasswordPolicyError
  ```
  - `verify_password` must run a **dummy verify** against a constant fixture hash when
    `stored_hash is None`, so an unknown-email path costs the same wall-clock time as a wrong password.
  - Never log, echo, or place the plaintext in an exception message or trace attribute.
- [ ] Implement the policy in `validate_password_policy`: minimum 12 characters, maximum 128, rejects
      passwords whose casefolded form appears in the denylist, and rejects passwords containing the
      local-part of the user's email.
  - Ship the denylist as `gateway/auth/common_passwords.txt` (top 10k list, one per line), loaded once
    into a `frozenset` at import via `functools.lru_cache`.
  - Raise `PasswordPolicyError(detail: str)` mapped to `422` with a non-leaky message
    (`"Password does not meet policy requirements"` plus a `rules` array).
- [ ] Add `POST /auth/register` (`gateway/auth/routes.py`) accepting `{email, password, display_name?}`:
  - Normalise the email (`email.strip().lower()`) before any comparison or write.
  - Reject with `403 {"reason": "SELF_REGISTRATION_DISABLED"}` when `settings.ALLOW_SELF_REGISTRATION` is false.
  - Delegate the account-creation branch to `resolve_signup(session, email, provider="password")` from
    S6-03d (invite → `active`; `AUTO_APPROVE_EMAIL_DOMAINS` match → `active`; otherwise `pending`).
  - Write a `user_identities` row with `provider="password"`, `provider_id=user.id`.
  - Return an identical `202 {"status": "registration_received"}` body whether or not the email already
    exists — never confirm account existence.
- [ ] Add `POST /auth/login` accepting `{email, password}` and returning `{access_token, token_type, user}`:
  - Load the user by lowercased email; run `verify_password` unconditionally (dummy hash if absent).
  - If `locked_until` is in the future → `423 {"reason": "ACCOUNT_LOCKED", "retry_after": <seconds>}`.
  - On failure: `failed_login_count += 1`; when it reaches `5`, set `locked_until = now + timedelta(minutes=15)`;
    always return the same `401 {"detail": "Invalid email or password"}`.
  - On success: reset `failed_login_count = 0`, clear `locked_until`, set `last_login`, touch
    `user_identities.last_used_at`, and call `needs_rehash` → transparently re-hash and persist.
  - Only issue a token when `user.status == "active"`; otherwise return `403` with the matching
    `ACCOUNT_PENDING_APPROVAL` / `ACCOUNT_SUSPENDED` / `ACCOUNT_REJECTED` reason (contract in S6-03c).
- [ ] Add `POST /auth/change-password` (authenticated, `Depends(get_current_user)`) accepting
      `{current_password, new_password}`:
  - Verify `current_password`; on mismatch return `403` and do **not** increment the lockout counter.
  - Run `validate_password_policy`, persist the new hash, set `password_updated_at = now`.
  - Delete every `UserSession` row for the user except the one matching `hash_token(request.state.token)`.
  - Write an `audit_log` row (`action="update"`, `resource_type="user"`, no password material in `before_json`/`after_json`).
- [ ] Add `POST /auth/forgot-password` accepting `{email}`:
  - Generate `raw = secrets.token_urlsafe(32)`, store `hashlib.sha256(raw.encode()).hexdigest()` in
    `password_reset_tokens` with `expires_at = now + timedelta(minutes=settings.PASSWORD_RESET_TTL_MINUTES)`.
  - Invalidate any prior unused token for that user before inserting the new one.
  - Send via the `Mailer` from S6-03e using `password_reset.html` / `.txt`, link
    `{APP_PUBLIC_URL}/auth/reset-password/{raw}`.
  - Always return `202 {"status": "reset_email_sent"}` — identical timing and body for unknown emails
    (perform a throwaway `secrets.token_urlsafe(32)` + sha256 so the work is symmetric).
- [ ] Add `POST /auth/reset-password` accepting `{token, new_password}`:
  - Look the row up by `token_hash` only; compare with `hmac.compare_digest`; require `used_at IS NULL`
    and `expires_at > now`; otherwise `400 {"detail": "Invalid or expired reset token"}`.
  - Apply the policy, set the new hash, set `used_at = now`, clear `failed_login_count` / `locked_until`,
    and delete **all** `UserSession` rows for that user.
- [ ] Extend `gateway/auth/utils.py::create_access_token` to carry `platform_role` and `status` in the
      JWT payload instead of the removed `role`, keeping `sub`, `email`, `iat`, `exp`.
- [ ] Add `PasswordPolicyError` and `AccountLockedError` to `common/observability/exceptions.py` and
      register handlers so they serialise to `422` / `423` with a stable `reason` key.
