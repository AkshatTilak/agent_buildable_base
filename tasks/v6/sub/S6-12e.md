# S6-12e: Onboarding & Contextual Guidance

> **Parent:** B6-12 (UX, Interaction & Accessibility Uplift)  
> **Status:** `[ ]`  
> **Complexity:** 🟢 Low  
> **Owner:** `frontend/src`

---

## Scope

The hub model introduces concepts a V5 user has never seen — typed hubs, hub roles, and directional
hub links. Without guidance the first experience is an empty directory and an unexplained "Link
required" badge. This subtask adds first-run guidance on the Hub Directory, an inline explainer for hub
links, per-hub-type getting-started checklists on empty hubs, and a persistent help affordance in the
hub shell.

Boundary: guidance content and its dismissal state only. No product tour library, no blocking modal
wizards, and nothing that cannot be dismissed permanently.

## Actionables

- [ ] Build `frontend/src/components/onboarding/FirstRunGuide.tsx` shown at the top of `/hubs` when the user has no hub memberships or has never dismissed it:
  - [ ] Three-card explainer — "A hub is an isolated workspace", "Hubs come in four types", "Hubs share resources only through links" — each with the hub-type accent from S6-12a.
  - [ ] A primary **Create your first hub** action, and a secondary **Learn how hubs work** opening the explainer drawer below.
  - [ ] Dismissible, with the dismissal persisted per user in `frontend/src/store/settingsSlice.ts` (server-persisted user preference where available, `localStorage` otherwise) and re-openable from the help menu.
- [ ] Build `frontend/src/components/onboarding/HubLinkExplainer.tsx` — a compact "What is a hub link?" popover reused wherever links are surfaced (`HubLinksPanel`, the agent/collection pickers in `PropertyDrawer.tsx`, the eval `TargetPicker`, and every `HUB_LINK_REQUIRED` error state):
  - [ ] States the direction rule plainly ("This workflow hub can use agents from a linked agent hub — not the other way round").
  - [ ] Lists the allowed directions from `hubs.md` §3.3 and notes explicitly that links are **not transitive** and that nothing may link into an eval hub.
  - [ ] Notes who can create a link (`owner`/`maintainer` on the source hub and `contributor`+ on the target).
- [ ] Build `frontend/src/components/onboarding/GettingStartedChecklist.tsx` rendered on an empty hub, with content per `hub_type` and each step deep-linking to the action:
  - [ ] `ingestion`: add a datastore binding → create a collection → ingest a document → run a search.
  - [ ] `agent`: link an ingestion hub → create an agent → bind a collection → invoke it.
  - [ ] `workflow`: link an agent hub → create a workflow → publish it → run it.
  - [ ] `eval`: link a workflow or agent hub → create a suite → add test cases → run the suite.
  - [ ] Steps auto-tick from live data (binding count, resource counts, run count) rather than from a client-side flag, and the checklist hides itself once complete.
- [ ] Add contextual empty-state copy on the hub creation wizard explaining what each of the four types owns, sourced from the table in `hubs.md` §2 so the wording matches the reference.
- [ ] Add a help affordance in the hub shell header: a `?` menu with "What is a hub?", "Hub roles explained", "Keyboard shortcuts" (opens the S6-12d `ShortcutSheet`) and a link to the deployment docs.
- [ ] Add a hub-roles explainer surfaced from the member-management UI: a compact matrix of `owner` / `maintainer` / `contributor` / `viewer` capabilities matching `hubs.md` §4.2, so an admin assigning a role can see what it grants.
- [ ] Add a first-visit inline hint in the workflow editor pointing at the validation strip and the save-state chip, dismissible and shown at most once per user.
- [ ] Ensure all guidance is non-blocking and accessible: no modal gates a first action, every popover is keyboard-reachable and `Esc`-dismissible per S6-12d, and no guidance element traps focus on mount.
- [ ] Add a `settings/Onboarding` control to reset all dismissed guidance, so the first-run experience can be re-tested without clearing storage.
- [ ] Add tests: the first-run guide renders only with zero memberships and stays dismissed after reload; checklist steps tick from live counts; the link explainer content matches the allowed-direction list.
